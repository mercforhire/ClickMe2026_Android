## Decision: in_progress and completed stay in the allow-list, time-gated

Evidence:
- The server Upcoming bucket is `UPCOMING_STATUSES = ['pending_approval', 'confirmed', 'pending_reschedule', 'in_progress']` (`clientBooking.controller.js:130`), and `isRejoinableCompleted` moves unfinished completed rows into Upcoming, so both statuses render on Upcoming surfaces.
- iOS shows Reschedule unconditionally on every Upcoming card (`UpcomingBookingCard.swift` secondaryActions, `UpcomingBookingSecondaryActions.swift`).
- The server `canReschedule` (`src/utils/reschedule.js`) allows `NO_TIME_GATE_STATUSES` (confirmed, pending_approval, pending_reschedule) at any time and `TIME_GATED_STATUSES` (completed, in_progress) only while `now < end_time`.

So the end bound is the server's own refusal condition and closes the "completed after end" hole without touching confirmed or pending_approval.

Note: `no_show` is not a backend booking status. The `bookings.status` CHECK constraint terminal set is cancelled, declined, missed, expired; `missed` is the server's no-show status. `no_show_both` (a call end reason) is tested as an unknown string.
