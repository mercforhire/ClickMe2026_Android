# Phase 10 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Requirements EXP-01 to EXP-04. Six surfaces:
> 1. The Topics tab (`TopicsScreen`): list, empty, loading, error, overflow menu, delete confirmation, FAB.
> 2. The Topic Editor (`TopicEditorScreen`): add and edit, with the price floor.
> 3. The "Edit Expertise" bottom sheet opened from the Topic Editor (D-08).
> 4. The Availability screen (`AvailabilityScreen`): timezone, overlap banner, seven day rows, Save state.
> 5. The Time Range picker bottom sheet and the Timezone picker bottom sheet (D-04, D-14).
> 6. Entry points (D-01) and the call guard on Save (D-03).
>
> Out of scope and must not appear in the UI: the Expert Dashboard (Phase 11), the Profile hub and Edit Profile (Phase 14), availability overrides, a currency picker, an unsaved-changes prompt (D-16), a bigger timezone list, a "24:00" end time.
>
> **Baseline.** `01-UI-SPEC.md` (tokens, shapes, motion, shell), `08-UI-SPEC.md` (tinted rows, dialog conventions, `AuthErrorDialog`, `EmptyState`, skeletons, result snackbars, destructive rule A5) and `09-UI-SPEC.md` (guard dialog, accent-reserved style) are locked and not restated. Dark only, Material 3, Nunito 400 / 600, exactly four text sizes (12 / 16 / 20 / 28 sp), `Spacing` xs..xxxl, `ClickMeShapes`, `MaterialTheme.extras`. Every value below is an existing token unless marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/ClickMe2026/Views/Screens/Expert Mode/Topics/**`, `.../Availability/**` and `.../Settings/Subviews/ExpertiseEditorSheet.swift`. Copy is taken from iOS verbatim unless marked "(Android)". Layout is ported and adapted to Material 3, not pixel-matched.
>
> **Source of decisions.** CONTEXT D-01..D-16 and its "ported as-is" blocks for behavior. This spec fills the "Claude's Discretion" areas: layout and copy beyond what is pinned, the "Saved" confirmation look (checkmark in the app bar), the time picker list (plain `LazyColumn`, no snapping), and the extra copy for dialogs, snackbars and states. The session had no live questions, so every assumption is recorded in "Assumptions and Open Items".

## Spacing Scale

Phase 1 tokens, all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

| Token | Used for in this phase |
|-------|------------------------|
| xs (4dp) | Gap between the label and its field helper line; gap between a card title and its price line; icon-to-text gaps in small text buttons |
| sm (8dp) | Gap between tag chips (horizontal and vertical); gap between icon chips; gap between a field label and its field; gap between the two time buttons and the minus sign; gap inside the overlap banner between icon and text |
| md (16dp) | Screen horizontal padding on every list and form; gap between topic cards; gap between day cards; card inner padding; gap between the timezone field and Auto-detect; dialog and sheet field gaps; gap between Cancel and Done on the time sheet |
| lg (24dp) | Gap between form sections in the Topic Editor (iOS 20); top padding of the Topics list and the Availability screen; gap between the timezone block and the day cards; bottom padding of sheets above the navigation inset |
| xl (32dp) | Bottom padding under the last form section and the last day card (plus the navigation inset); icon-to-heading gap in `EmptyState` (inherited) |
| xxl (48dp) | Minimum touch target: overflow button, icon chips, tag chips, stepper buttons, remove-slot button, time buttons, picker rows, text actions |
| xxxl (64dp) | Not used as spacing |

Exceptions (component dimensions and platform minimums, not layout spacing):
- Topic card icon tile 40dp (iOS 38) with a 24dp glyph, `small` shape. Icon picker chips 48dp (iOS 44) with a 24dp glyph.
- FAB 56dp (M3 standard). The Topics list bottom content padding is FAB 56dp plus `md` plus `md` (88dp) so the last card clears the FAB.
- Time picker: each list column is `height(240.dp)` (five 48dp rows; iOS 180). Rows are `heightIn(min = 48.dp)`.
- Time buttons on a day row: `weight(1f)`, `heightIn(min = 48.dp)` (iOS fixed 88 x 40).
- `Switch`: M3 default (52 x 32dp) inside a 56dp-minimum row.
- Description field `minLines = 3`; no fixed height.
- Dialogs and the sheet drag handle: platform / M3 metrics.

## Typography

Inherited: exactly four sizes (12, 16, 20, 28 sp), two weights (400, 600), line height 1.5 body and 1.2 headings. Nothing in this phase sets `fontSize`; every `Text` takes an M3 slot. Times use tabular numerals via `fontFeatureSettings = "tnum"` on the existing style (iOS used a monospaced font); this is not a new size or weight.

| Role | Size | Weight | Line height | Used for here |
|------|------|--------|-------------|---------------|
| Body | 16sp | 400 | 24sp (1.5) | Text typed in fields, time buttons and picker rows (`bodyLarge`), dialog messages, empty-state body, duration value, banner and error bodies |
| Label | 12sp | 600 | 16sp (1.33) | Field labels above inputs ("Topic Title", "Icon", …), banner title, "Select up to 3" (`labelMedium`; the count uses 12sp regular `bodySmall`), column labels on the time sheet |
| Heading | 20sp | 600 | 24sp (1.2) | TopAppBar titles, dialog titles, sheet titles ("Select Time Range", "Edit Expertise", "Select Timezone"), empty and error headings, the price on a topic card (`titleLarge`) |

`titleMedium` (16 / 600): topic title on a card, day name on a day card, selected time in the picker. `labelLarge` (16 / 600): every button label, app bar text action ("Save", the named exception in the Copywriting Contract), dialog buttons, "Add hours", "Auto-detect from device", "Add". `bodySmall` (12 / 400): "Per session · 60 min" line, helper line under the price field, "Unavailable" on a disabled day, description counter, "Select up to 3".

## Color

Dark only. All colors come from the Phase 1 ColorScheme and `MaterialTheme.extras`. No hex literal appears in this phase's code (`scripts/check-design-rules.sh`). Tinted fills are `color.copy(alpha = ...)` of a scheme color.

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `#131313` `surface` | Both screens' backgrounds, all app bars, the Topic Editor and Availability scroll areas |
| Secondary (30%) | `#1C1B1B` `surfaceContainerLow`, `#201F1F` `surfaceContainer`, `#2A2A2A` `surfaceContainerHigh` | Topic cards, day cards, duration stepper container, unselected icon chips: `surfaceContainerLow`, `medium` (cards) or `small` (chips), 1dp `outlineVariant`. Text fields keep the `ValidatedField` / `PickerField` look (`surfaceContainer`). Time buttons and unselected-state surfaces: `surfaceContainerHigh`. Dialogs and menus: `surfaceContainerHigh` |
| Accent (10%) | `#44F697` `primary` | See reserved list |
| Warning | `#FFB833` `tertiary` | Not used in this phase |
| Destructive | `#FFB4AB` `colorScheme.error` | "Delete" menu item and its dialog confirm text, the remove-slot icon, the overlap banner (10% fill, 1dp border at 45% alpha, warning icon) and the border of a day card that has an overlap (1dp at 50% alpha). Text on the banner stays `onSurface` / `onSurfaceVariant`. `ValidatedField` and `PickerField` keep their inherited error border and message (`extras.destructive`). Never a filled error button (Phase 8 rule) |

Accent reserved for (and nothing else in this phase):
1. Fill of the single primary CTA on each surface: the Topics FAB, "Add Topic" in the Topics empty state, "Retry" in every error state (via `EmptyStateAction`), "Done" on the time sheet, "Save Expertise" on the Edit Expertise sheet.
2. The text of the app bar "Save" actions (Topic Editor and Availability; the named copy exception), their 24dp in-flight spinner and the "Saved" check on Availability.
3. The glyph of a topic icon (card tile glyph, selected picker chip) plus the tile fill at 12% alpha and the selected chip fill (12%) and 2dp border.
4. The word "Free" on a topic card (Phase 5 D-21).
5. Inline text actions: "Add" (tags header), "Add hours", "Auto-detect from device", "Add Expertise" (outlined with a 1dp `primary` border).
6. The checked track of the day `Switch` (M3 default: `primary` track, `onPrimary` thumb) and the selected row in the time picker (text `primary`, 2dp `primary` border, `small` shape).
7. The trailing check on the current timezone row (inherited from `PickerRow`).
8. Focused border and cursor of every text field, and every `CircularProgressIndicator` (including the pull-to-refresh indicator).

Neutral, deliberately not accent: the price amount (`onSurface`; only "Free" is green), card titles, the overflow icon (`onSurfaceVariant`), the Availability app bar action icon (`onSurfaceVariant`), unselected icon glyphs (`onSurfaceVariant`), tag chips (inherited `SelectableChip` look: `secondaryContainer` when selected), stepper buttons (`onSurface`), Cancel on the time sheet (outlined, `onSurface`).

Contrast: `onPrimary` on `primary` 9.3:1 (FAB, buttons); `primary` on `surface` and on `surfaceContainerLow` above 9:1 (text actions); `error` on `surfaceContainerLow` above 8:1; `onSurfaceMuted` on `surfaceContainerLow` at least 5.9:1 (helper lines). State is never conveyed by color alone: the overlap banner carries a word and an icon, an overlapping day also appears by name in the banner, a selected icon / time row / tag carries a border or close icon plus a `stateDescription`, a disabled day says "Unavailable".

## Motion

Phase 1 durations. All of it follows the system animator duration scale; with animations off every transition is instant.

| Interaction | Duration / easing |
|---|---|
| Push / pop of Topic Editor and Availability on their tab's back stack | Phase 1: horizontal slide + fade, 300 ms (`Motion.PUSH_POP_DURATION_MS`, `pushPopEasing`); predictive back drives pops |
| Loading skeleton to content, quiet reload swapping rows | 150 ms cross-fade; list rows use `animateItem()` defaults when a topic is added, edited or deleted |

## Navigation and Structure

```
Expert shell (HomeExpertScreen), per-tab Navigation 3 back stacks

Topics tab stack:   TopicsRoot  ->  TopicEditorKey(topicId?)   (full-screen, back arrow)
                                ->  AvailabilityKey            (full-screen, back arrow)
Profile tab stack:  ExpertProfileRoot  ->  AvailabilityKey     (full-screen, back arrow)

Sheets (not routes): Edit Expertise (from Topic Editor), Time Range (from Availability), Timezone (from Availability)
```

- **Topics tab root** (`entry<TopicsRoot>`, replaces `ExpertTabRoot(TopicsRoot)`): `TopAppBar` (Phase 1 tab-root colors, no back) with title "Topics" and one action: an `IconButton` (`CalendarMonth`, `onSurfaceVariant`, `contentDescription` "Availability") that pushes `AvailabilityKey` (D-01). Bottom bar stays visible.
- **Expert Profile tab**: in the footer, above Log out, a `ProfileMenuRow` ("Availability", `CalendarMonth`) with `md` gap to the Log out button. It pushes `AvailabilityKey` onto the Profile stack. It is a placeholder row: Phase 14 replaces it (D-01). Test tag `profile_availability_row`.
- **Topic Editor and Availability**: `AuthTopAppBar` with a back arrow. Back (arrow, system, predictive) pops and silently discards edits (D-16). The bottom bar is hidden on pushed screens (Phase 1 rule).
- **While a save is in flight**: Topic Editor: Back (arrow and system) is ignored and the arrow is disabled (`backEnabled = false`, Phase 8 convention) because the result decides whether it stays open. Availability: Back still pops; the request finishes in the ViewModel and the result is dropped.
- **After a successful topic save** (D-07): pop to the Topics list, which updates the item in place (edit) or appends (create), and a snackbar confirms (see Copywriting). The pending message travels as a one-shot field on the screen's state holder, not a nav result.
- **Returning to the Topics tab or the list** from the editor or the Availability screen triggers a quiet reload (the list never returns to the skeleton).

## Screen Specifications

### 1. Topics tab (EXP-01, D-05, D-06)

Scaffold: tab-root app bar above, `SnackbarHost` above the bottom bar, FAB at bottom end (only when topics exist).

| State | Rendering |
|---|---|
| Loading (first load) | `TopicsSkeleton`: three `SkeletonBlock` cards, each `medium`, `heightIn(min = 96.dp)`, `md` between, `md` horizontal and `lg` top padding |
| Loaded, at least one topic | `PullToRefreshBox` around a `LazyColumn`: `md` horizontal padding, `lg` top, `md` between cards, bottom 88dp. FAB visible |
| Loaded, no topics (EXP-01) | `EmptyState` centered inside a `verticalScroll` `fillMaxSize` column (so pull-to-refresh works): icon `LibraryAdd` 48dp, heading "Add your first topic", body "Clients can't book you until you add at least one topic.", action "Add Topic" (filled `primary`). No FAB in this state (the empty-state button is the single CTA) |
| Error (first load) | `EmptyState` with `CloudOff`, heading "Couldn't load topics", body = server message else "Check your connection and try again.", action "Retry" |
| Quiet reload (pull-to-refresh, return from editor or Availability) | List stays on screen and updates in place. A failed pull-to-refresh shows a `Snackbar` "Couldn't refresh. Check your connection and try again." (Phase 8 copy); a failed return reload shows nothing |

**Topic card (`TopicCard`).** `Surface`, `medium`, `surfaceContainerLow`, 1dp `outlineVariant`; the whole card is clickable (`Role.Button`, opens the editor for that topic, D-05); ripple default.

```
Row (md padding, top-aligned)
 |- Icon tile 40dp (small, primary 12% fill) with the slug glyph 24dp primary
 |  (null / unknown slug: CategoryIconMap fallback GridView)
 |- md gap
 |- Column(weight 1f)
 |    Text title            titleMedium onSurface, maxLines 2
 |    xs
 |    FlowRow (sm / xs gaps, bottom aligned)
 |       price: titleLarge onSurface, or "Free" titleLarge primary
 |       "Per session · {duration}" bodySmall onSurfaceMuted
 |- Overflow IconButton 48dp (MoreVert 24dp, onSurfaceVariant)
```

- Price text: `Money.format(minorUnits, currency)` using `hourly_rate` (fallback `price`), full decimals, JPY none. A free topic (`price.is_free`) shows "Free" in `primary` and never the stored floor amount.
- Duration text: "30 min", "1 hour", "1 hr 30 min", "2 hours" (iOS `formatDuration`).
- Overflow menu: `DropdownMenu` (`surfaceContainerHigh`) anchored to the button with two items, each `heightIn(min = 48.dp)`: "Edit" (leading `Edit` icon, `onSurface`) and "Delete" (leading `Delete` icon and text in `error`). The button is in its own focus stop, outside the card's click target. While a delete is in flight the delete target's overflow button is replaced by a 24dp `primary` spinner (`stateDescription` "Deleting") and every card's overflow button is disabled (one operation at a time, Phase 7 precedent). The card itself stays tappable except the one being deleted.
- Semantics: the card is one node with `contentDescription` "{title}, {price}, {duration}" and `onClickLabel` "Edit topic"; the overflow button's `contentDescription` is "More options for {title}".

**FAB.** `FloatingActionButton`, `CircleShape`, container `primary`, content `onPrimary`, `Add` 24dp, `contentDescription` "Add topic". Standard M3 position (bottom end, `md` margin) above the bottom bar. Test tag `topics_add_fab`. It pushes `TopicEditorKey(null)`.

**Delete (D-06).** "Delete" opens `TopicDeleteDialog` (`AlertDialog`, `extraLarge`, `surfaceContainerHigh`, same structure as `PaymentMethodRemoveDialog`): title "Delete this topic?", message "“{title}” will be removed and clients won't be able to book it.", buttons "Keep Topic" (`onSurface`, dismiss) / "Delete" (`error`). The scrim and Back dismiss. On Delete the dialog closes and the card shows its spinner. Success removes the item with `animateItem()` and shows the snackbar "Topic deleted". Failure (409 for active bookings, or any other error) shows `AuthErrorDialog` titled "Couldn't delete topic" with the server `message`, else "Something went wrong. Please try again." (network: "Check your connection and try again."). The list stays unchanged.

### 2. Topic Editor (EXP-01, EXP-02, D-07, D-09 to D-12)

`AuthTopAppBar`: title "Add Topic" or "Edit Topic", back arrow, action with the visible label "Save" (`TextButton`, `labelLarge`, `primary`, `heightIn(min = 48.dp)`; named exception in the Copywriting Contract). Its `contentDescription` and `onClickLabel` are "Save topic". While saving the action is replaced by a 24dp `primary` spinner in a 48dp box (`stateDescription` "Saving topic"), the arrow is disabled and field taps are ignored. Test tag `topic_editor_save`.

Body: `Column` with `verticalScroll`, `imePadding()`, `md` horizontal padding, `lg` top, `lg` between sections, `xl` plus navigation inset at the bottom. The editor is a pushed route, so edits survive rotation (state in the ViewModel with `SavedStateHandle`).

Section order and spec:

| # | Section | Spec |
|---|---|---|
| 1 | Icon | Label "Icon" (`labelMedium`, `onSurfaceVariant`), `sm`, then a horizontally scrolling `LazyRow` (`sm` between) of 48dp chips: `small` shape; unselected `surfaceContainerLow` fill, 1dp `outlineVariant`, glyph 24dp `onSurfaceVariant`; selected `primary` 12% fill, 2dp `primary` border, glyph `primary`. The strip shows the 24 curated slugs alphabetically (ai, business, career, coaching, consulting, design, education, engineering, finance, fitness, healthcare, language, legal, marketing, music, photography, productivity, psychology, science, startup, tech, travel, wellness, writing). If the topic's current slug is not in the list it is prepended. Tapping the selected chip clears the selection (no icon). In edit mode the strip scrolls to the selected chip on open (centered, no animation). Chip semantics: `Role.Button`, `contentDescription` "{Slug label} icon" (for example "Marketing icon"), `stateDescription` "Selected" / "Not selected" |
| 2 | Topic Title (required) | Label "Topic Title"; `ValidatedField`, leading `Title`, placeholder "e.g. Go-to-Market Execution", single line, `KeyboardCapitalization.Sentences`, `ImeAction.Next`, input capped at 200 characters (server max) |
| 3 | Description (optional) | Label "Description (optional)"; multi-line field, `minLines = 3`, `maxLines = 6`, `surfaceContainer` fill, `medium` shape, 1dp `outline` border (2dp `primary` focused), placeholder "What clients will get out of this session", `ImeAction.Default`, capped at 2000 characters (server max) with a `bodySmall` `onSurfaceMuted` counter "{n}/2000" at the end below the field (same pattern as the Phase 8 comment field) |
| 4 | Session Duration | Label "Session Duration"; a `Row` in a `surfaceContainerLow` `medium` container with 1dp `outlineVariant`: `IconButton` `Remove` (48dp, `contentDescription` "Decrease duration"), the value centered `bodyLarge` `onSurface` (`weight(1f)`, `liveRegion = Polite`, text per the duration format above), `IconButton` `Add` (48dp, "Increase duration"). Range 30 to 480 min in steps of 30, default 60 for a new topic. Each button is disabled (38% alpha) at its bound. Holding a button does not repeat |
| 5 | Price per Session (EXP-02) | Label "Price per Session"; `ValidatedField`, leading `Payments`, placeholder "e.g. 150", `trailingBadge` = the ISO currency code in `labelLarge` `onSurfaceVariant` ("CAD"), `KeyboardType.Decimal` (`Number` when the currency has 0 fraction digits), `ImeAction.Done`. Accepts digits and one decimal separator with at most the currency's fraction digits (D-09); the field filters other characters as they are typed. Below the field (`xs`): helper line `bodySmall` `onSurfaceMuted` "Leave blank or enter 0 for a free session — otherwise min {floor}" (`{floor}` = `Money.format(floorMinorUnits, currency)`); hidden while `pricing_limits` is null; replaced by the field's error line whenever one is showing. Editing a free topic shows the field blank, not the stored floor amount. Editing a paid topic shows its price with the currency's decimals ("12.50", not "12") |
| 6 | Expertise Tags | See "Tag picker" below |

**Price validation states (D-11, D-12).**

| Condition | Rendering |
|---|---|
| Blank or `0` | Free session. No error. Helper line shown |
| Paid amount below `by_currency[currency]` (fallback `default_minor_units`), live while typing and on Save | Field error state with the line "A paid session must be at least {floor}." Save sends nothing |
| Not a number, negative, or more fraction digits than the currency allows (on Save) | Field error state with "Please fill in all required fields with valid values." |
| Server `422 PRICE_BELOW_MINIMUM` | The server `message` in the field's error line; the editor stays open; the error clears on the next keystroke |
| No floor available (`pricing_limits` still null after one `/me` refresh) | No client-side floor check and no helper line; the server 422 is the authority |

Currency suffix rules (D-10): existing topic keeps `hourly_rate.currency` (fallback `price.currency`); new topic uses `pricing_limits.min_session_amount.default_currency`, else "CAD". It is display-only (no picker).

**Required-field validation on Save.** Empty (after trim) title: the Title field shows its error state with "Please fill in all required fields with valid values." Focus moves to the first failing field (`FocusRequester`, Phase 3 pattern) and the form scrolls to it. No request is sent.

## Accessibility Contract

- Touch targets at least 48dp: overflow button, FAB (56), icon chips (48), tag chips (heightIn 48 via the shared chip), stepper buttons, remove-slot button, time buttons, picker rows, text actions, Switch rows (56), dialog and sheet buttons.
- Topic card: one clickable node with a merged description ("{title}, {price}, {duration}") and `onClickLabel` "Edit topic"; the overflow button is its own focus stop with a title-specific label.
- Menu items are standard `DropdownMenuItem`s (announced with their labels). The destructive item is identified by its word, not only its color.
- Icon chips and time-picker rows expose selection through `stateDescription` or `selectable`; selected icon chips also differ by border weight.
- The Save actions' states are exposed with the full phrases: `contentDescription` "Save topic" / "Save availability", `stateDescription` "Saving topic" / "Saving availability", and a polite live-region `contentDescription` "Availability saved". A disabled Save explains itself ("Fix overlapping time slots to save availability").
- The overlap banner is a polite live region and names the days, so a screen-reader user does not depend on the card borders.
- Field errors use the inherited `ValidatedField` semantics (`error`). On a failed Save focus moves to the first failing field.
- The duration value is a polite live region so each step is announced.
- Sheets: TalkBack focus lands on the title (`heading()`); the Time Range columns announce their label ("Start Time" / "End Time") as the group name.
- 200% font scale: card titles wrap to 2 lines and the price / duration line wraps in a `FlowRow`; the day-card rows and time buttons keep `heightIn(min)` and the slot row wraps the remove button to a second line if needed (use `FlowRow` for the slot row at large scales); labels, banner body and sheet titles wrap; the Time Range sheet scrolls; the Topic Editor scrolls with the IME open. Check the Topics list, the Topic Editor with an error line, an overlapping day with the banner, and the Time Range sheet at 200%.
- Reduce motion: with the system animator scale at 0 all fades and slides are instant.
- A full TalkBack pass is Phase 15 (POL-04).

## Assumptions and Open Items (for the planner and checker)

Assumptions made without the user (the session had no live questions):

- **A1. Availability action is an icon button** (`CalendarMonth`, labelled for TalkBack) in the Topics app bar rather than a text action, to keep the bar uncluttered at narrow widths. A `TextButton` "Availability" is a one-line swap if the icon proves unclear on device.
- **A2. Topic card layout** puts price and duration under the title (not beside it as on iOS) so the title keeps enough width on 320dp screens with the 48dp overflow button.
- **A3. Result snackbars** ("Topic added", "Topic updated", "Topic deleted") and the delete-failure dialog title are Android additions (Phase 8 precedent). Drop them if the checker prefers no new copy; nothing else depends on them.
- **A4. Empty-state body copy** is Android text built from the CONTEXT line ("clients can't book until a topic exists"). The heading and button are pinned by D-05.
- **A5. Required-field error on the field.** iOS shows the shared message once at the bottom; here it is shown on the failing field (title or price) with focus moved. The copy is unchanged.
- **A6. Time display follows the device 12 / 24 hour setting** on the day rows and in the picker. iOS shows 24-hour on the rows and AM/PM in the picker. Wire format is unaffected.
- **A7. Day names are full** ("Monday") instead of iOS's short names.
- **A8. Time sheet drafts.** Cancel and dismiss discard; iOS has no revert.
- **A9. "Add hours" at the end of the day.** When the latest end is 23:00 or later there is no non-overlapping room; the slot is still added and the overlap banner flags it. The planner may instead disable the button; either way the end stays at or below 23:30, never 24:00 (the iOS formula can produce 1440, which the picker and the wire format cannot represent).
- **A10. End time cap stays at 23:30.** The backend `HH:mm` regex (`availability.schema.js`) accepts any two-digit pair and there is no documented midnight form, so the CONTEXT research item stays open; this spec keeps the iOS cap. If research finds "24:00" safe, extend the End list by one row and nothing else changes.
- **A11. Topics FAB hidden in the empty state.** The empty-state "Add Topic" button is the single CTA, so two add controls never show at once.
- **A12. Delete message copy** ("“{title}” will be removed and clients won't be able to book it.") is Android text. If the topic has active bookings the server returns 409 and its message is shown in the error dialog.
- **A13. Saved check lasts 2000 ms** (iOS `didSave` is about 2 s); the existing 600 ms constant is not reused.
- **A14. Currency suffix is a trailing badge** inside the price field (via `ValidatedField.trailingBadge`) rather than a leading symbol, so a code like "CAD" or "JPY" is unambiguous; the leading icon is a generic `Payments` icon.
- **A15. The Expertise sheet reuses the signup tags body.** If extracting the shared composable from `SignupTagsScreen` is costly, the sheet may copy the layout; the contract above is the spec either way.
