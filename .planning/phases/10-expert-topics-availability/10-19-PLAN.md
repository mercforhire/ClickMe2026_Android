<objective>
Close two Availability warnings from 10-REVIEW.md.

- **WR-04:** the silent UTC auto-fill PUT sends the hydrated schedule. It can therefore delete server slots that `hydrate` dropped (malformed `HH:mm` or `end <= start`), in a screen that was merely opened.
- **WR-01:** `edit()` and `refresh()` run while Save is in flight, so "Saved" can show a schedule that was never sent, and a pull can land the pre-PUT copy.

**WR-04 design: skip the silent PUT when hydrate was lossy, honoring locked D-15 (reversible).** D-15 says "After hydration finishes, PUT the fully hydrated schedule silently" and lists when to skip (save in flight, overlaps, active call). This plan adds one condition to that list: skip when `hydrate` dropped any server range. When nothing was dropped, the hydrated schedule equals the server's, so the D-15 PUT cannot delete anything.

The review suggested a timezone-only PUT, and the backend allows it: `putAvailabilitySchema` has `timezone_id` and `schedule` both optional, and `putSchedule` preserves omitted days. That option is recorded but not taken, because it changes the D-15 body. When the PUT is skipped, the zone is still filled locally and goes out with the next explicit Save, the same as D-15's failure path ("the next open tries again").

**WR-01 design.** `edit()` and `refresh()` return early while `saveState == Saving`. An edit during the Saved hold ends the hold (cancels the hold job, sets Idle), so the check never sits over an unsent edit. The PUT already runs in `withContext(NonCancellable)`, so cancelling the hold only cuts the delay. No screen change is needed: the ViewModel is the single gate, and `PullToRefreshBox` retracts because `isRefreshing` stays false.

Purpose: availability edits (EXP-03) and the timezone auto-fill (EXP-04) never show or write anything the expert did not ask for.
Output: `AvailabilityScheduleLogic.isLossless`, the ViewModel guards, and regression tests.

Out of scope (deferred, recorded in 10-20): WR-03 and IN-01..IN-07. Plans 10-01..10-16 are not modified.
</objective>
