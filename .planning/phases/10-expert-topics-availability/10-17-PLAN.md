<objective>
Close the one blocking verification gap (CR-01) in the Edit Expertise sheet. Today the selection is seeded by a separate async `GET /expert/profile` whose failure is swallowed and whose late result is dropped once the user touches the selection, while Save is gated only on a non-empty selection. Because `PATCH /expert/profile` is a full replace, a failed or slow seed lets a one-tag save silently delete every existing tag, including the primary.

Fix: add an explicit seed state (Loading / Failed / Ready), gate Save on Ready in both the UI state and `save()`, show a Retry on failure, and block selection edits until the seed is Ready so the late seed can never be discarded.

**Choice: block until Ready, not merge (Claude's discretion; reversible).** The Failed path needs the Ready gate anyway, so letting the user toggle before Ready gains nothing and would need a merge rule (which tag is primary, where the profile tags go relative to early picks). Blocking keeps one rule: nothing changes the selection until it holds the full profile. That matches iOS, which seeds synchronously from the cached `expertProfile`, so its selection is always complete before the first tap.

**WR-05 note.** The orchestrator mapped WR-05 to this file, but 10-REVIEW.md places WR-05 in the Topic Editor (`TopicTagPicker.kt` with `TopicEditorViewModel.kt`). The same pattern in this sheet (a failed seed hides the selection) is removed by the seed gate here. The Topic Editor WR-05 fix is in plan 10-18.

Purpose: restore the 10-11 must-have and the T-10-34 mitigation (EXP-01: the sheet is the tag source for the topic picker, and a lost primary tag cascades into dropped topic tags through `applyProfileTagsUpdate`).
Output: a seed-gated ViewModel, two seed bodies in the sheet, 2 new string resources, and regression tests.

Out of scope (deferred, recorded in 10-20): WR-03 and IN-01..IN-07. Plans 10-01..10-16 are not modified.
</objective>
