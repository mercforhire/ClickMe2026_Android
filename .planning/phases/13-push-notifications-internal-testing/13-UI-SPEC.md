# Phase 13 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Requirements PUSH-01..05 and REV-01 (the UI half of the phase; REL-04/REL-05 are human-only Play Console and Firebase steps and have no UI contract). Six surfaces:
> 1. Notifications list (new route, pushed on the Explore stack in client mode and the Dashboard stack in expert mode).
> 2. Bell entry on the client Explore top bar and the expert Dashboard top bar.
> 3. Write Review (new full-screen route).
> 4. Booking Summary additions: the Leave a Review button and the Feedback block (restored, Phase 8 D-16).
> 5. Past booking card "Leave a review" affordance.
> 6. System notification presentation (channels, small icon, accent color, tap target) and the `POST_NOTIFICATIONS` system prompt timing.
>
> Out of scope and must not appear in the UI: a custom permission rationale screen or pre-prompt (D-01), an unread badge on either bell or on any tab, read/unread styling of rows (D-16), paging past 50 notifications, a "Mark all as read" action, notification preferences (`/notifications/preferences`), swipe-to-dismiss on rows, a Notifications row in the Profile tabs (iOS has one; not requested by D-17), the Payouts/Security/KYC destinations (Phase 14), any visual for the pending push destination or for the automatic mode switch beyond the existing Phase 4 transition, Write Review for experts, editing a submitted review, review tags, in-app store listing / data-safety copy (human-only drafts live in planning, not here).
>
> **Baseline.** `01-UI-SPEC.md` (tokens, shapes, motion, shell), `08-UI-SPEC.md` (Booking Summary, Past card, quiet-reload snackbar, destructive rule A5, `AuthErrorDialog`) and `12-UI-SPEC.md` (counters, footer bar, empty/error pattern, tinted tiles, tab-root rules) are locked and not restated. Dark only, Material 3, Nunito 400 / 600, exactly four text sizes (12 / 16 / 20 / 28 sp), `Spacing` xs..xxxl, `ClickMeShapes`, `MaterialTheme.extras`, Outlined icons, `AutoMirrored` Outlined back arrows. Every value below is an existing token unless marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/ClickMe2026/Views/Screens/Notification/**` (`NotificationsListView`, `NotificationRow`, view model), `Client Mode/Write Review/**` (view, view model, six subviews), `Client Mode/Booking Summary/**` (`leaveReviewButton`, `BookingSummaryFeedback`) and `Client Mode/My Bookings/Subviews/PastBookingCard.swift`. The per-screen iOS palettes (`WriteReviewBrand`, `BookingSummaryBrand`, `MyBookingsBrand`) collapse to the Phase 1 tokens (FND-02); glows, gradients and the star entrance spring become plain Material surfaces. Layout is ported and adapted to Material 3, not pixel-matched. Copy is taken from iOS unless marked "(Android)" or "(spec)".
>
> **Source of decisions.** CONTEXT D-01..D-22 are locked and not re-asked. D-01..D-04 and D-12 fix the permission, channel and heads-up behavior; D-16..D-19 fix the list, entry points and Write Review flow. This spec fills the "Claude's Discretion" areas: channel ids, names, descriptions and importance; small icon and accent color; list row, section, hint-row and state visuals; bell placement; Write Review layout and states; Feedback block and Past card affordance. The run was non-interactive, so every assumption is recorded in "Assumptions and Open Items". No RESEARCH.md exists; the review rules were read from `backend-reference/src/schemas/reviews.schema.js` (rating 1..5, comment 1..1000) and `reviews.controller.js` (`has_submitted` plus `prefill`, upsert-on-resubmit).

## Spacing Scale

Phase 1 tokens, all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

| Token | Used for in this phase |
|-------|------------------------|
| xs (4dp) | Title to body to timestamp gaps inside a notification row; icon-to-text gap in the already-submitted banner; gap between the subtitle and the session-topic line |
| sm (8dp) | Gap between the headline block and the subtitle; Past card action top gap (`sm` after the existing card gap); icon-to-label gap in Leave a review buttons; gap between the section header and its first row's top is `md` (not `sm`) |
| md (16dp) | Screen horizontal padding; row inner padding; gap between rows; gap between icon tile and text column; gap between a section header and its rows; gap between the hint row and the first section; footer bar padding; gap above the Feedback block; Leave a review top gap on Booking Summary |
| lg (24dp) | Top padding under the app bar on the list; gap between Write Review blocks; empty-state vertical padding |
| xl (32dp) | Gap between date sections; bottom scroll padding plus the navigation inset on the list and Write Review; `EmptyState` icon-to-heading gap (inherited) |
| xxl (48dp) | Minimum touch target: the bell action, each star target, the hint row, notification rows, the Past card action, the clear/retry controls |
| xxxl (64dp) | Not used |

Exceptions (component dimensions and platform minimums, not layout spacing):
- Notification icon tile: 48dp circle, glyph 24dp (iOS 48pt). Row minimum height `heightIn(min = 48.dp)`; rows otherwise grow with content (never fixed).
- Write Review avatar: 96dp (new size; the hero avatar). Star glyph 40dp inside a 48dp square touch target; five targets are 240dp wide and are centered. Review field `heightIn(min = 160.dp)` (iOS 160pt). Stroke widths 1dp resting, 2dp focused.
- Leave a review controls: text form `heightIn(min = 56.dp)` on Booking Summary (as Message Expert); the Past card action is a pill `heightIn(min = 48.dp)`.
- Feedback block stars: 24dp glyphs (the `RatingStars` `size` argument).
- Skeletons copy the real dimensions above.

## Typography

Inherited: exactly four sizes (12, 16, 20, 28 sp), two weights (400, 600), line height 1.5 body and 1.2 headings. Nothing in this phase sets `fontSize`; every `Text` takes an M3 slot. iOS kerning and uppercase tracked section captions are dropped (Phase 8 caption rule).

| Role | Size | Weight | Line height | Used for here |
|------|------|--------|-------------|---------------|
| Body | 16sp | 400 | 24sp (1.5) | Notification body, hint-row text, Write Review subtitle, review field text and placeholder, Feedback comment, banner hint line, error and empty bodies, dialog message |
| Label | 12sp | 600 | 16sp (1.33) | Not used on a Phase 13 surface. Regular 12sp captions (timestamp, session topic, counter, "End of recent updates") use `bodySmall` (400) |
| Heading | 20sp | 600 | 24sp (1.2) | Empty and error headings, dialog titles |
| Display | 28sp | 600 | 34sp (1.2) | Write Review headline "How was your experience with {name}?" only (`headlineLarge`, as the Dashboard hero) |

`titleMedium` / `labelLarge` (16 / 600): notification title, date section headers ("Today", "Yesterday", "Earlier"), the Feedback block header "Your feedback", the hint-row text, the banner title, button labels, `**bold**` spans inside a notification body (weight 600, same 16sp, still `onSurface`-family color). `bodyLarge` (16 / 400): bodies and the review text. `bodySmall` (12 / 400): timestamps, topic caption, counter, end note. `titleLarge` (20 / 600): app bar titles are the existing `AuthTopAppBar` style.

|------|-------|---------------------|
| Dominant (60%) | `#131313` `surface` | Every screen background, both app bars, the Write Review footer bar, the bell and avatar action area |
| Secondary (30%) | `#1C1B1B` `surfaceContainerLow`, `#201F1F` `surfaceContainer`, `#2A2A2A` `surfaceContainerHigh` | Notification rows, the permission-off hint row, the already-submitted banner, the Feedback block card, the read-only review text container: `surfaceContainerLow`, `medium`, 1dp `outlineVariant`. Accent reserved for (and nothing else in this phase):
1. Fill of the single primary CTA per surface: "Submit review" (Write Review footer) and "Retry" in the list and Write Review error states (via `EmptyStateAction`).
2. The glyph and 12% tile fill of the icon tile on booking, session, message and review rows (the four interactive categories, iOS `iconIsPrimary`). Payout and account tiles are neutral (`onSurfaceVariant` glyph, `surfaceContainerHigh` fill).
3. Focused border and cursor of the review field; every `CircularProgressIndicator`, including the pull-to-refresh indicator and the Submit spinner.
4. The `TaskAlt` glyph in the already-submitted banner.
5. The notification accent color (Surface 6): the small-icon tint of every ClickMe notification, set from `ClickMePalette.primary`.

Neutral, deliberately not accent: both bells (`onSurface` outline glyph), date section headers, notification titles and bodies (including bold spans, which iOS tints green; here they are semibold `onSurface`), timestamps, the "Turn on" text, "End of recent updates", Leave a Review button and the Past card action (outlined `onSurface` with a `StarBorder`, 1dp `outlineVariant`), the Feedback card, empty and error glyphs, empty stars (`onSurfaceVariant`).

## Motion

Phase 1 durations. All of it follows the system animator duration scale; with animations off every transition is instant.

| Interaction | Duration / easing |
|---|---|
| Push / pop of Notifications and Write Review | Phase 1: horizontal slide + fade, 300 ms (`PUSH_POP_DURATION_MS`, `pushPopEasing`); predictive back drives pops |

| Snackbar, dialogs | M3 defaults |
| Button press | Phase 1 press scale 0.96, 120 ms (`PressScaleButton`) |

## Navigation and Structure

```
Client shell (HomeClientShell) and Expert shell (HomeExpertShell): per-tab Navigation 3 back stacks.
Detail entries use BottomBar.hidden().

Explore stack (client):   ExploreRoot
   |- bell                >  NotificationsKey(origin = ClientExplore)        (also the push landing for unrouted pushes, D-10/D-11)
   |      |- row tap      >  routed through the PushDestination map (D-05..D-10); the destination is pushed on this
   |                         stack or on the destination's own tab per the push routing rules

Dashboard stack (expert): DashboardRoot
   |- bell                >  NotificationsKey(origin = ExpertDashboard)

Bookings stack (client):  MyBookingsRoot
   |- Past card "Leave a review"      >  WriteReviewKey(bookingId, expertName, expertAvatarUrl)
   |- Past card tap                   >  BookingSummaryKey
          |- "Leave a review" button  >  WriteReviewKey(...)          (pushed on the same stack as the Summary)
                 |- submit success    >  pop to the previous entry; the Summary or list reloads; snackbar "Thanks for your review"
```

Keys are `@Serializable NavKey` data classes registered next to the existing keys in both shells. `NotificationsKey` carries an `origin` so the same screen is a distinct entry on the Explore and Dashboard stacks (Phase 10/11 Pitfall 7). `WriteReviewKey` carries the expert name and avatar URL as a display seed so the header renders before the context call returns (iOS `seedExpertName`, `seedExpertImageURL`). If a `NotificationsKey` with the same origin is already the top entry of the stack, a repeat bell tap does nothing.

| Screen | App bar | Back behavior |
|---|---|---|
| Notifications | `AuthTopAppBar`, back arrow (`AutoMirrored` Outlined), title "Notifications", no actions | Pops to Explore / Dashboard. Never blocked |
| Write Review | `AuthTopAppBar`, back arrow, title "Leave a Review", no actions | Pops to the previous entry. While Submit is in flight Back (arrow, system, predictive) is ignored and the arrow is disabled (`backEnabled = false`, Phase 8 convention). Typed text is discarded on Back with no confirmation (iOS) |

**Bell placement.** Both bells are the shared `NotificationBellButton`: a 48dp `IconButton` with `Icons.Outlined.NotificationsNone` 24dp `onSurface`, `contentDescription` "Notifications", placed immediately before `TopBarAvatarButton` in the app bar `actions`, with no gap other than the two 48dp targets. No badge and no dot (D-16: no unread state). Explore: add it to the existing `TopAppBar` actions in `ExploreScreen.kt` (title stays "Explore"). Dashboard: add it to the `AuthTopAppBar` actions in `ExpertDashboardScreen.kt`. Note the `NotificationsNone` already in `DashboardHeader.kt` is the Pending-requests banner icon, not a bell button; it is unchanged (see Open Items 1). The bell is hidden in no state. Test tags `explore_notifications_bell`, `dashboard_notifications_bell`.

Insets: pushed screens use `safeDrawing`; the list handles the bottom with `contentPadding` `xl` plus the navigation-bar inset; Write Review's footer sits above the navigation inset and the IME (`imePadding()`).

## Screen Specifications

### 1. Notifications list (PUSH-05, D-11, D-16, D-17)

Route `NotificationsKey(origin)`. Background `surface`. `GET /notifications?page=1&limit=50`, first 50 only, no paging, no read state. Refresh: first load on entry; a quiet reload when the screen is shown again (`ON_RESUME`) and whenever the foreground-push refresh signal ticks (D-12); pull-to-refresh via `PullToRefreshBox`.

| State | Rendering |
|---|---|
| Loading (first load) | `NotificationsSkeleton`: a 80 x 20 section-header bar, then three row blocks copying the real row (`surfaceContainerLow` `medium` card, a 48dp circle, a 200 x 16 bar, a 240 x 16 bar, a 96 x 12 bar), `md` between, `xl` to a second header bar and two more rows. "Loading" description. The permission-off row is not shown while loading |
| Failed (first load) | `EmptyState` (`ErrorOutline`): heading "Couldn't load notifications", body = server message, else "Check your connection and try again.", action "Retry" (filled). Inside a `verticalScroll` `fillMaxSize` column so pull-to-refresh works |
| Empty (loaded, zero items) | `EmptyState` (`NotificationsNone`): heading "You're all caught up", body "No new notifications right now.", no action. Pull-to-refresh still works. The permission-off row (if applicable) sits above it |
| Loaded | Optional permission-off row, then the sections, then the end note |
| Quiet reload | Rows update in place and never return to the skeleton. A failed pull-to-refresh shows the snackbar "Couldn't refresh. Check your connection and try again." (carried); a failed resume or push-triggered reload shows nothing |

Layout: `LazyColumn`, `md` horizontal padding, `lg` top, `xl` plus navigation inset at the bottom, `xl` between sections, `md` between a section header and its first row and between rows.

**Date sections (`NotificationSectionHeader`).** Bucketed by the local calendar day of `created_at`: "Today" (on or after local midnight), "Yesterday" (the previous local day), "Earlier" (anything older). Empty sections are omitted. Server order (newest first) is kept inside each section. Header text: `titleMedium` `onSurfaceVariant`, sentence case, `heading()`.

**Row (`NotificationRow`).** `surfaceContainerLow`, `medium`, 1dp `outlineVariant`, `md` padding. `Row`, `md` between, top-aligned: `NotificationIconTile` (48dp circle, `surfaceContainerHigh` fill with 1dp `outlineVariant` for neutral categories; `primary` at 12% fill with a `primary` glyph for the four interactive categories), then a column (weight 1, `xs` between lines):

| Block | Spec |
|---|---|
| Title | `titleMedium` `onSurface`, wraps (no max lines) |
| Body | `bodyLarge` `onSurfaceVariant`, wraps. `**text**` spans render as weight 600 in `onSurface`; any other markup is shown literally; an unmatched `**` is shown literally |
| Timestamp | `bodySmall` `onSurfaceMuted`, `xs` above. Today: "Just now" (under 60 s), "{n} min ago" (under 60 min), "{n} hr ago". Yesterday: "Yesterday, {h:mm a}" in the device time format. Older: "{MMM d}, {h:mm a}" in the device locale |

Category glyphs (the six backend categories): `booking` `CalendarMonth`, `session` `Timer`, `message` `ChatBubbleOutline`, `review` `StarBorder`, `payout` `Payments`, `account` `Shield`; any other category `NotificationsNone` with the neutral tile. Rows are not truncated and have no unread dot, no chevron and no swipe action.

**Row tap (D-16).** A row whose notification resolves to a destination other than the notifications list is one `Role.Button` (`onClickLabel` "Open notification") and routes through the same `PushDestination` map and pending-destination slot as a real push tap. A row that resolves to no destination, or to the notifications list itself (payout and account until Phase 14, D-10; unknown categories; rows missing their id), is not clickable: no ripple and no `Role.Button`, so there is no dead tap. Rows keep their normal text semantics.

**End note (`NotificationsEndNote`).** After the last section, centered "End of recent updates" (`bodySmall` `onSurfaceMuted`), `md` vertical padding. iOS draws a 128dp bordered card here; the note is shortened to a text row (Deviations).

**Permission-off hint row (`NotificationsOffRow`, D-02).** The first item of the list content, shown in the Loaded and Empty states only when `NotificationManagerCompat.areNotificationsEnabled()` is false, hidden otherwise, and re-evaluated on every `ON_RESUME` (so it disappears after the user turns notifications on in system settings, 200 ms fade and shrink). Container `surfaceContainerLow`, `medium`, 1dp `outlineVariant`, `heightIn(min = 56.dp)`, `md` padding, `md` below. `Row`, `sm` between, centered: `NotificationsOff` 24dp `onSurfaceVariant`, "Notifications are off" (`titleMedium` `onSurface`, weight 1, wraps), and the visible label "Turn on" (`labelLarge` `onSurface`, underlined, the Phase 5 text-link style; not accent). The whole row is one `Role.Button` (`onClickLabel` "Open notification settings"); it merges to the spoken text "Notifications are off — Turn on". Tap launches `Settings.ACTION_APP_NOTIFICATION_SETTINGS` with `EXTRA_APP_PACKAGE`. There is no dismiss control and no snooze. Test tag `notifications_off_row`.

Test tags `notifications_list`, `notification_row`, `notifications_retry`.

### 3. Write Review (REV-01, D-18, D-19)

Route `WriteReviewKey(bookingId, expertName, expertAvatarUrl)`. Background `surface`. `GET /bookings/{id}/reviews/context` on entry, `POST /bookings/{id}/reviews` on submit with `{rating, comment?}`. Client-only; reachable only from a completed booking (Booking Summary, Past card).

| State | Rendering |
|---|---|
| Loading | `WriteReviewSkeleton`: a 96dp circle, a 240 x 28 bar and a 280 x 16 bar (centered), a five-star row of 40dp blocks, a `medium` 160dp field block, and a 56dp footer block. "Loading" description |
| Failed (context) | `EmptyState` (`ErrorOutline`): heading "Couldn't load review", body = server message, else "Check your connection and try again.", action "Retry" (filled; re-runs the context call). No footer |
| Ready (not yet reviewed) | The form below with the Submit footer |
| Already submitted (`has_submitted`) | Read-only form below, no footer, the banner at the top |
| Submitting | Stars and field lock, the Submit label is replaced by a 24dp `onPrimary` spinner (`stateDescription` "Submitting"), Back is ignored, repeat taps are ignored |

**Form (a `verticalScroll` column, centered, `md` horizontal padding, `lg` top, `lg` between blocks, `imePadding()`, `xl` plus navigation inset at the bottom).**

| Block | Spec |
|---|---|
| Avatar | `Avatar` 96dp, expert photo from the context (`review_target.avatar_url`) falling back to the key seed, then the person silhouette. No ring, no glow (iOS draws a pulsing green glow) |
| Headline | "How was your experience with {name}?" — `headlineLarge` `onSurface`, centered, `maxLines = 3`, `heading()`. `{name}` comes from the context (`review_target.name`) falling back to the key seed, then "your expert" |
| Subtitle | "Your feedback helps other users and experts." — `bodyLarge` `onSurfaceVariant`, centered, `sm` below the headline |

`PastBookingCard.kt`. ### 6. System notification presentation and the permission prompt (PUSH-01, PUSH-02, D-01, D-03, D-12)

**Permission timing (D-01).** The `POST_NOTIFICATIONS` system dialog is the only UI. It is requested once, right after a successful login or signup, when the destination screen is composed (a `LaunchedEffect` in the home shell or the post-signup landing screen, mirroring `MicPermissionRequester`), never over the login form's loading state and never during a call. It does nothing below API 33 and nothing if the user has already answered. There is no rationale sheet, no pre-prompt and no second ask (D-02). A denial changes only the permission-off row in the list.

**Channels (`NotificationChannels`, D-03).** Created idempotently at app start (`Application.onCreate`) and again before any foreground post. The ids are a contract with `backend-reference/src/services/push.js` (D-04) and must match exactly; renaming one orphans users' per-channel settings.

| Channel id | Name (user-visible) | Description (user-visible) | Importance | Backend `category` mapped to it |
|---|---|---|---|---|
| `bookings` | Bookings | Requests, confirmations, changes and cancellations for your bookings. | High | `booking` |
| `sessions` | Sessions | Reminders and updates about your live sessions. | High | `session`, `review` |
| `messages` | Messages | New chat messages from experts and clients. | High | `message` |
| `account_payouts` | Account & payouts | Payout and account security updates. | High | `payout`, `account` |
| `general` | General | Other ClickMe updates. | Default | anything else; also the manifest `default_notification_channel_id` |

The existing `ongoing_call` channel (Low importance) is unchanged and separate. `review` pushes map to Sessions so review nudges arrive with the session they belong to (user-confirmed 2026-10-27; CONTEXT D-04 amended). A foreground post on a Default channel appears in the shade with a status-bar icon but without a heads-up banner; that is the platform behavior for Default importance.

**Small icon and accent color.** A new vector `ic_stat_clickme.xml` (24dp, white-only, transparent background, derived from the launcher monochrome mark) is the small icon for every ClickMe push; the manifest sets `com.google.firebase.messaging.default_notification_icon` to it so background (system-rendered) notifications use it too. The accent color is `primary` `#44F697`: foreground posts use `ClickMePalette.primary.toArgb()` (as `CallNotificationFactory`); the manifest `default_notification_color` needs an XML color, so add `res/values/colors.xml` with `notification_accent` = `#44F697`, with a comment that it mirrors `ClickMePalette.primary`, the only hex outside `Color.kt` (the design-rules script must allow it or be told; Open Items 5). No large icon, no inline image.

**Content and behavior.** Title and body are the FCM `notification.title` and `notification.body` exactly as the backend sends them (same strings as the list rows, with `**` markers stripped for display). Foreground-posted notifications (D-12): `NotificationCompat` on the push's channel (falling back to `general`), `setAutoCancel(true)`, `BigTextStyle` for bodies longer than one line, category-appropriate `setCategory` (`CATEGORY_MESSAGE` for messages, `CATEGORY_EVENT` for bookings and sessions, `CATEGORY_STATUS` otherwise), `VISIBILITY_PRIVATE` with a public version titled "ClickMe" and the text "You have a new notification" (the call notification precedent). The notification id is stable per `(category, entity id)` (thread id or booking id) so a repeat for the same thread or booking updates in place; pushes without an entity id use a fresh id. No explicit group summary (the system auto-groups). Tap: a `PendingIntent.FLAG_IMMUTABLE` that opens `MainActivity` with `CLEAR_TOP | SINGLE_TOP` and the push `data` as string extras (the same flags as the call open intent), feeding the pending-destination slot (D-15). No action buttons. A chat push for the thread currently on screen is not posted (D-13).

## Accessibility Contract

- Touch targets at least 48dp: bells, each star, the hint row (56dp), notification rows, the Past card action, Retry, dialog buttons.
- A notification row exposes one merged node: "{title}, {body with ** stripped}, {timestamp}", with `Role.Button` and `onClickLabel` "Open notification" only when it is tappable. Section headers are `heading()`.
- The hint row is one `Role.Button` reading "Notifications are off — Turn on". The already-submitted banner and the empty/failed states are polite live regions where they replace content.
- The star group is a `selectableGroup` read once ("5 stars, selected"); each star is `Role.RadioButton`. The read-only stars are one node, "Rated {n} out of 5". The Feedback block stars read the same.
- In-flight Submit exposes `stateDescription` "Submitting". The disabled-looking states are avoided: Submit is always enabled once ready.
- Headings (`heading()`): "Today" / "Yesterday" / "Earlier", the Write Review headline, "Your feedback", the empty and error headings.
- The review field has the semantics label "Written review, optional" (the placeholder is not the only name); the IME never covers it (`imePadding()`); the footer rides above the IME.
- The Past card nests a clickable action inside a clickable card. The executor must confirm TalkBack exposes both; if it merges them, expose "Leave a review" as a custom accessibility action on the card.
- 200% font scale: rows, the hint row, the banner and the headline grow (`heightIn`, never fixed heights); the Write Review headline wraps; the five star targets stay 48dp (a 240dp group fits every phone width). Check the list with and without the hint row, Write Review in both states, and the Past card with the action.
- Reduce motion: with the animator scale at 0 every transition (row insert, hint row, Feedback block) is instant.
- Notifications are not the only channel for information: every push-routed destination is also reachable through the list or the tab screens.
- A full TalkBack pass is Phase 15 (POL-04).

## Assumptions and Open Items (for the planner and checker)

The run was non-interactive, so these were decided without the user:

- **A1. Bell placement.** The bell is a 48dp `IconButton` immediately before the avatar in both app bars, with no badge (D-16 has no unread state).
- **A2. Row tap on routeless rows.** A row that resolves to nothing, or to the notifications list itself, is inert rather than a button that does nothing. D-16 only says tapping routes through the map; D-10 makes payout and account resolve to the list.
- **A3. Channel importance.** Bookings, Sessions, Messages and Account & payouts are High so the D-12 foreground heads-up appears; General is Default. CONTEXT pinned only Messages and Sessions as high.
- **A4. Channel ids** `bookings`, `sessions`, `messages`, `account_payouts`, `general`, and `review` pushes on `sessions`. These are the backend contract; changing them after release orphans user settings.
- **A5. Default 5 stars.** Write Review preselects 5 (iOS parity), so Submit is always enabled once ready. If the product prefers no default, the footer would need a disabled state.
- **A6. Leave a review stays visible while the review state is unknown** (context pending or failed), and on Past cards for every completed booking, because the list payload has no review flag. Write Review resolves the truth with its read-only state.
- **A7. Leave a review sits between Book Again and Message Expert** on Booking Summary (iOS puts it last) because review pushes land there.
- **A8. Bold spans are not accent** in notification bodies, and the empty-state icon differs from the permission-off icon.
- **A9. Public version of foreground notifications** is generic ("You have a new notification") with `VISIBILITY_PRIVATE`; system-rendered background notifications follow the channel default and cannot be restyled by the app.
- **A10. No snackbar for an automatic mode switch (D-05).** The existing Phase 4 transition and the tab set change are the only cue.

Open items:

1. **Dashboard bell.** CONTEXT says `DashboardHeader.kt` already has the bell icon; the `NotificationsNone` there is the Pending-requests banner icon. The actual bell action belongs in the `AuthTopAppBar` `actions` of `ExpertDashboardScreen.kt` (beside `TopBarAvatarButton`). The planner confirms.
2. **Review state in the data.** `ClientBookingItem` (list) and `ClientBookingDetail` carry no review fields, and iOS also resolves it separately. Booking Summary needs a quiet `GET /bookings/{id}/reviews/context` call (or the Write Review context cached by the repository) to know `has_submitted`, the rating and the comment. The Past card cannot know per-card review state without a backend `has_review` flag; the in-memory reviewed-ids set bridges the session. Raise a backend follow-up if the always-visible action proves noisy.
3. **Reload-and-snackbar hand-off** from Write Review to the screen below it follows the Phase 8 launch-argument pattern (a one-shot field on shared client state), because the destination may be Booking Summary on the Bookings stack or on another tab stack.
4. **Backend `channel_id` mapping** (D-04): `booking`→`bookings`, `session` and `review`→`sessions`, `message`→`messages`, `payout` and `account`→`account_payouts`, else `general`. The `review`→`sessions` mapping was user-confirmed on 2026-10-27 (CONTEXT D-04 amended); the backend task still confirms the category names from `events.js` (`EVENT_CATEGORY`).
5. **Design-rules script.** The `notification_accent` XML color is the only hex outside `Color.kt`. `scripts/check-design-rules.sh` must either exempt `res/values/colors.xml` or this one value is added with an explicit allow comment. `ic_stat_clickme.xml` must be derived from the launcher monochrome mark; if the mark does not reduce cleanly to 24dp, fall back to the `ic_stat_call` pattern with a simple bell silhouette.
6. **Deferred manual checks** (project preference): permission prompt on a fresh Android 13+ install, deny then the list hint row and system settings round trip, one push per channel in foreground and background with icon and accent, a notification tap from cold start and while running, the list with a foreground push arriving, the Past card nested-click and TalkBack behavior, 200% font scale on the list (with and without the hint row), Write Review (both states) and the Past card.
7. **Probe not run interactively.** The UI Considerations table was derived by hand from the six surfaces; re-run the probe if the checker requires the original run record.
