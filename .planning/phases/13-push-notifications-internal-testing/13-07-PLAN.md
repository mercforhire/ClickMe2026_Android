## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| push payload -> mode switch | A payload (possibly forged through the exported activity) can ask for the other mode |
| backend -> resolver | Booking status and request expiry come from authenticated GETs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-13-18 | Elevation of privilege (accidental) | Push-driven switch to Expert for a client-only account | high | mitigate | `allowSwitch` requires the expert role for a switch to Expert; `noExpertRoleNeverSwitchesToExpert` test (RESEARCH F-5) |
| T-13-19 | Denial of service | Mode switch during a live call | medium | mitigate | `allowSwitch` refuses while `callActive`; the current list opens instead; `switchBlockedDuringCallOpensCurrentList` test |
| T-13-20 | Information disclosure | Probing another user's booking | low | accept | The probe uses the user's own token; the server answers 404/403 and the resolver only learns "not my client booking" |
| T-13-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs in this plan |
</threat_model>
