# Phase 7 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Requirements PAY-01 to PAY-07. Five surfaces:
> 1. The Payment Methods screen (new route `PaymentMethodsKey`), with its remove and error dialogs.
> 2. The Payment Methods row on the client Profile placeholder tab.
> 3. The paid changes to Make a Booking: the CTA label switch, the "How does payment work?" link and sheet, the in-flight states of the paid flow, and the extended error dialog.
> 4. The shared `PaymentLifecycleCard` composable (used by the info sheet and by Request Sent).
> 5. The paid card on Request Sent.
>
> Out of scope and must not appear in the UI: promo codes, the `payment-intent` summary total, payment history, reschedule payment, payouts, the Profile hub (Phase 14).
>
> **Baseline.** `01-UI-SPEC.md` (tokens, shapes, motion), `04-UI-SPEC.md` (picker sheet) and `06-UI-SPEC.md` (booking form, Request Sent, error dialog) are locked and not restated. Dark only, Material 3, Nunito 400 / 600, exactly four text sizes (12 / 16 / 20 / 28 sp), `Spacing` xs..xxxl, `ClickMeShapes`, `MaterialTheme.extras`. Every value below is an existing token unless marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/.../Settings/Payment Methods/**`, `Make a Booking/**` and `Request Sent/**`. Copy is taken from iOS verbatim unless marked "(Android)". `PaymentMethodsBrand` (a per-screen palette) collapses to the Phase 1 tokens (FND-02). Layout is ported, not pixel-matched.
>
> **Source of decisions.** CONTEXT D-01..D-17 for everything listed there. This spec fills the "Claude's Discretion" areas: skeleton and empty-state visuals, brand icons, lifecycle component location, PaymentSheet appearance, and the exact copy for dialogs and steps. The user was not available during this session, so every assumption is recorded in "Assumptions and Open Items".

## Spacing Scale

Phase 1 tokens, all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

| Token | Used for in this phase |
|-------|------------------------|
| xs (4dp) | Gap between a row's card name and its expiry line; gap between the connector line and its neighbors in the lifecycle card |
| sm (8dp) | Section label to first row; icon-to-text inside the Add button, the info link and badges; badge horizontal padding; gap between a step title and its subtitle |
| md (16dp) | Screen horizontal padding (iOS 20); row inner padding; gap between rows (iOS 10, widened); card inner padding; gap between a step badge and its text; gap between the sheet's text blocks |
| lg (24dp) | Top padding under the app bar; gap between the card list, Add button and trust copy (iOS 16, widened); empty-state top offset; gap above the "How does payment work?" link (the booking form's section gap) |
| xl (32dp) | Bottom scroll padding on Payment Methods and in the info sheet; empty-state icon-to-text spacing (inherited) |
| xxl (48dp) | Minimum touch target (overflow button, link, menu items) |
| xxxl (64dp) | Not used |

Exceptions (component dimensions and platform minimums, not layout spacing):
- Touch targets stay at least 48dp: overflow `IconButton` 48 x 48 (iOS 32), the "How does payment work?" link `heightIn(min = 48.dp)`, `DropdownMenuItem` rows (M3 default 48dp), dialog buttons, Retry.
- Controls (Add Payment Method, Got it, Book Now) use `heightIn(min = 56.dp)` (inherited).
- Card-brand tile: 48 x 32dp, `extraSmall` shape (iOS 44 x 30). Icon inside 24dp.
- Lifecycle step badge: 32dp circle (iOS 28), icon 16dp. Connector: 2dp wide, 16dp tall (iOS 14), horizontally centered under the badge (`Alignment.CenterHorizontally` within the badge's 32dp column, not a hard-coded offset).
- "Default" badge height is content-driven (`labelMedium` line height 16dp plus `xs` vertical padding).
- Busy spinner: 24dp `CircularProgressIndicator`, 2dp stroke, centered in a 48dp box that replaces the overflow button (the row does not change height).
- Stroke widths 1dp resting (hairlines).
- Skeleton shapes copy the real component dimensions above.

## Color

Dark only. All colors come from the Phase 1 ColorScheme and `MaterialTheme.extras`. No hex literal appears in this phase's code, with one exception that is still no literal: PaymentSheet's `Appearance` takes ARGB ints, so it is built with `Color.toArgb()` from `MaterialTheme.colorScheme` / `extras` (see Stripe UI).

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `#131313` `surface` | Payment Methods background and app bar |
| Secondary (30%) | `#1C1B1B` `surfaceContainerLow` and `#201F1F` `surfaceContainer` | Card rows, lifecycle card, Profile row: `surfaceContainerLow`, `medium`, 1dp `outlineVariant`. Brand tile: `surfaceContainer`. Info sheet: `surfaceContainerHigh` (container) |
| Accent (10%) | `#44F697` `primary` | See reserved list |
| Destructive | `#FFB4AB` `colorScheme.error` | The "Remove" menu item (text and icon) and the "Remove" confirm button in the remove dialog. Nothing else. (`extras.destructive` `#FF4D4D` measures 4.39:1 on `surfaceContainerHigh`, below 4.5:1, so the A5 fallback applies: use `error`) |

Accent reserved for (and nothing else in this phase):
1. Fill of the single primary CTA on each surface: "Add Payment Method" (Payment Methods), "Got it" (info sheet), and the existing "Book Now" / "Add a Payment Method" CTA on the booking form.
2. The "Default" badge fill (`onPrimary` text).
3. The "done" state of a lifecycle step: badge fill `primary` at 18% alpha, check icon `primary`, and the connector after it at 35% alpha.
4. Every `CircularProgressIndicator` (loading, busy row, Add button spinner uses `onPrimary` on the filled button).
5. The PaymentSheet primary button and focus color (Stripe UI).

Neutral, deliberately not accent: the "How does payment work?" link and its icon (`onSurfaceVariant`; iOS uses green, dropped per the Phase 1 accent rule), the overflow icon (`onSurfaceVariant`), the trust copy and expiry (`onSurfaceMuted`), the "Set as default" menu item (`onSurface`), future lifecycle steps (badge fill `outlineVariant` at 38%, icon `onSurfaceMuted`, connector `outlineVariant`).

Contrast: `onPrimary` on `primary` 9.3:1 (button, badge); `onSurfaceMuted` on `surfaceContainerLow` at least 5.9:1; `destructive` (`#FF4D4D`) on `surfaceContainerHigh` (`#2A2A2A`) measured 4.39:1 by the checker, which fails AA for 16sp text, so the destructive text and icon use `colorScheme.error` (`#FFB4AB`, well above 4.5:1).

## Navigation and Structure

```
Client shell (HomeClientScreen entryProvider):
  PaymentMethodsKey (object NavKey, no arguments)   BottomBar.hidden()

Profile tab back stack (ClientProfileRoot):
  Profile placeholder
   └─ Payment Methods (PaymentMethodsKey)
        ├─ PaymentSheet (Stripe Activity, setup mode)      not a route
        ├─ Remove dialog / error dialog (AlertDialog)      not routes

Explore tab back stack (ExploreRoot):
  Explore home > Expert Profile > Make a Booking (BookingKey)
   ├─ Payment Methods (PaymentMethodsKey)   only from the no-card CTA (D-08)
   ├─ "How does payment work?" sheet        (ModalBottomSheet, not a route)
   ├─ PaymentSheet FlowController           (Stripe UI, not a route)
   ├─ 3DS challenge                         (Stripe UI, not a route)
   └─ "Couldn't book" dialog                (AlertDialog, not a route)
```

| Screen | App bar | Back behavior |
|---|---|---|
| Payment Methods | `AuthTopAppBar`, title "Payment Methods" (iOS title is "Payment"; Android uses the row's name so the title matches what the user tapped), back arrow ("Back") | Pops to the origin: Profile tab or Make a Booking. Nothing to discard. While an add, remove or set-default call is in flight Back still pops; the call finishes in the ViewModel and its result is dropped when the screen is gone |

Return to the booking form (D-09): when Make a Booking resumes after Payment Methods was popped, it reloads `/me/payment-methods` (silent, no skeleton), keeps every selection, and recomputes the CTA label. Nothing continues automatically. Implement as a resume-driven refresh (`LifecycleEventEffect(ON_RESUME)` calling a ViewModel method that only reloads cards), not a nav result, so the Profile and booking origins behave the same.

Insets: Payment Methods handles `safeDrawing`; scroll content uses `contentPadding` with `xl` bottom plus the navigation-bar inset. The info sheet content has `xl` bottom padding above the navigation-bar inset.

## Screen Specifications

### 1. Payment Methods (PAY-01, PAY-02, D-04..D-07)

Background `surface`. Content depends on the list state.

| State | Rendering |
|---|---|
| Loading (first load) | Centered column: `CircularProgressIndicator` (`primary`), `sm`, "Loading payment methods…" `bodyLarge` `onSurfaceMuted` (iOS caption; Android uses body for 16sp legibility). `liveRegion = Polite`. Group `contentDescription` "Loading" |
| Failed | `EmptyState` (`Outlined.ErrorOutline`): heading "Couldn't load payment methods", body = server message, else "Check your connection and try again.", action "Retry" (re-runs the load with the Loading state). `liveRegion = Polite` |
| Empty | Scrolling column with `lg` top padding: `EmptyState` (`Outlined.CreditCard`), heading "No saved cards yet", body "Add your first card to book faster next time."; then `lg`, the Add button, `lg`, the trust copy |
| Loaded | Scrolling `LazyColumn`: `md` horizontal padding, `lg` top padding. Order: "Saved cards" label, rows, Add button, trust copy. `md` between rows; `lg` between the last row and the Add button and between the button and the trust copy |
| Reload after add, remove or set-default | Silent: the list stays on screen and updates in place. Never returns to the full-screen Loading state. A failed silent reload keeps the previous list (the action's own result alert, if any, is the only message) |

**"Saved cards" label.** `bodySmall` `onSurfaceMuted`, `xs` horizontal padding, `sm` below. Heading semantics (`heading()`).

**Card row (`PaymentMethodRow`).** `surfaceContainerLow`, `medium`, 1dp `outlineVariant`, `md` padding, `heightIn(min = 72.dp)`. Not clickable as a whole (the iOS row is not tappable either); actions live in the overflow menu. Layout, start to end:

| Element | Spec |
|---|---|
| Brand tile | 48 x 32dp, `surfaceContainer`, `extraSmall`; `Outlined.CreditCard` 24dp `onSurface` centered. Every brand uses the same icon (iOS does the same); the display name carries the brand. Decorative |
| Text column | `md` after the tile, flexible. Line 1: "{Brand} •••• {last4}" `titleMedium` `onSurface` (the dots are U+2022 bullets, 4 of them, not iOS's middle dots; wraps, `maxLines = 2`), followed on the same line when wide enough by the Default badge (`FlowRow` so it wraps below at large font scales), `sm` gap. Line 2: `xs` below, "Expires {MM}/{YY}" `bodySmall` `onSurfaceMuted` (month zero-padded, year last two digits) |
| Default badge | Only on the default card. `CircleShape`, `primary` fill, "Default" `labelMedium` `onPrimary`, `sm` horizontal and `xs` vertical padding |
| Trailing | `IconButton` 48dp with `Outlined.MoreVert` 24dp `onSurfaceVariant`, contentDescription "More options for {Brand} •••• {last4}". Opens the overflow menu. While this row is busy the button is replaced by the 24dp spinner in a 48dp box |

Brand display names (iOS `PaymentMethodBrandDisplay`): `visa` Visa, `mastercard` Mastercard, `amex` American Express, `discover` Discover, `diners` Diners Club, `jcb` JCB, `unionpay` UnionPay, anything else "Card". Matching is case-insensitive.

**Overflow menu (D-05).** M3 `DropdownMenu` anchored to the trailing button, `surfaceContainerHigh`. Items (`bodyLarge`, leading icon 24dp):

| Item | Shown | Icon | Color |
|---|---|---|---|
| "Set as default" | Only when the card is not the default | `Outlined.StarOutline` | `onSurface` |
| "Remove" | Always | `Outlined.Delete` | `colorScheme.error` text and icon |

Choosing "Set as default" closes the menu and starts the call. Choosing "Remove" closes the menu and opens the remove dialog.

**Busy rule (D-06).** Only one set-default or delete runs at a time. While one runs, its row shows the spinner and the other rows' overflow buttons are disabled (38% alpha, not focusable as enabled) so a second operation cannot start. The Add button stays enabled (it is independent), but not while its own setup-intent call is in flight.

**Add Payment Method button.** Full width, `PressScaleButton` filled (`primary` / `onPrimary`), `heightIn(min = 56.dp)`. Content: `Outlined.AddCircle` 24dp, `sm`, "Add Payment Method" (`labelLarge`). While the setup-intent call is in flight the icon is replaced by a 24dp `onPrimary` spinner and taps are ignored; the label stays. `stateDescription` "Adding" while minting. Flow: tap, `POST /me/payment-methods/setup-intent`, present the PaymentSheet in setup mode (Stripe UI below). Completion reloads the list silently; cancel does nothing; a failure shows the "Couldn't add card" alert. iOS blocks this entry during an active call (Agora audio session); Phase 9 owns that guard and adds it here if Stripe is found to interfere (Open Item 4).

**Trust copy.** "Cards are securely stored by Stripe. ClickMe never sees your full card number." `bodySmall` `onSurfaceMuted`, centered, `md` horizontal padding. Static text, not a live region.

**Remove dialog (D-06).** `AlertDialog` (`surfaceContainerHigh`, `extraLarge`). Title "Remove this card?" (`titleLarge`). Message (`bodyLarge`, `onSurfaceVariant`): "{Brand} •••• {last4} will no longer be available at checkout." Buttons: dismiss `TextButton` "Cancel" (`labelLarge`, `onSurface`); confirm `TextButton` "Remove" (`labelLarge`, `colorScheme.error`). Scrim tap and Back cancel. Confirm closes the dialog first, then starts the delete with the row spinner. Removing the default card does not promote another card in the app (D-07): after the DELETE the list is reloaded and shows whatever default the server returns, which may be none; the "Default" badge then appears on no card.

**Error alerts.** `AuthErrorDialog`, one at a time, one "OK" button. Message = the server's `message`, else the standard network copy "Check your connection and try again." Titles by source:

| Source | Title |
|---|---|
| Add: setup-intent call failed, or PaymentSheet reported a failure (Stripe error message) | "Couldn't add card" |
| Set as default failed | "Couldn't update" |
| Remove failed | "Couldn't remove" |

A failed initial load or retry uses the in-page failed state, not an alert.

### 3. Make a Booking, paid changes (PAY-03..PAY-07, D-08..D-16)

Everything from Phase 6 stays except what is listed here. The default selected topic is `topics.first` again (D-10; changing the topic still clears the slot). The Summary price row shows the topic price through `Money.format` (no change; the sheet and topic row already list paid prices).

**CTA (replaces the "coming soon" note).** The Phase 6 paid note ("Booking paid sessions is coming soon...") and its `BookDisabledReason.PaidTopic` state are removed. The button keeps its footprint (`PressScaleButton`, full width, `heightIn(min = 56.dp)`, filled).

| Situation | Label | Enabled | `stateDescription` when disabled |
|---|---|---|---|
| Free topic, slot chosen | "Book Now" | yes | - |
| Free topic, no slot | "Book Now" | no | "Choose a time slot to continue" |
| Paid topic, saved cards still loading (D-08) | "Book Now" | no | "Checking your payment methods" (Android) |
| Paid topic, no saved card or the card load failed (D-08) | "Add a Payment Method" | yes, with only a topic selected (no slot needed, iOS) | - |
| Paid topic, at least one saved card, slot chosen | "Book Now" | yes | - |
| Paid topic, at least one saved card, no slot | "Book Now" | no | "Choose a time slot to continue" |
| No topic | "Book Now" | no | "Choose a topic to continue" |
| Any request or paid step in flight | spinner | looks enabled, taps ignored (D-11) | "Booking" |

"Add a Payment Method" navigates to `PaymentMethodsKey` (D-08). The label change is a 150 ms cross-fade. This applies to short-lead and long-lead alike. A failed card load is treated as "no cards" (iOS); the failure is not shown separately, because the Payment Methods screen has its own error state and Retry.

**"How does payment work?" link (D-12).** Shown only when the selected topic is paid, directly above the CTA, centered, `lg` below the Summary (the section gap) and `md` above the button. A text button: `Outlined.Info` 16dp, `sm`, "How does payment work?" `labelLarge`, both `onSurfaceVariant`; `heightIn(min = 48.dp)`; `Role.Button`. Opens the info sheet. Not shown for free topics or with no topic.

**Info sheet (`PaymentInfoSheet`, D-12).** `PickerSheet(title = "How does payment work?")` (the sheet title is the headline, so the iOS body headline is not repeated). No search, no footer. Content in a scrolling column, `md` horizontal padding, `md` gaps, `xl` bottom padding:

1. Intro, `bodyLarge` `onSurfaceVariant`: "You pay exactly the session price — no additional fees. Here's when your card is charged."
2. `PaymentLifecycleCard` in the `Upcoming` state (nothing done, no session time).
3. "Got it" button: `PressScaleButton` filled, full width, `heightIn(min = 56.dp)`; closes the sheet.

Dismiss by drag, scrim, Back or "Got it". Open state survives rotation (`rememberSaveable`). No close "X" (iOS toolbar button; the sheet's drag handle and "Got it" cover it).

**Paid flow states and what the user sees.** The ViewModel's paid step is `Idle`, `CreatingIntent`, `CollectingPaymentMethod` or `Confirming` (exposed state; naming is the planner's call). The visible contract:

| Phase | What the user sees |
|---|---|
| `CreatingIntent` (payment-intent + setup-intent calls) | The CTA shows its in-flight spinner. Everything else stays as is. Taps on the CTA are ignored |
| `CollectingPaymentMethod` (PaymentSheet FlowController) | Stripe's sheet is on top, in setup mode, listing the customer's saved cards (customer id + ephemeral key from the setup-intent response). Behind it the CTA still shows the spinner. Dismissing the sheet without a card, or a FlowController cancel, silently resets to `Idle` and keeps the form (no alert, same `bookingAttemptId`) |
| `Confirming` (`POST /bookings/confirm`, also the retry after 3DS) | CTA spinner. Taps ignored. No other UI |
| 3DS challenge (`402 PAYMENT_REQUIRES_ACTION`) | Stripe's challenge UI on top of the form via `PaymentLauncher` with `stripeAccountId` from the 402 `detail` (never persisted). CTA spinner stays. On success the confirm is retried with the same `pm_…` (still `Confirming`). On cancel or failure see the 3DS rows below |
| Long-lead (`422 LONG_LEAD_REQUIRES_SAVED_CARD`) | No extra UI. The flow goes straight to confirm with the preferred saved card; the user sees only the spinner. (There is no "card will be charged later" notice on the booking form; Open Item 3) |
| Success | Request Sent replaces the form (Phase 6 D-12), with the paid card (below) |

System Back during any in-flight paid step is ignored (as in Phase 6 for the free path). While Stripe's UI is open, Back belongs to Stripe.

**Error dialog (D-13..D-16).** The existing "Couldn't book" `AuthErrorDialog` (title `titleLarge`, message `bodyLarge`, one "OK"). Messages are in the Copywriting Contract. Side effects happen before the dialog is shown, so dismissing it leaves a consistent form:

| Trigger | State after dismissal |
|---|---|
| `SLOT_UNAVAILABLE` / `MEETING_LINK_UNAVAILABLE` | Same as the free path (Phase 6 D-08, D-09): slot cleared, displayed month reloaded, new attempt id; or meeting type snapped back to In-app Voice |
| `BOOKING_ATTEMPT_CONFLICT`, `INTENT_EXPIRED`, `PI_CONTEXT_MISMATCH`, `PI_AMOUNT_MISMATCH` | New `bookingAttemptId`, paid flow reset, form kept; the next tap starts clean |
| 3DS cancelled or failed (D-15) | Paid flow reset, form kept, slot kept, same `bookingAttemptId` (a tap on Book Now is an idempotent retry) |
| Confirm network error or timeout (D-16) | Form kept, same `bookingAttemptId`, no automatic retry. The message ends with the payment reference when a `pi_…` exists |
| Any other `handlePaidFlowError` code | Paid flow reset, form kept |
| A confirm-phase failure not matched above | Server `message`, then a blank line and "Payment reference: {pi_…}" when a `pi_…` exists |

The payment reference is plain text in the dialog message; make it selectable (`SelectionContainer`) so the user can copy it for support. Not a separate button.

### 4. PaymentLifecycleCard (shared, PAY-07)

`surfaceContainerLow`, `medium`, 1dp `outlineVariant`, `md` padding, full width. Parameters: `currentStep: Upcoming | HoldPlaced`, `sessionWhen: String?`.

Header: "What happens next" `titleLarge` `onSurface` (`heading()`), `md` below. Three steps in a column, each a row: 32dp badge, `md`, text column (title `titleMedium` `onSurface`, wraps; `xs`; subtitle `bodySmall` `onSurfaceMuted`, wraps). A 2dp x 16dp connector sits between consecutive badges.

| # | Icon (future) | Title | Subtitle |
|---|---|---|---|
| 1 | `Outlined.Lock` | "A hold is placed on your card" | "No charge yet — funds are just reserved." |
| 2 | `Outlined.CalendarMonth` | "Your session runs on {sessionWhen}", else "Your session runs at the scheduled time" | "You can join the call from My Bookings." |
| 3 | `Outlined.Verified` | "Your card is charged after the session" | "Usually within 15 minutes of the session ending." |

| State | Badge | Connector after the step |
|---|---|---|
| Done (only step 1 in `HoldPlaced`) | `primary` at 18% alpha fill, `Outlined.Check` 16dp `primary` instead of the step icon | `primary` at 35% alpha |
| Future (every step in `Upcoming`, steps 2 and 3 in `HoldPlaced`) | `outlineVariant` at 38% alpha fill, step icon 16dp `onSurfaceMuted` | `outlineVariant` |

Step titles are `onSurface` in every state (iOS does the same). `sessionWhen` format: month-day plus the start time in the device time format, e.g. "Oct 24, 2:00 PM" (iOS "Aug 15, 2:00 PM"; no year, because the details card above already shows it). ## Interaction Contract (summary)

| Rule | Behavior |
|---|---|
| One operation at a time | Payment Methods: one set-default or delete at once (D-06). Booking: a tap during any in-flight paid step is ignored (Phase 6 D-11) |
| Not optimistic | Payment Methods rows show a spinner and the list reloads from the server afterward (D-06, D-07). iOS updates optimistically and rolls back; Android does not, so the badge never flips to a state the server rejected |
| Default after remove | The server's answer, never promoted by the app (D-07) |
| Gate | Any paid topic with no saved card (or a failed card load) routes to Payment Methods (D-08); on return the cards reload, selections stay, the user taps again (D-09) |
| `bookingAttemptId` | New on topic change and slot change (D-11), after a conflict-type error (D-13). Reused for a network retry and a 3DS cancel (D-15, D-16). Memory only (D-17) |
| Cancel silently | Dismissing PaymentSheet or FlowController without a card resets the paid flow with no message |
| Rotation / process death | Form state follows Phase 6 (`SavedStateHandle`). The paid step, `pm_…`, payment-intent id and `bookingAttemptId` are not saved: after process death the CTA is idle and the next tap starts a fresh attempt (D-17). Rotation during an in-flight paid step keeps the ViewModel state and the spinner; Stripe's own UI restores itself. The remove-dialog target, the open overflow menu and the info-sheet open state survive rotation (`rememberSaveable`) |
| Money | Minor units everywhere except `payment-intent` amounts; display only via `Money.format` (JPY no decimals) |

## Accessibility Contract

- Touch targets at least 48dp: overflow button, link, menu items, Add button (56), dialog buttons, Retry. The 32dp iOS overflow target is widened to 48.
- "Saved cards" and the lifecycle header carry `heading()` semantics.
- Each card row is a merged group "{Brand} ending {last4}, expires {MM}/{YY}, default card" (the last clause only for the default). The brand tile and bullets are decorative; the bullets are read as "ending" in the merged label, not as "bullet bullet bullet bullet".
- Busy rows announce "Updating" or "Removing" through `stateDescription` and disable the other rows' menus.
- The Default badge is not color alone: it carries the word "Default".

- The overflow menu returns focus to its trigger on dismissal (M3 default). The remove dialog states the card in its message.

- Contrast figures in the Color section. Disabled content is exempt but stays legible.
- 200% font scale: card names and the badge wrap (badge drops below the name), step titles and subtitles wrap, dialog text wraps, the sheet scrolls, the Add button label wraps within its 56dp minimum (it grows, nothing truncates). Row height grows with `heightIn`, never fixed. Check Payment Methods, the info sheet and the paid Request Sent.

## Assumptions and Open Items (for the planner and checker)

Assumptions made without the user (the session had no live questions):

- **A2. No separate paid headline (verified against iOS).** CONTEXT says Request Sent gets "the paid headline". iOS `BookingRequestSentView.swift` renders the same `BookingRequestSentHeadline` ("Request Sent!") for free and paid bookings and differentiates only with `PaymentLifecycleCard` under `!isFree`. Per CLAUDE.md (iOS is the source of truth), this spec keeps the headline and body unchanged and adds the card. A paid-specific sentence would be new copy and is risky because of Open Item 3.
- **A2. No separate paid headline.** CONTEXT says Request Sent gets "the paid headline"; iOS has one headline for both and differentiates only by the lifecycle card. This spec keeps the headline and body unchanged and adds the card. A paid-specific sentence would be new copy and is risky because of Open Item 3.
- **A3. "Save card" PaymentSheet button label** (Android only) instead of Stripe's default "Set up". Drop it if Stripe's default localization is preferred.
- **A4. Stripe appearance values** are a best match to the dark tokens; verify on a device once D-01 is resolved (contrast of Stripe's field borders on `surfaceContainerHigh`).
- **A5. Resolved.** The checker measured `destructive` (`#FF4D4D`) on `surfaceContainerHigh` (`#2A2A2A`) at 4.39:1, below 4.5:1. All destructive text and icons in this phase use `colorScheme.error` (`#FFB4AB`) instead.

Open items:

1. **Remove dialog title.** CONTEXT D-06 says "Remove this card?"; iOS says "Remove payment method?". The spec follows CONTEXT.
2. **Lifecycle card steps and the reserved/hold wording.** The card copy is iOS verbatim. It says "A hold is placed on your card", which matches the short-lead path.
3. **Long-lead bookings and the paid card.** For a booking more than 6 days out the server saves the card and charges at T-24h (RESCHEDULE-PAYMENT-CONVERSION.md), so "A hold is placed on your card" and the card's step 1 as "done" are inaccurate for that case. iOS shows the same card for both. This phase ports iOS; a long-lead variant needs a copy decision and, if the booking detail does not say which path was used, a backend field. Raise it with the iOS side; the checker should not fail the spec on it.
4. **Active-call guard on Add Payment Method.** iOS blocks Stripe's sheet during a call because it can silence Agora. Android's Agora lifecycle lands in Phase 9; add the guard there if the same problem appears.
5. **Manual checks deferred** (D-03, project preference): PaymentSheet add card, set default, delete; short-lead paid booking reaching the iOS expert; forced-failure retry with no duplicate; long-lead with a saved card; 3DS with `4000 0025 0000 3155`; JPY price with no decimals; 200% font scale on all five surfaces; PaymentSheet dark appearance; rotation during an in-flight paid step.
