<objective>
Connect the paid ViewModel to Stripe's UIs on the booking screen: the FlowController sheet and the 3DS PaymentLauncher host, the "How does payment work?" link and sheet, and the payment reference in the error dialog.

Purpose: this is the only place the paid flow touches the Stripe SDK. It is new, device-unproven code (no FlowController exists in the Phase 2 spike, RESEARCH "No Analog Found"), so it is kept small, follows RESEARCH Patterns 1-3 exactly, and is swappable for a fake in Robolectric tests; the real sheet and challenge are device checks (D-03).
Output: `PaidFlowStripeHost.kt`, screen wiring, a selectable-message option on `AuthErrorDialog`, screen tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ViewModel -> Stripe SDK UIs | SetupIntent secret, ephemeral key, PI client secret and connected account id pass to Stripe |
| Stripe UIs -> ViewModel | Selection, setup and challenge results decide whether money moves |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-46 | Tampering | Duplicate sheet or challenge after rotation | mitigate | Consume-before-launch for both requests (tested with a fake host); account-keyed launcher stays stable via `challengeAccount` |
| T-07-47 | Tampering | Dismissal authorizing the preselected card | mitigate | `shouldConfirmSelection(didCancel, hasOption)` (D-18) gates `confirm()`; a dismissal reports Canceled |
| T-07-48 | Elevation of privilege | 3DS on the platform account | mitigate | Launch only when `challengeAccount == request.stripeAccount`; ViewModel never publishes a challenge without an account (07-03, 07-11) |
| T-07-49 | Tampering | Client-side confirmation of the booking PI | mitigate | No `confirmPayment` / `presentWithPaymentIntent` in the host (grep gate); only `handleNextActionForPaymentIntent` after a 402 |
| T-07-50 | Spoofing | Fake payment UI | mitigate | Only Stripe's FlowController and PaymentLauncher collect card data or authenticate |
| T-07-51 | Information disclosure | Payment reference shown on screen | accept | The pi_ id is a support reference shown to its owner (D-16); secrets are never displayed or logged |
</threat_model>
