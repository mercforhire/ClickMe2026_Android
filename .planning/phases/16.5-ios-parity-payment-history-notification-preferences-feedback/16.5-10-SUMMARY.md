# Phase 16.5 Plan 10: Send Feedback screen Summary

Send Feedback's Compose screen: server-driven type picker, uncapped Details field with the D-05 inline error, optional email, and the D-06 Material thanks dialog that returns to the hub.

## What was built

- **Task 1 (tracer):** `FeedbackKey`, the 15 strings, `FeedbackDetailsField` (180 dp minimum, no line or character cap, no counter, content description "Details", error message sliding in over `Motion.FIELD_ERROR_DURATION_MS`), and `FeedbackScreen`/`FeedbackContent` with `Scaffold` + `AuthTopAppBar`, an `imePadding` + `verticalScroll` + `contentMaxWidth` column, labels `sm` above `PickerField`, Details, `ValidatedField` (email) and `AsyncSaveButton`. `FeedbackThanksDialog` copies the `AuthErrorDialog` styling; OK, scrim and system back all call `onBack`.
- **Task 2:** a 150 ms `Crossfade` on the load state: a form-shaped `SkeletonGroup` (three label blocks, two pills, a 180 dp Details block) while loading; `ErrorState` ("Couldn't load categories", the message, Retry) on failure with no form. The `PickerSheet` lists one `PickerRow` per server type (label only, keyed by id); its open flag is `rememberSaveable` and survives recreation. No type id is hard-coded.
- **Task 3:** `AuthErrorDialog` titled "Couldn't send feedback" for `state.dialog` (null for a suspended account). Fields are never disabled while saving. Tests cover the Details error showing and clearing, placeholder, a 2,000-character value, the field name, email error on its own field, the failure dialog keeping the form, both fixed-copy dialog messages, the busy state, and label-before-control order.
