# Phase 16.5 Plan 09: Notification preferences screen Summary

Notification Settings UI: four sectioned cards of 13 whole-row switches, a skeleton and a retryable load failure, and an app-bar Saving/Saved/Error-with-Retry status that leaves the bar steady, flushing a pending edit on every way off the screen.

## What was built

- **Task 1 (tracer):** `NotificationSettingsKey`, the Hilt-facing `NotificationSettingsScreen` (leave lambda flushes then pops, `BackHandler`, `DisposableEffect` flush) and stateless `NotificationSettingsContent`. Section cards (heading, `surfaceContainerLow` card with `outlineVariant` border, dividers between rows only), and `NotificationToggleRow` as one `toggleable(role = Role.Switch)` target of at least 56 dp with a decorative `Switch`. Strings `notification_settings_title`, `notification_settings_load_error_title`, `notification_settings_save_error_a11y`.
- **Task 2:** Crossfade over the load state: skeleton shaped like the 7/3/1/2 cards, `ErrorState` ("Couldn't load preferences" with Retry). `NotificationSaveStatusAction` with Idle (empty slot), Saving spinner, Saved check (polite live region) and Error icon plus Retry (one polite live region described "Couldn't save preferences. Retry"). Toggles are never disabled by a status.

The 200% font backstop (device row FS.NS1, plan 16.5-12) stays open; the unit test only checks wrap, switch containment and the 56 dp row minimum at font scale 2 on 360 dp.

## Deviations from Plan

- **Slot sizing:** The plan says "48 dp slot never shifts the bar". A fixed 48 dp box would clip the Error look (icon plus Retry label) and block hit-testing outside its bounds, so the slot is `defaultMinSize(48, 48)`. Idle, Saving and Saved are exactly 48 dp; Error grows toward the title. The back arrow and the title's x position are asserted identical across all four states in `theBarDoesNotShiftBetweenStates`. Rule 1 (would not work as specified).
- The plan-commit ledger file under the git dir could not be created (the worktree guard blocks writes outside the worktree), so `plan_head_before` is the dispatch base commit, equal to HEAD at the first commit.
- Tests that click a row use `performScrollTo()` first, because rows below the first screenful are outside the Robolectric window.
