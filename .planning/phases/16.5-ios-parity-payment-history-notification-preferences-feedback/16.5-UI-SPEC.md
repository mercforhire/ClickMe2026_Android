# Phase 16.5 — UI Design Contract

> Visual and interaction contract for Phase 16.5: client Payment History, Notification preferences, Send Feedback, the animated splash, the two new hub sections and the "View Past History" confirmation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Designs live in Google Stitch and are not accessible, so the iOS views under `ios-reference/ClickMe2026/Views/Screens/{Client Mode/Payments, Settings/Notifications, Settings/Feedback, Splash}` are the stand-in source of truth. Where iOS and the Android design system disagree on a value, the Android token wins (see "Deliberate visual deviations from iOS"). **No new colors, font sizes, weights or spacing tokens are introduced.**
>
> Decisions D-01 to D-10 in `16.5-CONTEXT.md` are locked and are not re-argued here. In particular: **no quiet-hours card (D-01)** and **no Delete Account "Before you go" card (D-10)** exist in this contract, although the roadmap title names the card. Items this spec had to decide that CONTEXT left open are tagged **Assumption** and collected in "Open assumptions".

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Jetpack Compose + Material 3; shadcn does not apply to Android) |
| Preset | not applicable |
| Component library | Material 3 (`androidx.compose.material3`) plus the in-house `components/` set |
| Theme | Dark only. `ClickMeTheme` in `ui/theme/` (`Color.kt` `ClickMePalette`, `Type.kt`, `Spacing.kt`, `Shape.kt`, `Extras.kt`, `Motion.kt`, `ContentWidth.kt`) |
| Icon library | Material Icons Extended (`androidx.compose.material:material-icons-extended`, `Icons.Outlined.*` / `Icons.Filled.*` / `Icons.AutoMirrored.*`) |
| Font | Nunito variable font (`NunitoFamily`), weights 400 and 600 only |

Hard rules inherited from the project and enforced by `scripts/check-design-rules.sh` (read before writing this contract; nothing below asks for something it rejects): no `Color(0x…)` / `Color(red=…)` literals outside `ui/theme/Color.kt` (so the splash gradient and glow use theme slots, never hex); no `*Brand` types (iOS `NotificationSettingsBrand`, `FeedbackBrand` are not ported); a `Scaffold` content lambda must name its padding parameter and apply it (rule a); a `*Screen.kt` / `*Sheet.kt` file containing `TextField(` or `ValidatedField(` must also contain `imePadding`, `verticalScroll` or `LazyColumn` (rule c), which `FeedbackScreen.kt` does; an `AlertDialog(...)` argument span never contains `TextField(` / `ValidatedField(` (R7), so both Feedback dialogs are text-only. Never set `fontSize` outside `Type.kt`; read colors from `MaterialTheme.colorScheme` or `MaterialTheme.extras`; read spacing from `Spacing`; do not pass `FontWeight.Bold` (use the 600 styles). The splash is a full-bleed screen with no `Scaffold`, so rule (a) and (b) do not apply to it; if the splash composable does use a `Scaffold`, apply its padding or add `// insets-ok: full-bleed splash`.

## Spacing Scale

Declared values (multiples of 4), from `Spacing`:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4dp | Row title-to-line gap, row line-to-pill gap, notification subtitle gap, refund subtitle gap |
| sm | 8dp | Gap between Payment History rows, label-to-control gap on Feedback, pill horizontal padding, heading-to-card gap on Notifications, "Loading more" icon-to-text gap, splash wordmark-to-tagline gap |
| md | 16dp | Screen horizontal and top padding on Payment History, Notifications and Feedback; row inner padding (Payment History and notification rows); row column gap; hub section caption-to-rows (existing) |
| lg | 24dp | Gap between Feedback fields (iOS 24); gap between notification sections |
| xl | 32dp | Bottom padding of all three scrolling screens (plus the navigation-bar inset); splash logo-to-wordmark gap (iOS 30 mapped to 32); hub section gap (existing) |
| xxl | 48dp | Not used by a new screen (hub spacing unchanged) |
| xxxl | 64dp | Not used |

Layout values:
- **Payment History** list: `LazyColumn`, `contentMaxWidth()`, `contentPadding` start/end `md`, top `md`, bottom `xl` + `WindowInsets.navigationBars` bottom, rows `sm` apart (identical to `TransactionsContent`). Row card: `shapes.medium` (16dp), padding `md`, 1dp `outlineVariant` border, fill `surfaceContainerLow`.
- **Notifications** column: `verticalScroll`, `contentMaxWidth()`, horizontal `md`, top `md`, bottom `xl`; sections `lg` apart; heading `sm` above its card; card `shapes.medium`, fill `surfaceContainerLow`, 1dp `outlineVariant`; rows separated by a 1dp `HorizontalDivider` in `outlineVariant`, full card width.
- **Feedback** column: `imePadding()`, `verticalScroll`, `contentMaxWidth()`, horizontal `md`, top `md`, bottom `xl`; fields `lg` apart; label `sm` above its control. There is no outer form card (iOS draws a 20dp iridescent card; dropped, see deviations).
- **Splash**: one centered column offset up by 20dp (iOS `offset(y: -20)`), logo-to-wordmark `xl`, wordmark-to-tagline `sm`.

Exceptions (fixed sizes, not spacing):
- Row minimum heights: Payment History row 72dp (matches the Earnings row), notification row 56dp, hub rows 56dp (existing).
- Touch targets: every row, switch row (whole row is the target), app-bar status action, "Retry" footer button, picker field and Submit button are at least 48dp; Submit uses `AsyncSaveButton`'s 56dp.
- Pill minimum height 24dp (decorative, not interactive).
- Details field minimum height 180dp (iOS 180), growing with content inside the scroll column.
- Splash mark 148dp (iOS 148); splash glow circle 190dp with a 160dp drawn gradient radius; background gradient radius 520dp (iOS 520). Component dimensions, intentionally outside the scale.
- Skeletons: Payment History row blocks 72dp tall `shapes.medium`; Notifications heading block 24dp x 120dp and row blocks 56dp; Feedback label blocks 16dp x 96dp, pill blocks 56dp, Details block 180dp.
- Switch: Material 3 default size (52 x 32dp) inside the 56dp row, so the row, not the switch, is the 48dp target.

## Screen And Component Contracts

### 1. Payment History (`ClientTransactionsScreen`)

Chrome: `Scaffold(containerColor = surface)` + `AuthTopAppBar(title = "Payment History", onBack)` + `SnackbarHost`. Body is a `PullToRefreshBox` (pull works from every state), exactly the `TransactionsContent` structure. State changes cross-fade over 150ms (`Motion.CONTROL_STATE_DURATION_MS`).

| State | Contract |
|-------|----------|
| Loading (first) | `SkeletonGroup`: six `shapes.medium` blocks 72dp tall, `sm` apart, inside the list padding. No spinner |
| Loaded | `LazyColumn` of rows (below), keyed by booking id, newest first as the server returns them |
| Empty | `EmptyState` centered in a scrollable column (so pull works), no action |
| Failed (page 1) | `ErrorState`-style `EmptyState(Icons.Outlined.ErrorOutline, "Couldn't load payments", message, Retry)` centered in a scrollable column. A 500 on page 1 is this state |
| Refreshing | Rows stay visible; M3 pull indicator; the list is never cleared (deviation from iOS) |
| Refresh failed over loaded | Rows stay; `RefreshFailedSnackbarEffect` shows "Couldn't refresh" with Retry |
| Next page loading | Footer item: 24dp `CircularProgressIndicator` (`onSurfaceVariant`, 2dp stroke) plus "Loading more…" `labelSmall` `onSurfaceMuted`, centered, `md` vertical padding |
| Next page failed | Footer item: message (`bodySmall`, `onSurfaceMuted`, centered, wraps) over `TextButton("Retry")` (`labelLarge`, `primary`, 48dp minimum); rows stay. A 500 on page 2 or later shows nothing (end of list) |

Row (`ClientTransactionRow`): `Surface` with `shapes.medium`, `surfaceContainerLow`, 1dp `outlineVariant` border, clickable with `Role.Button` and `onClickLabel = "Open booking"`, one merged TalkBack node. Same anatomy as `EarningsTransactionRow`: a `Row` with `spacedBy(md)`, top-aligned, min height 72dp, padding `md`.
- Left column (weight 1, `spacedBy(xs)`): topic (`titleMedium`, `onSurface`, wraps, no line limit), the line `{expert} · {date}` (`bodySmall`, `onSurfaceMuted`, wraps), then, only when a partial refund exists, `Refunded {amount}` (`bodySmall`, `onSurfaceMuted`), then the status pill.
- Right: amount (`titleMedium`; `onSurface`, or `onSurfaceMuted` when `payment_status` is `refunded`). It never shrinks or truncates; the left column wraps instead.
- Partial refund means `0 < refunded_amount < amount` with a positive amount. `refunded_at` is never read.
- Pill (`ClientPaymentStatusPill`): the `EarningsStatusPill` look: `labelMedium` `onSurface` text, minimum 24dp tall, `CircleShape`, horizontal padding `sm`, 12% fill. The label wraps inside the left column, so "Authorized (not yet charged)" never clips at 200% font. Not interactive. Tint by status, and the text always names the status, so color is never the only signal:

| Payment status | Tint (fill) |
|----------------|-------------|
| `captured` | `primary` at 12% |
| `requires_capture`, `scheduled`, `processing`, `requires_payment_method` | `tertiary` at 12% |
| `failed`, `canceled`, `auth_expired` | `error` at 12% |
| `refunded`, `partially_refunded`, `none`, any unknown value | `surfaceContainerHigh` (neutral) |

Row tap: pushes `UpcomingBookingKey(bookingId)` on the opener's stack for every row, including past, cancelled and failed bookings (D-03). Back returns to the list with scroll position and loaded pages intact. Those bookings show no live Join or Reschedule action on the destination (A8, a requirement).

### 2. Notification preferences (`NotificationSettingsScreen`)

Chrome: `Scaffold(containerColor = surface)` + `AuthTopAppBar(title = "Notifications", onBack, actions = save status)`. No pull-to-refresh (Assumption A5). Body cross-fades over 150ms.

| State | Contract |
|-------|----------|
| Loading | `SkeletonGroup`: four sections, each a 24dp x 120dp heading block, `sm` below, then a `shapes.medium` card of 56dp row blocks (7, 3, 1, 2 rows, matching the real sections). Save status shows nothing |
| Loaded | `verticalScroll` column of four `NotificationSectionCard`s |
| Failed | `ErrorState("Couldn't load preferences", message, "Retry")` centered; no toggles, no save status |

Section: heading (`titleLarge`, `onSurface`, heading semantics), `sm` below, then the card. Order: Bookings (7 rows), Sessions (3), Messages (1), Reviews (2). The `payout`, `account` and `promotions` categories are never shown.

Row (`NotificationToggleRow`): whole row is one `toggleable(role = Role.Switch)` target, min height 56dp, padding `md`, merged semantics reading "{title}, {subtitle}, on/off". Layout: weighted column (title `bodyLarge` `onSurface`, wraps; `xs` below it the subtitle `bodySmall` `extras.onSurfaceMuted`, wraps) and a trailing Material 3 `Switch` (`onCheckedChange = null`, because the row owns the toggle). Switch colors: checked track `primary`, checked thumb `onPrimary`; unchecked track `surfaceContainerHigh`, unchecked thumb `outline`, unchecked border `outline`. Rows are separated by a 1dp `outlineVariant` `HorizontalDivider`. Toggling gives M3's built-in thumb motion; no extra animation.

Save status action (`NotificationSaveStatusAction`, in the app-bar `actions` slot; 48dp box so the bar never shifts; 150ms cross-fade between looks), driven by `AutoSaver.status`:
- Idle: nothing (an empty 48dp slot).
- Saving: 24dp `CircularProgressIndicator` (`primary`, 2dp stroke), description "Saving".
- Saved: `Icons.Filled.CheckCircle` 24dp `primary`, description "Saved", polite live region, held `SAVED_HOLD_MS` (2s) then Idle.
- Error: `Icons.Outlined.ErrorOutline` 24dp `error` followed by `TextButton("Retry")` (`labelLarge`, `primary`, 48dp minimum height); the group is one polite live region described "Couldn't save preferences. Retry". Retry calls `AutoSaver.retry`. Toggles stay exactly as the user set them. The error clears when a retry or a later edit saves successfully.

Behavior the layout depends on: 800ms debounce coalescing rapid flips into one trailing PATCH; leaving the screen calls `AutoSaver.flush` so a last-moment flip is not lost; a toggle stays interactive while a save is in flight (a later flip is saved after it). No dialog is ever shown for a save failure.

### 4. Splash (`SplashScreen`, Compose stage after the system splash)

A full-bleed screen shown by the root route switch for the `AppRoute.Splash` route, replacing the current `EmptySurface()`. Edge-to-edge: the background draws under both system bars, which stay transparent as elsewhere.

Layers, back to front:

Decorative.
3. **Mark**: `painterResource(R.drawable.clickme_mark)` at 148dp, decorative. With the glow it forms the "logo" group: opacity 0 to 1 and scale 0.82 to 1 over 700ms ease-out (`FastOutSlowInEasing` is acceptable; iOS `easeOut`), starting on first frame.
4. **Text group**, `xl` below the logo group: wordmark "ClickMe" (`displaySmall`, `onSurface`, centered), `sm` below it the tagline (`bodyLarge`, `extras.onSurfaceMuted`, centered, wraps). Opacity 0 to 1 over 600ms ease-out after a 350ms delay.

Timing and handoff:
- The screen stays up for at least 3000ms on every launch path (D-08, D-09). It never replays on rotation or other configuration change; it shows once per cold process start (state in `AppViewModel`, which survives configuration change).
- System splash to Compose splash: keep the system splash on screen until the Compose splash's first frame is drawn, then release it with no exit animation (`setOnExitAnimationListener` removing the view immediately, including on API 31+ where the default icon fade would otherwise stack a second fade). Replace the current `setKeepOnScreenCondition { !destinationResolved }` with a "first Compose frame drawn" condition. The 3s clock starts at the Compose splash's first frame, not at process start.
- Splash to destination: the existing root-route transition in `ClickMeApp` (unchanged). The destination is only revealed after both 3000ms have elapsed and `destinationResolved` is true (Claude's discretion; auth resolution runs alongside the 3s, not after it). If auth is still unresolved after 3s the splash simply stays, with no spinner and no extra copy.
- System back during the splash is not intercepted (the app closes as usual). No taps do anything.
- Reduced motion: when the system animator scale is 0 (`Settings.Global.ANIMATOR_DURATION_SCALE == 0f`), skip the logo and text entrance (show them at full opacity and scale 1) and hold the glow at its midpoint (alpha 0.365, scale 1.0, no pulse). The 3s hold is unchanged. There is no existing reduced-motion helper to reuse; add one small shared helper rather than inlining it.
- Accessibility: the screen is one merged node "ClickMe. Book time with the best minds."; mark and glow are decorative. The text is announced once and is not a live region.

## Accessibility Contract

- Touch targets are at least 48dp: back arrow, each Payment History row, each notification row (whole row), the Notifications Retry action, the page-error Retry, the picker field, the Submit button, dialog buttons, the hub rows.
- Headings: TopAppBar titles, notification section headings, dialog titles, `EmptyState` headings. Failure states and the save-error group are polite live regions; the saved check is a polite live region.
- Skeleton groups announce one "Loading" (`SkeletonGroup`).
- Merged nodes: each Payment History row (`{topic}, {expert}, {date}, {status}, {amount}` plus the refund line), exposed as a Button with the click label "Open booking"; each notification row as a Switch with its title, subtitle and state; the splash as one node.
- Color is never the only status signal: every pill carries its status text.
- Decorative: row and hub icons, status-pill fills, the splash mark and glow, empty-state icons.
- Switch rows use `Role.Switch` with the row as the toggleable, so TalkBack announces "switch, on/off" once and the Switch itself has no separate focus.
- The Details field has the content description "Details"; field labels precede their controls in reading order (Assumption A3).
- Contrast: all text uses `onSurface`, `onSurfaceVariant`, `extras.onSurfaceMuted`, `extras.destructive` or `primary` on `surface`, `surfaceContainer`, `surfaceContainerLow` or `surfaceContainerHigh`, the same pairs already used app-wide. Pills put `onSurface` text on a 12% tint, as the Earnings pill does.
- Dialogs and snackbars follow the Material 3 defaults (focus trap, back dismisses; here back on the thanks dialog also leaves the screen).
- Font scale: nothing in this phase uses a fixed text height; rows and cards use minimums so 200% font grows them.
- Motion: see the splash reduced-motion rule; no other new continuous motion exists.
