# Phase 16.5 Plan 07: Send Feedback state and rules Summary

Send Feedback's repository, 10-trimmed-character details gate, email prefill, error mapping and sent state, all unit tested with no UI.

## What was built

- **Task 1 (tracer):** `FeedbackRepository` (`types()`, `submit()`), `FeedbackValidation` (`FEEDBACK_DETAILS_MIN = 10`, `feedbackDetailsTooShort`), and `FeedbackViewModel` with `FeedbackLoad` and a `FeedbackUiState` whose `toString` prints only `load` and `saveState`. Types load once with the first preselected; an empty list or a failure is `Failed` with Retry. A valid form sends the trimmed details and a trimmed-or-null email, goes `Saving` then `Saved`, and sets `showThanks`.
- **Task 2:** `showDetailsError` set when details are under 10 trimmed characters (no request), cleared by `onDetailsChange` as soon as the trimmed length reaches 10. Email prefilled from `userManager.me` then the cached profile only when empty, never overwriting typed text; blank is omitted. `saveState != Idle` ignores repeated taps while sending and after success. No selected type shows the `feedback_no_category` dialog. `strings_feedback.xml` added.
- **Task 3:** Failure mapping in `applySendFailure`: 422 on details sets the inline error, 422 on email sets `emailError`, 422 on type or an unnamed field shows the dialog preferring the field message; 429 shows the fixed copy; other Http shows the server message else `feedback_send_failed`; Network shows `login_error_network`; Decoding shows `feedback_send_failed`; `ACCOUNT_SUSPENDED` shows nothing here. The form is kept on every failure. `dismissDialog()`.
