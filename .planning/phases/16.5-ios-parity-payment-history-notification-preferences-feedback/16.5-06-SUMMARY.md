# Phase 16.5 Plan 06: Notification preferences state and rules Summary

Notification preferences' ViewModel, 13-row grid and repository, built on `AutoSaver` with a new 800 ms debounce parameter, hydrating without sending a PATCH and saving without losing an edit.

## What was built

- **Task 1 (tracer):** `AutoSaver` gains `debounceMs` (default `AUTO_SAVE_DEBOUNCE_MS`, so profile settings callers stay at 1,200 ms). New grid, repository, ViewModel and strings. A real load through `NotificationSettingsRepository` and `FakeClickMeApi` hydrates the grid, and one flip sends one 13-row PATCH at exactly 800 ms (not at 799).
- **Task 2:** Hydration rules pinned by tests: any channel on means on, a missing row is on, rows outside the grid (promotions, payout, account, payment actions) and plural category keys never enter the state or a PATCH; rapid flips coalesce to one PATCH with the final values; a flip back to the saved value sends nothing. `ProfileAutoSaveTest` gains `customDebounceIsHonoured` and `defaultDebounceIsUnchanged`.
- **Task 3:** `retrySave`, `flushPendingSave` and an `onCleared` flush on the application scope. Tests cover a failed save (Error, toggles kept), Retry (Saved then Idle after `SAVED_HOLD_MS`), a later edit recovering, an edit during a save landing after it with no overlap, flush on leave, `onCleared` through a `ViewModelStore`, and a load failure followed by Retry.
