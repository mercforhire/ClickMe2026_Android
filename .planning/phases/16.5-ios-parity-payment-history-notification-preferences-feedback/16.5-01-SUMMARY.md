# Phase 16.5 Plan 01: Wire contract for payment history, notification preferences and feedback Summary

Five Retrofit calls, their Moshi DTOs, the FakeClickMeApi overrides and MockWebServer tests pinning the exact method, path, body and null handling, with all four new paths authed and `publicPaths` untouched at 5.

## What was built

- **Task 1 (tracer):** `GET client/transactions` with `page` and `limit`. `ClientTransactionItem` keeps a null `amount` distinct from 0, holds `paymentStatus` as a raw string so an unknown value decodes, does not declare `refunded_at`, and has a `toString` that prints the booking id and status only. `ClientTransactionsData.hasMore` derives from the pagination block. Added `phaseSixteenFiveConstants_areAuthed`.
- **Task 2:** `GET` and `PATCH notifications/preferences`. The PATCH test pins the body to exactly `{"preferences":[{"category","sub_category","push_enabled","email_enabled","in_app_enabled"}]}`. Unknown categories and extra server fields still decode.
- **Task 3:** `GET feedback/types` and `POST feedback/submit`. The body is exactly `{type_id, details}` plus `email` only when present; a 422 maps to `fieldMessage("details")`; `toString` prints lengths and flags, never the text or email.
