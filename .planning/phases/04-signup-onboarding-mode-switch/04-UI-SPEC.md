# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Twelve surfaces: Signup Initial; the setup Overview hub; the five hub steps (Personal Details, Timezone, Profile Photo with its full-screen crop, Verify Email, Expertise Tags); Review and Publish; the Mode Switch page; and the Onboarding carousel. Requirements: SIGN-01..05, ONB-01, ONB-02.
>
> **Baseline.** `01-UI-SPEC.md` and `03-UI-SPEC.md` are locked and are not restated here. Dark only, Material 3, Nunito 400/600, four type sizes (12 / 16 / 20 / 28 sp), the Phase 1 spacing, color, shape and motion tokens, and the shared components `ValidatedField` (with `trailingBadge`, `contentType`), `PasswordStrengthMeter`, `AsyncSaveButton`, `PressScaleButton`, `GreenGlowBlobLayer`, `EmptyState`, `Avatar`, `TopBarAvatarButton`, `AuthTopAppBar`, `AuthErrorDialog`. Every value below is a Phase 1 or Phase 3 token unless it is marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/ClickMe2026/Views/Screens/Signup Flow/**`, `Onboarding/**` and `Settings/Mode Switching/**`. Copy is taken from iOS verbatim except where marked "(Android)". Layout is ported, not pixel-matched. Per-screen iOS palettes (`SignupBrand`, `BasicInfoBrand`, `OnboardingBrand`, `ModeSwitchBrand`, and the others) all collapse to the Phase 1 tokens.
>
> **Locked upstream decisions used here.** CONTEXT D-01..D-22 (field and error rules from Phase 3 D-01..D-04: silent until the first submit then live, submit never disabled for an invalid form, server errors inline or in a dialog). Hub "Next" is always enabled; only Publish is gated (D-05).

## Spacing Scale

Phase 1 tokens, all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

| Token | Used for in this phase |
|-------|------------------------|
| xs (4dp) | Gap between chips (both axes use `sm` for the chip flow, `xs` inside a chip between label and close icon), icon-to-text inside links, gap between progress label and value |
| sm (8dp) | Label-to-field gap, gap between chips, gap between hub rows' title and status text, gap between "Tips" rows' title and detail, gap between the two Mode Switch card texts |
| md (16dp) | Inner padding of hub rows, review cards, tips card and mode cards; vertical gap between hub rows; field bottom margin (built into `ValidatedField`); gap between page dots and the carousel button |
| lg (24dp) | Horizontal screen padding on all form screens (same as Phase 3), gap between field groups, gap between header and form, pinned-button bottom padding, gap between review cards |
| xl (32dp) | Gap between header block and first field on Initial, gap above the crop hint, bottom scroll padding (so content clears the pinned button), carousel gap between illustration and title |
| xxl (48dp) | Initial header top padding, carousel top padding below the status bar |
| xxxl (64dp) | not used |

Exceptions (component dimensions and platform minimums, not layout spacing):
- Touch targets stay at least 48dp. Hub rows, picker rows, chips, links and overflow menu items use `heightIn(min = 48.dp)` or larger.
- Controls (`ValidatedField`, `PickerField`, `AsyncSaveButton`, `PressScaleButton` CTAs) stay `heightIn(min = 56.dp)`.
- Hub step status circle 40dp (iOS 44, snapped to the grid); progress bar height 8dp.
- Profile Photo preview `Avatar` 160dp; crop guide circle diameter = the smaller of (screen width - 2 x 24dp) and (available height - 224dp) and never below 240dp (it scrolls vertically at 200% font scale rather than shrinking); guide ring stroke 2dp.
- Mode Switch card illustration 88dp x 88dp (iOS 88), card min height 120dp.
- Carousel illustration card height 260dp (iOS 260); page dot 8dp, active dot 24dp x 8dp.
- Review avatar 96dp (existing `Avatar` size).
- Stroke widths 1dp resting, 2dp focused / error / active-card (hairlines).

## Color

Dark only. All colors come from the Phase 1 ColorScheme and `MaterialTheme.extras`. No hex literal appears in this phase's code (Phase 1 CI grep applies). The crop overlay uses `colorScheme.scrim` at 60% alpha, not a literal.

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `#131313` `surface` | Every screen background, TopAppBar container. Crop screen background `surfaceContainerLowest` (`#0E0E0E`) |
| Secondary (30%) | `#201F1F` `surfaceContainer` and the tier below | Field fill (via `ValidatedField` / `PickerField`); hub rows, review cards, tips card and inactive mode cards on `surfaceContainerLow` (`#1C1B1B`); `PickerSheet` and `AlertDialog` on `surfaceContainerHigh`; unselected chips on `surfaceContainerHighest` |
| Accent (10%) | `#44F697` `primary` | See reserved list |
| Destructive | `#FF4D4D` `destructive` | Field error border, icon and message; "Required" markers in Review; Remove Photo and Log out confirm buttons. Never on a navigation or save button |
| Warning | `#FFB833` `tertiary` | Password strength "Fair" on the Initial screen only (via `PasswordStrengthMeter`); no other use this phase |

Accent reserved for (and nothing else on these screens):
1. Fill of the single primary CTA on each screen: "Continue" (Initial), "Next" (hub), "Save" (steps), "Verify" or "Send Verification Email" (Verify Email), "Publish Profile" (Review), "Use Photo" (crop), "Next" / "Get Started" (carousel). The Mode Switch page has no CTA.
2. Focused border, cursor and selection handle of `ValidatedField` and `PickerField` (inherited).
3. The glow in `GreenGlowBlobLayer` (Initial, Verify Email, Onboarding).
4. Completed hub step circle (filled `primary` with `onPrimary` check) and the hub progress bar fill.
5. The selection check mark (`Icons.Outlined.Check`, 24dp) on selected rows in Country, Timezone, Language and Tag lists and the selected radio mark on the timezone sheet.
6. The Active mode card's 2dp border and "Active" badge dot and check.
7. The active page dot in the carousel.
8. Password-strength Strong segments and the "passwords match" mark (inherited from `PasswordStrengthMeter`).

Text links ("Resend code", "Skip", "Edit") use `onSurface`, semibold, underlined where they are inline links; they are not accent (Phase 1 rule). Body copy `onSurfaceMuted` (`#999999`); "Skip" uses `onSurfaceVariant`. `onSurfaceFaint` is never used for required text; it is not used in this phase.

Surface tier rules follow Phase 1 exactly: Screen `surface`; Card (list) `surfaceContainerLow`; Resting container `surfaceContainer`; Raised `surfaceContainerHigh`; Highest `surfaceContainerHighest`.

## Motion

Phase 1 durations plus the following (new). All of it follows the system animator duration scale.

| Interaction | Duration / easing |
|---|---|
| Push / pop between signup screens | Phase 1: horizontal slide + fade, 300ms, `FastOutSlowIn`; predictive back drives pops |
| Initial → hub (replace) | Same slide; the Initial entry is removed from the back stack |
| Field error, button states, press scale | Phase 1 values (200ms / 150ms / 120ms) |
| Hub progress bar fill, step circle fill | 300ms `animateFloatAsState` / `animateColorAsState`, `FastOutSlowIn`, runs when returning to the hub from a step |
| Verify Email code field appearing | 200ms fade + vertical expand (`AnimatedVisibility`) |
| Resend countdown | Text updates once per second with no animation |
| Saved confirmation hold | After a step Save succeeds the button shows Saved for 600ms, then the screen pops. Publish: 600ms, then navigate. (Same hold as Phase 3) |
| Crop gestures | No animation while dragging. On release, if the image no longer covers the guide, it springs back to the nearest valid position: 200ms `FastOutSlowIn` |
| `PickerSheet` open / close | M3 `ModalBottomSheet` defaults |
| Mode Switch card press | Phase 1 press scale 0.96, 120ms. Active-card border and fill change: 200ms `animateColorAsState` |
| Mode swap (shell replaced after a switch) | Fade-through: 90ms out, 150ms in (Phase 1 tab-switch value) |
| Carousel page change | `HorizontalPager` default snap animation; the Next button advances with `animateScrollToPage` (300ms). Dot width and color: 200ms `animateDpAsState` / `animateColorAsState`. Carousel exit (Skip / Get Started): 200ms fade out |

No Compose `blur`.

## Navigation and Structure

```
Auth back stack (AppRoute.Login):
Login (root)
 ├─ Forgot Password ... (Phase 3, unchanged)
 └─ Sign Up Initial  "Create Account"   (TopAppBar, back arrow)
       └─ on success: whole stack REPLACED by AppRoute.SignupSetup

SignupSetup back stack (AppRoute.SignupSetup):
Overview hub  "Profile Setup"   (TopAppBar, no back arrow, overflow menu)
 ├─ Personal Details
 ├─ Timezone
 ├─ Profile Photo ── Crop (full screen)
 ├─ Verify Email
 ├─ Expertise Tags
 └─ Review "Profile Review"
      ├─ (Edit buttons push the same step screens; Save pops back to Review)
      └─ Publish success: root becomes clientHome, mode = client, carousel shows

Mode Switch  "Mode Switcher"   (pushed from the avatar on Explore / Dashboard; hides the bottom bar)
Onboarding carousel            (full-screen overlay on client home while hasSeenOnboarding is false)
```

| Screen | App bar | Back behavior |
|---|---|---|
| Sign Up Initial | `AuthTopAppBar`, title "Create Account" is NOT in the bar (the page headline carries it); bar title empty, back arrow (contentDescription "Back"), transparent container so the glow shows | Pops to Login. Back is disabled (`backEnabled = false`) while the request is in flight |
| Hub | `TopAppBar` title "Profile Setup" (`titleLarge`), no navigation icon, trailing `MoreVert` overflow (contentDescription "More options") with one item "Log out" (Android, see Open Items) | System Back exits the app (it is the stack root; resume always opens here, D-10) |
| Step screens | `AuthTopAppBar`, titles "Personal Details", "Timezone", "Profile Photo", "Verify Email", "Expertise Tags" | Pops to the previous screen (hub or Review). Unsaved edits are discarded without a prompt (iOS parity, steps save only on Save) |
| Crop | none (immersive; status bar visible); bottom button row | System Back = Cancel |
| Review | `AuthTopAppBar`, title "Profile Review" | Pops to hub |
| Mode Switch | `AuthTopAppBar`, title "Mode Switcher" | Pops (mode unchanged) |
| Onboarding | none | See Onboarding |

Insets: every screen handles `safeDrawing` and `imePadding`. Form content is `verticalScroll`. Horizontal padding `lg`. Pinned buttons sit in a bar with `lg` horizontal and bottom padding and a `surface` background that rides above the keyboard.

### 1. Sign Up Initial (SIGN-01)

Background `surface` with `GreenGlowBlobLayer`. Scrollable column, `lg` horizontal padding, `xxl` top padding, centered header.

| # | Element | Spec |

| 4 | Strength meter | `PasswordStrengthMeter`, shown while the password is non-empty (200ms), `md` gap below (D-02) |
| 5 | Rule hint | Under the meter, always visible: "At least 8 characters, with a letter and a number." `bodySmall` `onSurfaceMuted`. Turns `destructive` only when the validation error for the password is showing |
| 6 | Submit | `AsyncSaveButton(title = "Continue")` full width, always enabled (D-03 of Phase 3). Saving state shows the spinner; fields disabled. `lg` gap above, `xl` bottom padding |

**Focal point and hierarchy.** The "Continue" button is the only filled accent, anchored by the glow. Emphasis: headline (28sp / 600), then the two fields, then the button, then the muted subtitle and hint.

**States.**
- Default: no errors.
- Validation (after the first submit, then live): email empty "Email is required", bad format "Invalid email format" (shared `AuthValidators`); password empty "Password is required", under 8 "Password must be at least 8 characters", no letter "Password must include a letter", no digit "Password must include a number".
- Submitting: spinner, fields and back disabled.
- 409: server message inline under the email field (fallback "An account with this email already exists."), cleared on the next edit of the email.
- 422: each `errors[]` item maps to its field and shows inline.
- Anything else (5xx, network, unknown): `AuthErrorDialog` with title "Couldn't create account" (iOS), body = server message, else "Something went wrong. Try again." or "Check your connection and try again."; button "OK".
- Success: tokens stored, no Saved hold (the stack is replaced immediately, the next screen is the confirmation).

### 5a. Crop screen (D-12)

Full-screen route, background `surfaceContainerLowest`, no app bar, `safeDrawing` insets. Layout, top to bottom:

| Region | Spec |
|---|---|
| Canvas | Fills the space above the button row. The image is drawn with `graphicsLayer` scale and translation under a fixed circular guide centered in the canvas. Outside the guide a `scrim` 60% overlay (drawn with `BlendMode.Clear` cutout); the guide edge is a 2dp ring in `overlayWhite80` |
| Gestures | `detectTransformGestures`: pinch to zoom, drag to pan. Minimum zoom makes the image cover the guide circle fully (no empty area). Maximum zoom = minimum x 5. Panning is clamped so the guide always stays inside the image; on release an out-of-bounds state springs back (200ms). Double-tap toggles between minimum zoom and 2.5x |
| Hint | `xl` below the canvas, centered: "Pinch to zoom and drag to reposition." `bodyLarge` `onSurfaceMuted` |
| Buttons | Bottom row, `lg` horizontal and bottom padding, `md` gap: "Cancel" (tonal `PressScaleButton`, equal width) and "Use Photo" (filled accent, equal width). While the bitmap is being cropped and scaled, "Use Photo" shows the spinner and both buttons are inert |

Output: a square JPEG, about 1024 px, quality 0.85, taken from the region inside the guide (decoded with `inSampleSize` so large camera photos do not OOM).

## Accessibility Contract

- All tap targets at least 48dp (rows, chips, links, picker rows, clear buttons, Edit buttons).
- Field errors are exposed through `ValidatedField` `error()` semantics; on a failed submit, focus moves to the first invalid field.
- Hub rows announce title plus "Completed" or "Not completed" and act as buttons; the progress block is a single merged node.
- Mode cards are a radio group with `selected` state; "Active" is read as part of the label.
- Pickers: the `PickerField` reads placeholder and value; sheet rows expose `selected` for chosen items.
- The crop canvas has custom actions (Zoom, Move) so it is usable without touch gestures; the Use Photo and Cancel buttons are reachable by focus order after the canvas.
- Timer announcements: the resend countdown is not live-announced every second; announce "You can resend the code" once at zero (`liveRegion = Polite`).
- Saved and Published states are announced via `AsyncSaveButton` `liveRegion = Polite` (Phase 1).
- Color is never the only signal: required-missing in Review has an icon and the word "Required"; hub completion has a check icon and a state description; the active mode has the word "Active".
- Carousel: pager pages have "Page n of 4" semantics; the title is a `heading()`; the Skip control is reachable on every page.
- Check every screen at 200% font scale: the hub rows, chips, mode cards and the carousel footer wrap and scroll rather than clip; the crop guide keeps its minimum size and the screen scrolls.
- Full TalkBack pass is still Phase 15 (POL-04).
