## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| System photo picker -> app | An untrusted image file of any size and format arrives through a content URI |
| App -> upload | The processed JPEG leaves the device in plan 04-16 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Denial of service | Oversized or malformed image decode | mitigate | Bounds-only decode first, power-of-two inSampleSize to at most 2048 px, decode failures mapped to PhotoImportException; covered by PhotoProcessorTest |
| T-04-11 | Information disclosure | EXIF/GPS metadata in the user's photo | mitigate | The upload JPEG is re-encoded from pixels, so no source metadata is copied |
| T-04-12 | Elevation of privilege | Picker URI reuse (confused deputy) | mitigate | The URI is opened once during import and never stored in state, keys or saved state; later steps read the app-private working file |
| T-04-13 | Information disclosure | PII image files left on disk | mitigate | Files live only in `cacheDir/signup` (app-private, excluded from backup); `clearWorkingFiles()` is called on save, remove, logout and publish (plans 04-07, 04-16) |
</threat_model>
