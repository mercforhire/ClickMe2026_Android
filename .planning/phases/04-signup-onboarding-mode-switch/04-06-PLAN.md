- `managers.UserManager.signup(email: String, password: String): SignupData` (stores tokens, sets authUser, isLoggedIn true, clears wasSuspended, meStale and setupCheckPending, best-effort background profile refresh).
- `managers.UserManager.requestModeSwitch(target: AppMode): LaunchDestination` (Client: setMode, Home(Client); Expert: SignupSetup without persisting when setup is incomplete, else setMode(Expert) and Home(Expert)).
- `managers.UserManager.recheckSetupIfPending(): LaunchDestination?` (SignupSetup or null; makes no request unless pending, a session exists, the roles are known, and the roles include expert or the current mode is Expert).
- `managers.UserManager.completeSetup()` (D-22: setMode(Client), clear setupCheckPending, best-effort refreshProfile in appScope).
- Private `@Volatile var setupCheckPending: Boolean`. Set to true whenever a home route is chosen without a setup answer: the expert-profile lookup fails (launch, login or switch), `afterMeFailure()` keeps the session, or `offlineDestination()` returns Home (offline launch, unexpected restore failure, roles missing, or the 5 s splash cap). Cleared only by a successful lookup inside `recheckSetupIfPending()`, by the role guard there, and by login, signup, completeSetup and logout. A lookup that succeeds during launch, login or a switch leaves it unchanged, so the late restore on the cap path (whose SignupSetup result AppViewModel discards) cannot clear it.
- Private `fetchSetupCompleted(): Boolean?` (null on ApiException); `isExpertProfileIncomplete()` is built on it and keeps "failed counts as complete".
- Private `persistedStateLoaded` flag used by `offlineDestination()`.
- `UserManager.logout()` reorder: `_isLoggedIn.value = false` now happens before `_currentMode.value = AppMode.Client` and `_hasSeenOnboarding.value = false`.
- `AppViewModel.switchMode(target: AppMode)` (cancels any in-flight switch; applies the result only while the route is ClientHome or ExpertHome).
- `AppViewModel.onSetupPublished()` (calls `userManager.completeSetup()`, then route = ClientHome).
- `AppViewModel` init: a second collector on `userManager.currentMode`; `onAppForegrounded()` now also runs the setup re-check.
- Constructor `AppViewModel(userManager)` and `UserManager(...)` are unchanged (test harnesses construct them positionally).
