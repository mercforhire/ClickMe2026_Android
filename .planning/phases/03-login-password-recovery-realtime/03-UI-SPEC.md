# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Five screens: the real **Login** screen (replaces the temporary `screens/login/LoginScreen.kt`), **Forgot Password** (titled "Reset Password"), **Set New Password**, **Password Changed**, and a **Sign Up "coming soon" placeholder**. Realtime (RT-01..03) has **no UI**; its only visible artifact is a debug-only Logcat collector (CONTEXT D-20), so this spec defines nothing for it.
>
> **Baseline.** `.planning/phases/01-foundation-app-shell-play-account/01-UI-SPEC.md` is locked and is not restated here. Dark only, Material 3, Nunito 400/600, four type sizes (12 / 16 / 20 / 28 sp), the Phase 1 spacing, color, shape and motion tokens, and the shared components `ValidatedField`, `AsyncSaveButton`, `PressScaleButton`, `GreenGlowBlobLayer`, `EmptyState`. Every value below is a Phase 1 token unless it is marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/ClickMe2026/Views/Screens/Login Flow/**`. Copy is taken from iOS verbatim. Layout is ported, not pixel-matched. Where iOS used a per-screen palette (`LoginBrand`, `ForgetPassBrand`, `NewPasswordBrand`, `PasswordUpdatedBrand`, green-tinted `bgTop`/`bgBottom` gradients) everything collapses to the Phase 1 tokens (see Deviations from iOS).

### Shared-component changes this phase needs (the only edits to Phase 1 components)

`ValidatedField` (`components/ValidatedField.kt`) gets two optional, backward-compatible parameters. No existing call site changes.

| New parameter | Default | Purpose |
|---|---|---|
| `trailingBadge: (@Composable () -> Unit)? = null` | `null` | Content drawn in the trailing slot before the eye toggle. Used for the "passwords match" check on Confirm Password. |
| `contentType: ContentType? = null` | `null` | Autofill semantics for non-password fields. The verification-code field passes `ContentType.SmsOtpCode`; the email field passes `ContentType.EmailAddress`. |

A new shared composable `PasswordStrengthMeter(strength: PasswordStrength, modifier)` goes in `components/PasswordStrengthMeter.kt` (iOS `PasswordStrengthMeter.swift`) so Phase 4 signup can reuse it. `PasswordStrength` is an enum `Empty, Weak, Fair, Strong` with the iOS scoring (`evaluate`) ported unchanged.

## Spacing Scale

Phase 1 tokens (`Spacing.kt`), all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

Phase 3 usage:

| Token | Used for in this phase |
|-------|------------------------|
| xs (4dp) | Gap between a password-strength segment and its neighbor, gap between "Strength:" and the value, icon-to-text gap inside a text link |
| sm (8dp) | Label-to-field gap on Forgot / Set New Password, gap between the Forgot link row and the submit button, gap between "Don't have an account?" and "Sign Up" |
| md (16dp) | Field block bottom margin (built into `ValidatedField`), gap between the strength meter and the next field label, vertical gap inside the Password Changed text block |
| lg (24dp) | Horizontal screen padding on every form screen, header-to-form gap on Login, gap between field groups on Set New Password, gap between submit button and footer on Login, bottom padding of the pinned submit button |
| xl (32dp) | Gap between the checkmark glyph and the headline on Password Changed, Forgot Password info-text top gap, bottom scroll padding |
| xxl (48dp) | Login header top padding (iOS 56 rounded down), Password Changed button bottom padding |
| xxxl (64dp) | not used |

Exceptions (component dimensions, not layout spacing):
- Touch targets stay at least 48dp (links and text buttons use `heightIn(min = 48.dp)`).
- Controls (`ValidatedField`, `AsyncSaveButton`) stay `heightIn(min = 56.dp)` (Phase 1).
- Login logo mark 80dp square (decorative asset size; iOS 80pt).
- Password Changed check glyph 72dp; its glow radius 120dp (decorative geometry).
- Strength meter segment height 4dp and corner radius 2dp (iOS 5 / 3, snapped to the 4 grid).

## Typography

Inherited from Phase 1: exactly four sizes (12, 16, 20, 28 sp) and two weights (400, 600). Line heights 1.5 body, 1.2 headings. Nothing in this phase sets `fontSize` directly; every `Text` takes an M3 slot.

| Role | Size | Weight | Line height | Used for here |
|------|------|--------|-------------|---------------|
| Body | 16sp | 400 | 24sp (1.5) | Login tagline, Forgot description, Forgot info text, Password Changed body, field text and placeholders, dialog body, "Don't have an account?" (`bodyLarge`) |
| Label | 12sp | 600 | 16sp (1.33) | Field error text (built into `ValidatedField`), strength value ("Weak" / "Fair" / "Strong") (`labelMedium`). The "Strength:" caption is `bodySmall` (12sp, 400) |
| Heading | 20sp | 600 | 24sp (1.2) | TopAppBar titles "Reset Password" and "Set New Password" (`titleLarge`), Sign Up placeholder heading |
| Display | 28sp | 600 | 34sp (1.2) | "ClickMe" wordmark on Login, "Password Updated!" on Password Changed (`headlineLarge`) |

Buttons and link buttons use `labelLarge` (16sp / 600). Field labels above fields ("Email", "Verification Code", "New Password", "Confirm New Password") use `titleMedium` (16sp / 600, `onSurface`).

The iOS wordmark (38pt bold rounded) and the iOS Password Updated headline (36pt) both fold to 28sp, per the Phase 1 folding rule. The iOS code-field kerning (2) is not ported (letter spacing is 0 everywhere).

## Color

Dark only. All colors come from the Phase 1 ColorScheme and `MaterialTheme.extras`. No hex literal appears in this phase's code (Phase 1 CI grep applies).

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `#131313` `surface` | Every screen background, TopAppBar container on the two pushed form screens. No green-tinted vertical gradient (iOS `bgTop`/`bgBottom`); atmosphere comes from `GreenGlowBlobLayer` on Login and Password Changed only |
| Secondary (30%) | `#201F1F` `surfaceContainer` | Text field fill (via `ValidatedField`). `surfaceContainerHigh` (`#2A2A2A`) for the error `AlertDialog` |
| Accent (10%) | `#44F697` `primary` | See reserved list |
| Destructive | `#FF4D4D` `destructive` | Field error border, icon tint and message (via `ValidatedField`). Weak segment of the strength meter and the word "Weak". Never on buttons in this phase |
| Warning | `#FFB833` `tertiary` | Fair segment of the strength meter and the word "Fair" (iOS amber 0.95, 0.65, 0.10) |

Accent reserved for (and nothing else on these screens):
1. Fill of the single primary CTA on each screen (`AsyncSaveButton`: "Login", "Send Reset Code", "Set New Password", "Go to Login"; the "Back to Login" `EmptyStateAction` on the Sign Up placeholder)
2. Focused border, cursor and selection handle of `ValidatedField` (inherited)
3. The glow in `GreenGlowBlobLayer` (Login, Password Changed)
4. The Strong segments and the word "Strong" in the strength meter
5. The "passwords match" `CheckCircle` in the Confirm Password field
6. The Password Changed check glyph and its glow

Text links ("Forgot Password?", "Sign Up", "Back to Login") use `onSurface` semibold with underline, **not** accent. This follows the Phase 1 rule "Text links use `onSurface` with underline, not accent", and is a deliberate deviation from iOS, which colored them green. Body copy `onSurfaceMuted` (`#999999`); the Password Changed body uses `onSurfaceVariant`. The Forgot info text uses `onSurfaceMuted` (not `onSurfaceFaint`: it is text the user needs to read).

Strength colors (the iOS red, amber and green map to existing tokens): empty track `overlayWhite15`; Weak `destructive`; Fair `tertiary`; Strong `primary`. Contrast of each on `surface` is 3:1 or better, and the meter is never the only signal (the word is always shown next to it).

## Motion

Phase 1 durations, plus the Password Changed entrance sequence (new). All of it follows the system animator duration scale.

| Interaction | Duration / easing |
|---|---|
| Push / pop between Login, Forgot, Set New Password, Password Changed, Sign Up | Phase 1: horizontal slide + fade, 300ms, `FastOutSlowIn`. Predictive back drives pops |
| Field error appear / disappear | Phase 1: 200ms fade + 4dp slide (inside `ValidatedField`) |
| Button idle / saving / saved | Phase 1: 150ms crossfade, width never changes |
| Strength meter appear / disappear (when the new-password field becomes non-empty / empty) | 200ms fade + vertical expand (`AnimatedVisibility`). Segment color changes: 300ms `animateColorAsState` |
| Password Changed entrance (new, all one-shot on first composition) | 1. Check glyph: scale 0.4 to 1.0 and fade in, `spring(dampingRatio = 0.6f, stiffness = StiffnessMediumLow)`, starts at 150ms. 2. Glow: alpha 0 to full, 550ms `EaseOut`, starts at 300ms. 3. Headline + body: fade in with 16dp upward slide, 450ms `EaseOut`, starts at 520ms. 4. Button: fade in with 16dp upward slide, 400ms `EaseOut`, starts at 700ms |
| Login / Forgot / Set New Password content entrance | None. iOS fades the content in (0.45 to 0.55s); on Android the push transition is enough and an extra fade would delay the form |
| "Sent" / "Updated" confirmation hold | After the request succeeds the button shows its Saved state for 600ms, then the screen navigates (see Interaction Contract) |

No Compose `blur`. The check glow is a radial gradient, the same technique as `GreenGlowBlobLayer`.

## Navigation and Structure

The auth back stack lives under `AppRoute.Login` and reuses the `navigation/Navigator` back-stack pattern (CONTEXT Claude's Discretion). Every screen is **pushed** (no `ModalBottomSheet`), matching iOS.

```
Login (root, no app bar)
 ├─ Forgot Password  "Reset Password"   (TopAppBar, back arrow)
 │    └─ Set New Password               (TopAppBar, back arrow)
 │         └─ Password Changed          (no app bar)
 └─ Sign Up placeholder  "Sign Up"      (TopAppBar, back arrow)
```

| Screen | App bar | Back behavior |
|---|---|---|
| Login | none (iOS hides the nav bar). Status-bar inset only | System Back exits the app (it is the auth root) |
| Forgot Password | `TopAppBar`, title "Reset Password" (`titleLarge`, `onSurface`), container `surface`, back arrow (contentDescription "Back") | Pops to Login |
| Set New Password | `TopAppBar`, title "Set New Password", back arrow | Pops to Forgot Password (email preserved) |
| Password Changed | none; no back arrow (the success screen is terminal) | System Back and the button do the same thing: clear the recovery screens and return to Login with the reset email pre-filled and the password empty (CONTEXT D-10, D-11) |
| Sign Up placeholder | `TopAppBar`, title "Sign Up", back arrow | Pops to Login |

Insets: each screen handles `safeDrawing` and `imePadding`. Form content is `verticalScroll`. Horizontal padding is `lg` (24dp) on all form screens.

## Screen Specifications

### 1. Login

Background `surface` with `GreenGlowBlobLayer` behind the content (Phase 1 opt-in for login). Content column, scrollable, `lg` horizontal padding, `xxl` top padding.

Top to bottom:

| # | Element | Spec |
|---|---|---|
| 1 | Header block, centered | `clickme_mark` / `splash_logo` drawable at 80dp (decorative, `contentDescription = null`); `sm` gap; wordmark "ClickMe" `headlineLarge` `onSurface`; `sm` gap; tagline "Welcome back! Please enter your details." `bodyLarge` `onSurfaceMuted`, centered, horizontal padding `xl` |
| 2 | Spacer | `lg` |
| 3 | Email field | `ValidatedField`, placeholder "Email", icon `Outlined.Email`, `KeyboardType.Email`, `ImeAction.Next`, error from the view model |
| 4 | Password field | `ValidatedField`, placeholder "Password", icon `Outlined.Lock`, `isSecure = true`, `ImeAction.Done` (submits), error from the view model. Includes the built-in eye toggle |
| 5 | "Forgot Password?" | Right-aligned `TextButton` row, `labelLarge`, `onSurface`, underlined, min 48dp tall. `sm` gap below to the submit button |
| 6 | Submit | `AsyncSaveButton(title = "Login", state = Idle or Saving)`, full width, always enabled (D-03). While Saving the fields are `enabled = false` |
| 7 | Footer | `lg` gap above. Centered row: "Don't have an account?" (`bodyLarge`, `onSurfaceMuted`) + `xs` gap + "Sign Up" `TextButton` (`labelLarge`, `onSurface`, underlined, min 48dp). `lg` bottom padding |

**Focal point and hierarchy.** The focal point is the filled green "Login" button (the only filled accent element) anchored by the glow behind the header. Order of emphasis: wordmark (28sp / 600), then the email and password fields, then the Login button, then the secondary text links (Forgot Password?, Sign Up), then the muted tagline. The glow and logo set the mood but do not compete with the form.

**States.**
- Default: no errors shown (D-02).
- Validation (after the first submit, then live): inline error under the failing field; border and icon go `destructive`.
- Submitting: button shows the spinner (`Saving`), fields disabled, links disabled.
- 401: the server message ("Invalid email or password" or whatever the server returns) shows inline under the **password field only**, no dialog (D-04). It clears on the next edit of either field.
- 422 with `errors[].field == "email"`: server message inline under the email field, no dialog.
- Anything else (5xx, network, unknown): `AlertDialog` (see Dialog below). Suspension is handled by the existing global `SuspendedAccountDialog` and is not duplicated here.

### 2. Forgot Password ("Reset Password")

Background `surface`, no glow. `TopAppBar` (title "Reset Password"). Scrollable column, `lg` horizontal padding.

| # | Element | Spec |
|---|---|---|
| 1 | Description | "Enter your email to receive a password reset code" `bodyLarge` `onSurfaceMuted`; `lg` top padding |
| 2 | Field label | "Email" `titleMedium` `onSurface`; `xl` gap above, `sm` below. Hidden from TalkBack (the field's accessible name is its placeholder) |
| 3 | Email field | `ValidatedField`, placeholder "Email", icon `Outlined.Email`, `KeyboardType.Email`, `ImeAction.Done` (submits). Pre-filled with the Login email (D-07) |
| 4 | Submit | `AsyncSaveButton(title = "Send Reset Code", savedTitle = "Code Sent!")`, `lg` gap above (the field's `md` margin plus `sm`) |
| 5 | Info text | "The reset code will be sent to the email associated with your account. Check your inbox and enter the code on the next screen to reset your password." `bodyLarge`, `onSurfaceMuted`, centered, line height 24sp, horizontal padding `md`, `lg` top gap |
| 6 | Back to Login | Centered `TextButton`: `ArrowBack` 20dp + `sm` gap + "Back to Login" (`labelLarge`, `onSurface`), min 48dp. `xl` top gap, `xl` bottom padding |

**Focal point and hierarchy.** The email field and the "Send Reset Code" button form the focal cluster; the button is the single filled accent. Emphasis: field label and field first, then the button, then the muted description and info text, then the Back to Login link.

**States.** Default; validation error (empty: "Please enter your email"; bad format: "Invalid email format"); sending (button Saving, field disabled); sent (button shows `CheckCircle` + "Code Sent!" for 600ms, then push to Set New Password with the trimmed email); server error (`AlertDialog`, plus inline under the email field when the 422 error field is `identity` or `email`). When the user returns here with Back, the button is reset to Idle (an improvement over iOS, where it stays disabled).

### 3. Set New Password

Background `surface`. `TopAppBar` (title "Set New Password"). Layout is a `Column` with a scrolling form region (`weight(1f)`) and the submit button pinned below it. The pinned button container has `lg` horizontal and bottom padding and rides above the keyboard (`imePadding`).

Scrolling region, `lg` horizontal padding, `lg` top padding:

| # | Element | Spec |
|---|---|---|
| 1 | Label "Verification Code" | `titleMedium`, `sm` gap below |
| 2 | Code field | `ValidatedField`, placeholder "Enter 6-digit code", icon `Outlined.Pin`, `KeyboardType.NumberPad`, `ImeAction.Next`, `contentType = SmsOtpCode`. Input filtered to digits and clipped to 6 on every change |
| 3 | Label "New Password" | `titleMedium`; `lg` gap above (the field's `md` margin plus `sm`), `sm` below |
| 4 | New password field | `ValidatedField`, placeholder "Enter your new password", icon `Outlined.Lock`, `isSecure`, `ImeAction.Next`. Own eye toggle |
| 5 | Strength meter | Shown only while the new password is non-empty (200ms fade/expand). See below. `md` gap below |
| 6 | Label "Confirm New Password" | `titleMedium`, `sm` gap below |
| 7 | Confirm field | `ValidatedField`, placeholder "Confirm your new password", icon `Outlined.Lock`, `isSecure`, `ImeAction.Done` (submits). Own eye toggle. `trailingBadge` = `Outlined.CheckCircle` 24dp `primary`, shown when `confirm.isNotEmpty() && confirm == new` (contentDescription "Passwords match") |
| 8 | Bottom spacer | `xl` |

Pinned: `AsyncSaveButton(title = "Set New Password", savedTitle = "Password Updated!")`.

**Strength meter** (`PasswordStrengthMeter`): a row of 3 equal-width segments, 4dp high, 2dp radius, `xs` gaps, then `sm` below a row with "Strength:" (`bodySmall`, `onSurfaceMuted`), `xs`, and the value (`labelMedium`, colored). Fill: Weak = 1 segment; Fair = 2; Strong = 3; unfilled segments `overlayWhite15`. Scoring is the iOS `PasswordStrength.evaluate`: +1 each for length >= 8, length >= 12, an uppercase letter, a digit, a non-alphanumeric; score 0-1 Weak, 2-3 Fair, 4-5 Strong. Accessibility: the row carries `contentDescription = "Password strength: {Weak|Fair|Strong}"` and the child texts are merged into it. The meter is informational only; it never blocks submit (the validation rules do).

**Validation copy and rules (iOS verbatim).** Code: empty "Please enter the 6-digit code"; not 6 digits "Code must be 6 digits". New password: empty "Please enter a new password"; under 8 chars "Password must be at least 8 characters"; missing a digit or a non-alphanumeric "Password must include a number and a symbol". Confirm: empty "Please confirm your password"; different "Passwords do not match". Timing as Login (D-02): nothing until the first submit, then live per field.

**Focal point and hierarchy.** The focal point is the verification-code field at the top, because it is the first thing the user must do after leaving for their inbox; the filled "Set New Password" button is the single accent anchor at the bottom. Emphasis order: code field, new password field and its strength meter, confirm field, then the button. Labels are `titleMedium` and secondary to the fields.

**States.**
- Default: empty fields, no meter, button Idle.
- Typing a password: meter appears and updates live.
- Submitting: button Saving, all fields disabled.
- 400: code field error "Invalid or expired code. Please request a new one." The user fixes it by going Back and requesting a new code (no resend button, D-09).
- 422: messages map to the code, new password, confirm, and (for `email`) the `AlertDialog`.
- Missing email (defensive): `AlertDialog` "Missing account email. Please start the reset flow again from the login screen."
- Success: button shows `CheckCircle` + "Password Updated!" for 600ms, then push to Password Changed.
- After a failed submit, focus moves to the first field with an error.

Background `surface` with `GreenGlowBlobLayer`. No app bar. Column filling the screen with `lg` horizontal padding: `weight(1f)` centered block, then the button.

| # | Element | Spec |

**Focal point and hierarchy.** The glowing check glyph is the single focal point (it is the only large accent-colored shape). Emphasis: check glyph, then the "Password Updated!" headline (28sp / 600), then the muted body, then the Go to Login button (the one filled accent control).

### 5. Sign Up placeholder ("coming soon")

Replaced by `SignupInitialScreen` in Phase 4, so it stays small and uses only shared components. `TopAppBar` titled "Sign Up", then an `EmptyState` centered in the remaining space:

### Dialog (Login, Forgot Password, Set New Password)

Material `AlertDialog` (CLAUDE.md platform swap for `.alert`): container `surfaceContainerHigh`, `extraLarge` shape, title "Something went wrong" (`titleLarge`), body = server `message` (`bodyLarge`, `onSurfaceVariant`), a single confirm `TextButton` "OK" (`labelLarge`, `onSurface`; it is not a destructive action and is not accent). Dismissing it (OK, scrim tap, Back) clears the stored error. When the server sends no message, use the fallback "Something went wrong. Try again." (network failures: "Check your connection and try again."), which reuse the Phase 2 strings.

## Interaction Contract (summary)

| Rule | Behavior |
|---|---|
| Field-level validation | Silent until the first submit; then live (D-02). The submit button is never disabled for an invalid form (D-03) |
| Submit while in flight | Ignored; the button is Saving and not clickable |
| IME | Login: email Next, password Done submits. Forgot: email Done submits. Set New Password: code Next, password Next, confirm Done submits |
| Keyboard | Fields stay visible above the keyboard (`imePadding` + scroll). The pinned submit button on Set New Password rides above the keyboard |
| Pre-fill | Login email to Forgot (D-07); Forgot email to Set New Password (carried state, not editable there); reset email to Login after Password Changed, password empty (D-10) |
| Confirmation hold | 600ms Saved state on "Send Reset Code" and "Set New Password" before navigating |
| Rotation / process death | Field text survives via `rememberSaveable` / saved state; server error text does not need to |
| Server inline errors | Clear on the next edit of that field |
| No resend, no cooldown | By decision (D-09) |

## Accessibility Contract

- All tap targets at least 48dp (links, text buttons, eye toggles).
- Error text is exposed through the `error()` semantics already inside `ValidatedField`; on a failed submit, focus moves to the first invalid field and TalkBack reads its error.
- The visible field labels on Forgot / Set New Password are hidden from TalkBack (`clearAndSetSemantics {}`) so a field is not announced twice; the placeholder is the accessible name (Phase 1 rule).
- The verification-code field offers SMS/email OTP autofill (`ContentType.SmsOtpCode`); password fields keep `ContentType.Password`; Login email `EmailAddress`.
- Saved states are announced via `liveRegion = Polite` (`AsyncSaveButton`, Phase 1).
- "Password Updated!" is a `heading()`; focus lands on it on arrival so TalkBack reads the success first.
- Meter color is never the sole signal: the strength word is always present. `destructive`, `tertiary`, `primary` on `surface` are all above 4.5:1 for the label text.
- Check all five screens at 200% font scale: the header, link rows and footer wrap rather than clip; the pinned Set New Password button keeps `heightIn(min = 56.dp)`.
- Full TalkBack pass is still Phase 15 (POL-04).

## Deviations from iOS (all intentional)

| iOS | Android | Why |
|---|---|---|
| Per-screen palettes and green gradients (`LoginBrand`, `ForgetPassBrand`, `NewPasswordBrand`, `PasswordUpdatedBrand`) | Phase 1 tokens; `GreenGlowBlobLayer` for atmosphere | Phase 1 FND-02 forbids per-screen palettes |
| Green text links ("Forgot Password?", "Sign Up", "Back to Login") | `onSurface` underlined | Phase 1 accent rule (links are neutral) |
| Login button radius 16, white text on green | `AsyncSaveButton` capsule, `onPrimary` text | Shared component and contrast (white on `#44F697` fails) |
| Wordmark 38pt, headline 36pt, titles 18-22 | 28sp / 20sp | Four-size type scale |
| 401 shows inline error and an alert | Inline under the password field only | CONTEXT D-04 |
