Build the app-scoped connection policy: when the realtime socket should be connected, which token it uses, and how it recovers from a handshake rejection without bypassing the Phase 2 refresh machinery.

Output: ProcessForeground seam and implementation, the manager, two test doubles and a virtual-time test class.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Socket handshake rejection -> REST session | A socket-side rejection triggers an authenticated REST call |
| Process lifecycle -> network | Background/foreground transitions open and close the socket |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-32 | Elevation of privilege / Denial of service | Refresh-token reuse from a socket-driven refresh | mitigate | The manager only calls `UserManager.refreshMe()`; refresh happens inside TokenAuthenticator's mutex with its rotated-token check; grep forbids TokenRefresher in realtime/ |
| T-03-33 | Denial of service | Reconnect or probe storm on a rejected or suspended token (against our own backend) | mitigate | `lastProbedToken` allows one probe per token; retries back off 2 s to 30 s; ACCOUNT_SUSPENDED routes to the global suspension trap and logout; background and logout cancel retries; tests cover each path |
| T-03-34 | Information disclosure | Previous user's socket alive after logout | mitigate | isLoggedIn false always disconnects; lastProbedToken resets; the service's generation guard drops stale callbacks (plan 03-08) |
| T-03-35 | Information disclosure | Socket open while the app is in the background | mitigate | ProcessLifecycleOwner STARTED gate disconnects on ON_STOP (D-14); push delivery is FCM's job (Phase 13) |
| T-03-36 | Denial of service | Rapid logout/login conflating the isLoggedIn StateFlow so the false edge is missed | accept | Login needs user input (seconds), so the collector sees the false edge; even if conflated, `connectWithStoredToken` reads the new token and the service rebuilds on a token change |
