# Phase 14 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Requirements PROF-01..05, PAYOUT-01..03 and the proposed PAYOUT-04 (Tax & Payout Info, CONTEXT D-08). Twelve surfaces:
> 1. Client Profile hub and Expert Profile hub (replace the throwaway Profile footers).
> 2. Client Profile Settings and Expert Profile Settings (auto-save).
> 3. Account Security (change password).
> 4. Delete Account: Warning, Reason + password, Farewell.
> 5. Help / FAQ.
> 6. Payouts.
> 7. Transactions ("Activity", full list).
> 8. Tax & Payout Info.
> 9. Log-out confirmation dialog and the Connect onboarding hand-off (Custom Tab, deep-link return).
> 10. Hand-offs that change visible behavior: Expert Tools "Profile Settings" and "Payouts" cells and the earnings-card tap (snackbar replaced by navigation), Notifications rows for payout and account (become tappable), expert self-view of the public profile.
>
> Out of scope and must not appear in the UI (CONTEXT D-01, D-06 and Deferred): Saved Experts, Payment History, Notification settings, Send Feedback, the iOS "Discovery" section, a Pause Account card (shown only if the backend ships the endpoint before planning; never inert), a fake "online" dot on the user card, the iOS "reset onboarding" version-tap affordance in release builds, a Save button on the settings screens, a discard dialog, a withdraw or "Cash out" button (payouts are automatic, `POST payouts/withdraw` is retired), and any "coming soon" placeholder.
>
> **Baseline.** `01-UI-SPEC.md` (tokens, shapes, motion, shell), `08-UI-SPEC.md` (destructive rule A5, `AuthErrorDialog`, quiet-reload snackbar), `12-UI-SPEC.md` (footer bar, empty/error pattern, tinted tiles) and `13-UI-SPEC.md` (row cards, `NotificationRow` look, `AuthTopAppBar`, `EmptyState` use) are locked and not restated. Dark only, Material 3, Nunito 400 / 600, exactly four text sizes (12 / 16 / 20 / 28 sp), `Spacing` xs..xxxl, `ClickMeShapes`, `MaterialTheme.extras`, Outlined icons, `AutoMirrored` Outlined back arrows. Every value below is an existing token unless marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/ClickMe2026/Views/Screens/` — `Client Mode/Profile/**`, `Expert Mode/Profile/**`, `Settings/Client Profile Settings/**`, `Expert Mode/Settings/ExpertProfileSettingsView.swift`, `Settings/Account Security/**`, `Settings/Delete account/**`, `Settings/Help/**`, `Expert Mode/Payouts/**`, `Expert Mode/Tax Profile/**`. The per-screen iOS palettes (`ProfileSettingsBrand`, `DeleteAccountBrand`, `HelpBrand`) collapse to the Phase 1 tokens (FND-02); glows, gradients and iOS-green money text become plain Material surfaces. Layout is ported and adapted to Material 3, not pixel-matched. Copy is taken from iOS unless marked "(Android)" or "(spec)". Section captions that iOS uppercases ("AVAILABLE BALANCE", "ACCOUNT") are sentence-cased (Phase 8 caption rule). Navigation-row and screen titles keep iOS Title Case where an existing Android row already does (`Payment Methods`); buttons and actions are sentence case (Phase 12 rule).
>
> **Source of decisions.** CONTEXT D-01..D-12 and the carried-forward items are locked and not re-asked. RESEARCH findings 1-11 and Pitfalls 1-10 supply the behavior contracts (deep links, delete race, null fields). This spec fills the "Claude's Discretion" areas: hub row order and icons, shared field composables, visual treatment of every state, and all copy marked (Android) / (spec). The run was non-interactive; every assumption is recorded under "Assumptions and Open Items". The `14-BACKEND-REQUEST.md` answers are still empty, so the Pause card is **absent** from this contract (D-06 default).

## Spacing Scale

Phase 1 tokens, all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

| Token | Value | Used for in this phase |
|-------|-------|------------------------|
| xs | 4px | Title-to-caption gaps in rows; icon-to-label gap inside pills; label-to-field gap; counter below a field |
| sm | 8px | Gap between rows inside a section; icon-to-label gap in buttons; gap between chips |
| md | 16px | Screen horizontal padding; card inner padding; gap between a section caption and its first row; gap between fields; footer bar padding |
| lg | 24px | Gap between hub sections; gap between form blocks; top padding under the app bar; empty-state vertical padding |
| xl | 32px | Bottom scroll padding plus navigation inset; gap above the version footer; `EmptyState` icon-to-heading gap (inherited) |
| xxl | 48px | Minimum touch target: auto-save status icon, edit icon button, password visibility toggle, radio rows' controls, FAQ headers, Retry |
| xxxl | 64px | Not used |

Exceptions (component dimensions and platform minimums, not layout spacing):
- Hub rows keep the `ProfileMenuRow` 56dp minimum height (grows with content). User card avatar 56dp; settings avatar 96dp.
- Mode-switch icon tile 48dp circle, glyph 24dp.
- Payout status card icon tile 64dp square, `medium` shape (iOS 64pt), glyph 32dp (new size, status-card hero only).
- Status pills (`EarningsStatusPill`): `heightIn(min = 24.dp)`, horizontal padding `sm`, non-interactive.
- Reason rows on Delete Account: `heightIn(min = 56.dp)`, whole row is the `selectable` target.
- Bio and feedback fields `heightIn(min = 120.dp)`; stroke 1dp resting, 2dp focused.
- Skeletons copy the real dimensions above.

### 2. Profile Settings and Expert Settings (PROF-02, D-10..D-12)

Routes `ClientProfileSettingsKey`, `ExpertProfileSettingsKey`. Background `surface`. `verticalScroll` column, `imePadding()`, `md` horizontal padding.

**Auto-save (D-10).** No Save button, no discard dialog. A 1.2 s debounced PATCH after each change (RESEARCH Pattern 3); unchanged snapshots are skipped; a pending edit is flushed on Back. `AutoSaveStatusIcon` lives in the `AuthTopAppBar` `actions`, 48dp target, one of four states with a 150 ms cross-fade:

| State | Glyph | Semantics |
|---|---|---|
| Idle | none (an empty 48dp slot so the bar does not shift) | none |
| Saving | 24dp `CircularProgressIndicator`, 2dp stroke, `primary` | `stateDescription` "Saving" |
| Saved | `CheckCircle` Outlined 24dp `onSurfaceVariant`, fades to Idle after 2 s | `contentDescription` "Changes saved", `liveRegion = Polite` |
| Error | `ErrorOutline` 24dp `error`, stays until the next successful save; tapping it re-runs the save | `contentDescription` "Couldn't save changes. Tap to retry." |

A save failure also opens `AuthErrorDialog` titled "Couldn't save changes" with the server message else "Check your connection and try again." (dismiss "Got it"). A failed avatar upload opens its own `AuthErrorDialog` titled "Couldn't upload avatar" (iOS), same body rule, and the previous avatar remains. Test tags `settings_autosave_status`.

**Avatar block (`ProfileAvatarSection`).** Centered `Avatar` 96dp, `lg` top, `md` below it a text button "Change photo" (`labelLarge`, `onSurface`, underlined, 48dp target). Tapping the avatar or the button launches `PickVisualMedia` (image only); the result goes through the Phase 4 `PhotoCropScreen` / `PhotoProcessor`, then uploads. While uploading, a 96dp scrim (`scrim` 40%) with a 32dp `primary` spinner covers the avatar. On success `userManager.refreshProfile()` updates the hub card and top-bar avatar.

**Field stack (`lg` between groups, `md` between fields in a group; label `labelLarge` above each field, `xs` gap, as `ValidatedField`).**

| # | Field | Rule |
|---|---|---|
| 1 | Email | `ProfileReadOnlyField`: `surfaceContainerLow` container, `medium`, 1dp `outlineVariant`, value `bodyLarge` `onSurfaceVariant`, `Lock` 20dp `onSurfaceMuted` trailing. Not focusable; semantics "Email, {value}, read only" |

## Accessibility Contract

- Touch targets at least 48dp: auto-save icon, edit icon, password toggles, "Change photo", hub rows (56dp), reason rows (56dp), FAQ headers (56dp), all buttons (56dp), Retry.
- Hub rows, the user card, the mode-switch card and transaction rows each expose one merged node; icons are decorative. Section captions and screen headlines are `heading()`.
- Reason rows are a `selectableGroup` of `Role.RadioButton` items; FAQ headers expose `stateDescription` "Expanded" / "Collapsed"; password toggles expose their action as `contentDescription`.
- The auto-save Saved state is a polite live region; inline field errors are announced with the field (`error` semantics); the Farewell headline takes focus on entry.
- Status pills carry their label as text (color is never the only signal); amounts read with the currency via `Money.format`.
- All text scales with the system font scale; no fixed-height text containers.
- Passwords, TIN and the deletion token are masked and excluded from autofill saving where the platform allows (`contentType = Password` only for the sign-in-style fields; the TIN and deletion password use no autofill hint).
