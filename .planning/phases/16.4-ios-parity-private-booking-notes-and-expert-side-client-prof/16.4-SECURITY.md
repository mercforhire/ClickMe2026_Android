# Phase 16.4 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| app → backend | Authenticated GET and POST on the note routes (`client/bookings/{id}/note`, `bookings/{id}/note`) and GET `expert/clients/{id}` | Bearer, id in the path, `{"note"}` body of at most 5,000 UTF-16 units |
| backend → app | Server JSON decoded to DTOs | Note text, `private_note_preview`, a client's name, bio, location and avatar, earnings breakdown |
| user → editor → backend | User-written note text sent as the strict body | Note text, in memory only |
| backend → editor (404 ambiguity) | A 404 on load or save means missing or not yours | Status code |
| ViewModel state → logs and crash reports | Note text and client profile live in memory only | Note text, profile |
| Nav3 back stacks | Keys from different tabs are flattened into one `NavDisplay` | Typed keys |
| Saved navigation state | Keys are serialized for process death | Ids, display name, topic and times only |
| Server text → UI | Untrusted text rendered on cards, summaries and the profile | Notes, previews, name, bio, location |
| backend → user (money) | Earnings from the feed shown as net amounts | Net amount, currency |
| 403 and 404 responses | Friendly states must not imply more than the response says | Status and code |
| Nested tap targets | A clickable control inside a clickable card | Tap events |
| Shell registration, chat menu → backend | Which shell or menu item can reach the expert routes; `ensureExpert` converts a client-only account on first touch | Route keys, `AppMode` |
| Repository docs → people | Committed Phase 16 runbook | Role labels, outcomes only |
