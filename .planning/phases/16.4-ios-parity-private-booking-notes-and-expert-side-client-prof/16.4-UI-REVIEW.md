## Top 3 Priority Fixes

1. **Editor field `contentDescription` override (TalkBack, unconfirmed)** — a TalkBack user may not hear the typed note text — set the label through a visible `label` or `stateDescription` instead of overriding `contentDescription`, and verify on a device. Same pattern in `ReviewTextField.kt:76`.
2. **Dashed "Add private note" row has no `onClickLabel`** — TalkBack reads a bare "Add private note, button" while the strip, action and card all announce "Open private note" — add `onClickLabel = stringResource(R.string.booking_note_open_a11y)` in `AddNoteRow` (`PrivateNoteParts.kt`, the `clickable(role = Role.Button, ...)` call).
3. **Dashed row shape mismatch** — it draws a hard-coded 10dp radius while its sibling strip uses `shapes.small` (12dp), and the `clickable` is not clipped so the ripple is square — read the radius from `MaterialTheme.shapes.small`, add `.clip(shape)` before `clickable`.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- Checked `strings_booking_note.xml` and `strings_client_profile.xml` against the contract table: every row matches. That covers titles, placeholder, counter `%1$s / %2$s`, a11y Saving/Saved, load and save error titles, the Discard dialog (title, body, Keep editing, Discard), `Private Note`, `Add private note`, My Note card title and prompt, all section headings, About labels, stat labels with the Session/Sessions plural, bucket labels, `%1$s - %2$s` subtitle, the 403 and 404 heading and body, and `—`.
- Fallbacks reuse the existing resources (`explore_session_topic_fallback`, `expert_profile_go_back`, `section_retry`).
- I did not open `strings_expert_booking_summary.xml`, but the `View Profile` link uses `R.string.expert_summary_view_profile`.
- WARNING: `AddNoteRow` in `PrivateNoteParts.kt` omits `onClickLabel`, which the spec lists as shipped for all note surfaces ("Open private note").

### Pillar 2: Visuals (3/4)
- Focal points match: editor field with Save as the single bar action; avatar with ring and glow, then the `displaySmall` name.
- Placement against spec section 2 verified:
  - `UpcomingBookingCard.kt` and `ExpertUpcomingCard.kt` render `PrivateNoteZone` as the last child of the card column, after Join, Reschedule and Message.
  - `PastBookingCard.kt` uses a `FlowRow` with `SpaceBetween` holding `PrivateNoteAction` plus the review pill, then `NotePreviewFooter` only for a non-blank preview.
  - `ExpertPastCard.kt` has the action alone, start-aligned, then the footer.
  - Client `BookingSummaryScreen.kt:336` places `MyNoteCard` after the feedback block and before Book Again with `padding(top = Spacing.lg)`.
  - Expert `ExpertBookingSummaryScreen.kt:400` places it after the message card and before Join and Message in the `spacedBy(md)` column.
  - Upcoming Booking Details has no note surface (not touched).
- `ExpertSummaryCard.kt`: the "View Profile" `TextButton` (`labelLarge`, `primary`, zero padding, 48dp min height) sits between the name and the short id in a wrapping `FlowRow`, as specified.
- WARNING: `AddNoteRow` radius is a private 10dp constant (`ZoneCornerRadius`) while strips use `shapes.small`, and its ripple is unclipped.
- Finding 3 (avatar glow), verified against source and downgraded to minor: the glow is a 130dp-radius `drawBehind` on a 200dp-tall box, so it overflows 30dp top and bottom. At that edge the alpha is about 0.20 x (1 - 100/130), roughly 0.05, so it is very faint. LazyColumn clips to its own bounds, so the top overflow is cut at the app bar edge. The bottom overflow sits behind the name text. Not verified on a device.

### Pillar 3: Color (4/4)
- Colors come from `MaterialTheme.colorScheme` and `extras`, and the script found no hex literals.
- The primary tint alphas match the spec: strip 0.08/0.25, My Note card 0.06/0.30, tile 0.15/0.45, Upcoming row border 0.55.
- The Cancelled tile uses `error`. The amount stays `onSurface`. The "Client" pill is not accent. The counter is `tertiary` only at the cap.
- Not verified: the 60/30/10 split as actually rendered.

### Pillar 4: Typography (4/4)
- Only `typography.*` slots are used: `displaySmall`, `titleLarge`, `titleMedium`, `titleSmall`, `bodyLarge`, `bodyMedium`, `bodySmall`, `labelLarge`, `labelMedium`, `labelSmall`. This matches the spec's role table.
- No `fontSize` or `FontWeight.Bold` anywhere in the audited files.

### Pillar 5: Spacing (3/4)
- Section gaps are `spacedBy(md)` plus a top `md`, which gives `xl` between sections. History rows stay `md` apart. Info rows are `sm` apart. Stat cells are `sm` apart with equal height via `IntrinsicSize.Min`. List bottom padding is `xxl` and the `EmptyState` top offset is `xxxl`.
- Fixed dp values (24, 44, 142, 148, 200, 260, 1, 2, 3) are all listed under the spec's "Exceptions".
- WARNING: `ZoneCornerRadius = 10.dp` is off the shape scale.
- WARNING (low): `ProfileSkeleton` has no `contentMaxWidth()` on its column, and `ErrorState`, `EmptyState` and the editor Failed state are not width-capped. The spec only requires the cap on loaded content.

### Pillar 6: Experience Design (3/4)
- Covered in code:
  - Editor: loading skeleton, loaded, failed with Retry, a 150ms Crossfade, and Save in Idle, Saving and Saved modes in 48dp boxes. The Saved check is a polite live region and shows only while the text is unchanged since save. Back is disabled and swallowed while saving. The Discard dialog has no text field. The save error uses `AuthErrorDialog`.
  - Client Profile: skeleton, loaded, `ErrorState` with Retry, 403 and 404 with "Go back" and no Retry, `PullToRefreshBox` over every state, and the refresh-failed snackbar.
  - History rows are non-interactive, with a merged TalkBack description.
- Finding 1 (editor field `contentDescription`), what I could and could not confirm:
  - Confirmed: `BookingNoteScreen.kt` sets `semantics { contentDescription = fieldLabel }` on the `TextField`, with the same pattern as `ReviewTextField.kt:76`.
  - Confirmed: Compose BOM is 2026.09.00. The Gradle cache holds foundation 1.10.4 and 1.12.1.
  - Not confirmed: how that Compose version announces a text field with `contentDescription` set. I did not read Compose source or run TalkBack. The concern is that it replaces the value announcement. Treat it as a risk to test on a device, not a proven defect.
- Finding 2 (editor header name not a heading): confirmed in source. The name is `titleLarge` in a merged node with no `heading()`. Minor.
- Finding 8, corrected: **withdrawn.** In `ClientProfileBookingHistory.kt` the same `date` variable, from `formatShortDate` (medium locale style, "Oct 1, 2026" in en-US), feeds both the visible subtitle (`client_profile_row_subtitle`) and the spoken string (`client_profile_row_a11y`). The spoken and visible dates cannot disagree. The spoken form reads "title. Completed, date. Earnings amount" (the amount only when it shows).
- Unproven: wrapping at 200% font for stat cells and history rows (default wrapping, no `maxLines`); the Failed editor state is not scrollable and could clip at large font (spec backstop FS.PN1 covers only the loaded form).
