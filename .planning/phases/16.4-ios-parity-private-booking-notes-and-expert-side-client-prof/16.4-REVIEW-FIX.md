### WR-02: Save failures that `toDialogError()` maps to null leave the user with no feedback

**Files modified:** `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/bookingnote/BookingNoteViewModel.kt`
**Commit:** ed36e219
**Option taken:** (b) record the guarantee in a comment. No behavior change. `suspendedSaveShowsNoDialog` is unchanged and still passes.

**Evidence that the global handler takes over the UI:**
- `toDialogError()` (`screens/login/FieldError.kt:35`) returns null in exactly one case, `ApiException.Http` with `code == ErrorCode.AccountSuspended`. Every other failure maps to a `FieldError`, so no other class of error is silent.
- `SuspensionInterceptor` is installed on the shared OkHttp client (`NetworkFactory.kt:49`). On any 403 whose body code is `ACCOUNT_SUSPENDED` it clears the tokens synchronously and emits `SessionEvent.Suspended`.
- `UserManager.onSessionEvent` (`UserManager.kt:134`) calls `handleAccountSuspended()`, which sets `wasSuspended` and calls `logout()`, which flips `isLoggedIn` to false.
- `AppViewModel` (`AppViewModel.kt:57-61`) collects `isLoggedIn`; when it goes false on a route in `SESSION_ROUTES` (`ClientHome`, `ExpertHome`, `SignupSetup`) it sets the route to `Login`. The note editor is only reachable from a home route, so it leaves composition.
- `ClickMeApp.kt:88` shows `SuspendedAccountDialog` from `showSuspendedDialog` (= `wasSuspended`), drawn above the route switch.
- Sibling convention is the same silent-on-suspension pattern: `WriteReviewViewModel`, `BookingErrors` (`BookingFailure.Silent`), `RescheduleErrors`, `ProposeErrors`, `PaidFlowError`, `SafetyErrors`/`ReportAndBlockViewModel`/`ProfileSafetyViewModel`, `DeleteAccountViewModel`, `AccountSecurityViewModel`, `SignupInitialViewModel`. None adds a generic fallback for suspension.
- iOS: `ClientBookingNoteViewModel.save()` sets `errorMessage = error.userMessage` for any error, but iOS also has the global `suspensionHandler` in `UserManager.swift:134-139` that raises `wasSuspended` and logs out; the comment there says the original error still propagates to the caller. The Android split (global dialog owns it, screen stays silent) is the app-wide port of that.

Adding a generic "Couldn't save note" message would have shown a second, redundant dialog under the suspended-account dialog on a screen that is being torn down, and would have broken the sibling convention, so option (a) was not taken.
