## Summary

This is an incremental re-review of the two fix commits. Both fixes are sound and I found no new defects. WR-01 and WR-02 from the previous report are resolved and are dropped from this report. IN-01, IN-02 and IN-03 were not part of the fix commits and are still open. They are retained below, with one line number updated.

**1239f53f (WR-01).** Resolved.
- `notePreviewText` is `raw.trim().replace(Regex("\\s*\\n\\s*"), " ")`. The old failure input `"\n\nCall about pricing"` now becomes `"Call about pricing"`, because `trim()` removes the leading blank lines before the line-break collapse runs.
- It is display only. The only call site is `NotePreviewStrip`, and the `MyNoteCard` change is `note.trim()` in the `Text` argument. The ViewModel and the request path are not touched, so what is saved and what is edited are unchanged.
- The `isNullOrBlank` gates (the two card callers, `PrivateNoteZone` and `MyNoteCard`) and `trim()` both use `isWhitespace`, so a preview that passes the gate cannot trim to empty.
- A hand trace of `"one\n \n  two  "` gives `"one two"`, which matches the test. Windows `\r\n` is covered because `\s` includes `\r`.
- The new tests would have failed before the fix. `onNodeWithText` is an exact match by default, and the old code exposed `"\n\nCall about pricing"` as the node text. `previewWithLeadingBlankLinesShowsItsFirstWords` and `myNoteCardTrimsLeadingBlankLines` therefore exercise the change. `previewTextTrimsEdgesAndCollapsesLineBreaks` covers the pure function, including the non-regression case `"a b"`.

**ed36e219 (WR-02).** Comment only, with no behavior change. Every claim in the new comment checked out against the source:
- "`toDialogError()` is null only for ACCOUNT_SUSPENDED": true. `FieldError.kt:35-45` returns null only for `ApiException.Http` with `code == ErrorCode.AccountSuspended`. The `Network` and `Decoding` branches and every other `Http` code return a non-null error.
- "`SuspensionInterceptor` has already cleared the tokens and raised `SessionEvent.Suspended`": true. `SuspensionInterceptor.kt:22-28` calls `tokens.clear()` and then `sessionEvents.emit(SessionEvent.Suspended)` inside the 403 plus `AccountSuspended` branch. This runs in the interceptor, before the exception reaches the ViewModel's catch block.
- "`UserManager` logs out": true. `UserManager.kt:134` maps `Suspended` to `handleAccountSuspended()`. That sets `_wasSuspended` once and calls `logout()`, which flips `_isLoggedIn` to false.
- "`AppViewModel` moves this home route to Login": true. The `isLoggedIn` collector at `AppViewModel.kt:56-62` sets `AppRoute.Login` when the route is in `SESSION_ROUTES`. `SESSION_ROUTES` contains `ClientHome` and `ExpertHome`, and the editor is hosted under those shells.
- "`ClickMeApp` shows the global suspended dialog": true. `ClickMeApp.kt:88` renders `SuspendedAccountDialog` when `showSuspendedDialog` is set. That flag comes from `userManager.wasSuspended`, and the dialog is outside the route switch.
- "Same as every sibling screen": true for the screens I checked. `DeleteAccountViewModel`, `WriteReviewViewModel`, `SafetyErrors`, `BookingErrors`, `PaidFlowError` and `ClientProfileSettingsViewModel` all return null for this code and defer to the global dialog.

One nuance, not a defect: the chain is asynchronous. `emit` is picked up by a collector on `appScope`. The catch block can therefore reset `isSaving` a moment before the route changes, and the editor can briefly show an enabled Save button. The comment says "(the editor leaves composition)", which is accurate in the end state. The project's global-handler design (Phase 2 D-08) accepts this brief window, so I am not raising it as a finding.

The new comment lines and the rewritten code stay within 120 columns. The only over-long line in the two production files is the existing `BookingNoteViewModel.kt:66`, which is IN-02.

### IN-01: Client Profile history row shows an empty title for a blank topic

**File:** `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/expertmode/clientprofile/subviews/ClientProfileBookingHistory.kt:75`
**Issue:** `row.item.topic ?: stringResource(...)` falls back only on null. The carried iOS rule ("topic falls back to Session") uses `??` too, but every other Android card in this phase treats a blank topic as missing, for example `BookingNoteScreen.kt:341` uses `takeIf { it.isNotBlank() }`. A `""` or whitespace topic from the server gives a blank row title and a spoken description that starts with ". ".
**Fix:** `val title = row.item.topic?.takeIf { it.isNotBlank() } ?: stringResource(R.string.client_profile_session_fallback)`

### IN-03: "Add private note" row has no `onClickLabel`

**File:** `app/src/main/java/com/uptrendinvestments/clickmeapp/components/booknote/PrivateNoteParts.kt:275`
