# Phase 16.4 Plan 09: My Note and View Profile on Expert Booking Summary, and the real expert shell registrations Summary

**The expert's full private note (or the prompt) now shows on Expert Booking Summary in the iOS position, a "View Profile" link under the client's name opens the read-only Client Profile on the summary's own stack, and `HomeExpertScreen` registers the real note editor and Client Profile so every expert entry point opens them end to end.**

## Accomplishments

- `ExpertBookingDetail` decodes `expert_private_note`; the display model maps a blank note to null; both `toString` implementations omit the note (T-16.4-26).
- `MyNoteCard` sits after the client's message and before Join and Message on every status. The tap asks the ViewModel for a note key, which copies the summary's origin (T-16.4-28), so the editor lands on the stack that opened the summary.
- `ExpertSummaryCard` has a "View Profile" `TextButton` (48 dp, `labelLarge`, primary) between the client name and the short id. `expertBookingSummaryEntries` pushes `key.clientProfileKey(clientId)`.
- `HomeExpertScreen.detailEntries` registers `expertBookingNoteEntry` with `ExpertBookingNoteRoute` and `expertClientProfileEntry` with `ExpertClientProfileRoute`. This closes the gap from 16.4-07: expert card note controls navigated to a key with no entry in production. The client shell is untouched (acceptance grep: 0 matches in `HomeClientScreen.kt`) (T-16.4-27).
- `aSavedNoteShowsOnReturn` passes with no refresh code: the first load has no note, the handler then returns "Call back", and `onScreenHidden()` plus `refreshQuietly()` leave `Loaded` throughout with the note shown (D-08).
