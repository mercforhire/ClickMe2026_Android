# Phase 16.4 — UI Design Contract

> Visual and interaction contract for Phase 16.4 (private booking notes, both roles, and the expert-side Client Profile). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Late spec.** This contract was written after Wave 1 (plans 16.4-01 and 16.4-02) merged, because the UI safety gate halted execution without one. Shipped code is the baseline for the shared note composables; plans 16.4-03 to 16.4-10 are not started and can still be shaped by it. The one place where this spec asks for something different from a plan is `## Conflicts With Existing Plans`.
>
> Designs live in Google Stitch and are not accessible, so the iOS views under `ios-reference/ClickMe2026/Views/Screens/{Client Mode/Booking Note, Expert Mode/Booking Note, Expert Mode/Client Profile}` are the stand-in source of truth. Where iOS and the Android design system disagree on a value, the Android token wins (see "Deliberate visual deviations from iOS"). No new colors, sizes, weights or spacing tokens are introduced.
>
> Decisions D-01 to D-15 in `16.4-CONTEXT.md` are locked and are not re-argued here. Items this spec had to decide that CONTEXT left open are tagged **Assumption** and collected in "Open assumptions".

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Jetpack Compose + Material 3; shadcn does not apply to Android) |
| Preset | not applicable |
| Component library | Material 3 (`androidx.compose.material3`) plus the in-house `components/` set |
| Theme | Dark only. `ClickMeTheme` in `ui/theme/` (`Color.kt` `ClickMePalette`, `Type.kt`, `Spacing.kt`, `Shape.kt`, `Extras.kt`, `Motion.kt`, `ContentWidth.kt`) |
| Icon library | Material Icons Extended (`androidx.compose.material:material-icons-extended`, `Icons.Outlined.*` / `Icons.Filled.*` / `Icons.AutoMirrored.*`) |
| Font | Nunito variable font (`NunitoFamily`), weights 400 and 600 only |

Hard rules inherited from the project (enforced by `scripts/check-design-rules.sh`): no hex literals outside `ClickMePalette`; no `*Brand` types (so `ClientProfileBrand` is not ported); never set `fontSize` outside `Type.kt`; read colors from `MaterialTheme.colorScheme` or `MaterialTheme.extras`; read spacing from `Spacing`; a screen file with a text field needs `imePadding` plus `verticalScroll`; an `AlertDialog` never contains a text field. Do not pass `FontWeight.Bold`: use the 600 styles.

## Spacing Scale

Declared values (multiples of 4), from `Spacing`:

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4dp | Editor header line gaps, counter top gap, info-row label-to-value gap, history title-to-subtitle gap, stat value-to-label gap, "Client" pill vertical padding |
| sm | 8dp | Info-row gaps (About), bio label gap, name-to-badge gap, stat-cell gap, note strip inner padding (shipped) |
| md | 16dp | Screen horizontal padding on both new screens, card inner padding (info rows, stat cells, history rows, My Note card), history-row gap, section heading to content, icon-to-text in info rows, status tile to text, "Client" pill horizontal padding, top padding of both screens |
| lg | 24dp | Editor header-to-field gap; gap above the client Booking Summary "My Note" card |
| xl | 32dp | Gap between Client Profile sections (name block, About, Sessions Together, History), editor bottom padding |
| xxl | 48dp | Client Profile list bottom padding (clears the system bar) |
| xxxl | 64dp | Top offset of the 403 and 404 `EmptyState` (same as Expert Profile's `UnavailableBody`) |

Layout values (every gap is a token from the standard set; iOS values that were off-scale are mapped to the nearest token and listed under "Deliberate visual deviations from iOS"):
- Card corner: `MaterialTheme.shapes.medium` (16dp) for every Client Profile card and the My Note card; `shapes.small` (12dp) for the note strips (shipped); `shapes.extraSmall` (8dp) for the history status tile.
- Gap between booking cards on the Bookings tabs: unchanged (existing `CardSpacing`). The note zone is the **last child of the card column**, `md` below the action row (the column's existing `spacedBy(Spacing.md)`).
- Expert Booking Summary: the My Note card is a sibling in the existing `Column(spacedBy(Spacing.md))`, so it sits `md` below the client message card and `md` above Message. Client Booking Summary: `padding(top = Spacing.lg)` above the card, matching the existing `Book Again` button's `lg` top padding.

Exceptions (fixed sizes, not spacing):
- Editor field minimum height 260dp (iOS 260); it grows with content inside the scroll column.
- Client Profile avatar block: 200dp tall, ring 148dp (3dp stroke), photo 142dp, glow radius 130dp. Component dimensions, intentionally outside the scale.
- History status tile 44dp square with a 24dp icon (iOS 44).
- Note composables (shipped): 48dp minimum targets, 16dp icons, 1dp borders, dash 4dp on and 3dp off.
- Touch targets: Save action 48dp box, back arrow 48dp, "View Profile" link minimum height 48dp, "Private Note" action 48x48dp minimum, "Go back" / "Retry" buttons per `PressScaleButton`.
- Skeletons: editor field block 260dp; Client Profile avatar circle 142dp, name line 28dp tall, card blocks 72dp tall.

| Label | 12sp | 400 / 600 | 16sp (1.33) | `bodySmall` (400) / `labelMedium` (600) / `labelSmall` (400) | Editor date line, counter, info-row labels (600), stat labels (400), history subtitle (400), note preview text (400, shipped), "Add private note" (600, shipped) |

Values come from `ClickMePalette` (documentation only: always reference the theme slot, never the hex).

| Role | Slot | Value | Usage |
|------|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` | #131313 | Screen background of the editor and Client Profile, TopAppBar |

Accent reserved for (and nothing else):
1. The editor's Save action text when enabled, its saving spinner and its saved check.
2. The note field's cursor and 2dp focused border.
3. The shipped note surfaces: "Private Note" action text and pencil, note and pencil icons, the preview strip tint (fill 0.08, border 0.25) and the My Note card tint (fill 0.06, border 0.30).

5. The 1dp 0.55-alpha border on Upcoming-bucket history rows.
6. The "View Profile" link on Expert Booking Summary.
7. The filled Retry / Go back button inside `ErrorState` / `EmptyState` (existing behavior) and the pull-to-refresh indicator.

Not accent: amounts (`onSurface`), the Cancelled tile (`error`), the "Client" pill (`onSurfaceVariant` on `surfaceContainerHigh`), the chat menu's "View profile" item (`onSurface`, existing menu styling), the "Discard changes?" title.

Selected-state color: none. The status tile tint is the only per-status color, mapped by bucket (Upcoming and Completed `primary`, Cancelled `error`).

## Screen And Component Contracts

### 1. Note editor (`BookingNoteScreen`, both roles)

Chrome: `Scaffold(containerColor = surface)` + `AuthTopAppBar(title = "My Note", onBack = leave, backEnabled = !isSaving, actions = save slot)`. TopAppBar container is `surface`. No snackbar host (errors are dialogs by D-03).

Body by load state, cross-faded over 150ms (`Motion.CONTROL_STATE_DURATION_MS`):

| State | Contract |
|-------|----------|
| Loading | `SkeletonGroup`: name block 24dp x 160dp, topic block 16dp x 120dp (`xs` apart), then a 260dp `shapes.medium` field block, `lg` below the header. Save is shown disabled |
| Loaded (empty or with note) | Column: `fillMaxSize`, Scaffold padding consumed, `imePadding()`, `verticalScroll`, `contentMaxWidth()`, horizontal `md`, top `md`, bottom `xl`. Header block, then the field `lg` below it, then the counter `xs` below the field |
| Failed | `ErrorState(heading = "Couldn't load note", body = message, retryLabel = "Retry")` centered, Save shown disabled, back arrow active |

Header block (one merged TalkBack node): name `titleLarge` `onSurface` (wraps); topic `bodyMedium` `onSurfaceVariant` (wraps); date line `bodySmall` `extras.onSurfaceMuted`; `xs` between lines.

Field: plain M3 `TextField` styled exactly like `ReviewTextField`: min height 260dp, grows with content, no `maxLines`, `shapes.medium`, container `surfaceContainer`, indicator colors transparent, a hand-drawn border 1dp `outlineVariant` resting and 2dp `primary` focused, cursor `primary`, text `bodyLarge` `onSurface`, placeholder `bodyLarge` `extras.onSurfaceMuted`, capitalization sentences. Content description "Private note". No autofocus (iOS has none; opening the keyboard on load would cover the header). Text is plain; no autolink or markdown.

Counter: shown only when length is at least 4,500; below the field, end-aligned, `xs` top, `bodySmall`, `extras.onSurfaceMuted`, `tertiary` at exactly 5,000. Not a live region.

Save action slot (mirrors `AvailabilitySaveAction`; 48dp boxes so the bar never shifts; 150ms cross-fade between the three looks):
- Idle: `TextButton("Save")`, `labelLarge`. Enabled only when loaded, changed and not saving. Disabled (M3 default 38% content alpha) in Loading, Failed and unchanged.
- Saving: 24dp `CircularProgressIndicator` (`primary`, 2dp stroke) in a 48dp box, description "Saving". Back arrow and system back are disabled.
- Saved: `Icons.Filled.CheckCircle` 24dp `primary` in a 48dp box, description "Saved", polite live region, shown for 1.5s (D-03). The check is shown only while `didSave` and the text has not changed again (see Conflicts C2); an edit during the 1.5s brings Save straight back.

Dialogs: both are Material `AlertDialog`s with `containerColor = surfaceContainerHigh`, `shape = shapes.extraLarge`, title `titleLarge`, body `bodyLarge` `onSurfaceVariant` (the shipped `AuthErrorDialog` styling).
- Save error: `AuthErrorDialog` titled "Couldn't save note", server message, "OK". The text stays in the field.
- Discard (D-01): dismiss `TextButton("Keep editing")` (`labelLarge`, `onSurface`), confirm `TextButton("Discard")` (`labelLarge`, `colorScheme.error`). Back and scrim cancel the dialog (= Keep editing). Shown from the app-bar arrow and from system back, only when there are unsaved changes. No text field inside.

### 4. Client Profile (`ExpertClientProfileScreen`, read-only)

Chrome: `Scaffold(containerColor = surface)` + `AuthTopAppBar(title = "Client Profile", onBack)` + a `SnackbarHost`. The whole body sits in a `PullToRefreshBox` (pull works from every state, as on iOS), cross-faded over 150ms between states.

| State | Contract |
|-------|----------|
| Loading | `SkeletonGroup`: 142dp circle, 180dp x 28dp name line, then three 72dp `shapes.medium` blocks, `md` apart. No spinner |
| Loaded | `LazyColumn`, `contentMaxWidth()`, horizontal `md`, top `md`, bottom `xxl`, sections `xl` apart, in the iOS order below |
| Failed (D-12) | `ErrorState("Couldn't load profile", message, "Retry")` centered in a scrollable column (so pull works). Never a partial history |
| NoRelationship (D-14) | `EmptyState(icon = Icons.Outlined.PersonOff, heading, body, action = "Go back")`, top offset `xxxl`, scrollable. No Retry |
| Unavailable (D-15) | Same layout as NoRelationship with the 404 copy. No Retry |
| Refresh in progress | Existing content stays; M3 pull indicator |
| Refresh failed over loaded | Content stays; `RefreshFailedSnackbarEffect` shows "Couldn't refresh" with Retry |

Loaded sections, top to bottom:

1. **Avatar** (`ClientProfileAvatar`): 200dp tall box, centered, decorative (`clearAndSetSemantics {}`). Layers: a static radial glow (`primary`, alpha 0.20 at the center to 0 at 130dp, drawn with `drawBehind`, no blur, no pulse, Assumption A5); a 148dp ring (`border(3.dp, primary, CircleShape)`); `Avatar(size = 142.dp, contentDescription = null, fallbackColor = ClickMePalette.avatarFallback)`. The iOS ring shadow glow is dropped (blur is API 31+ only).
2. **Name and badge** (`ClientProfileNameBadge`): name `displaySmall` `onSurface`, centered, wraps, heading semantics, fallback "Client"; `sm` below, a non-interactive pill "Client" (`labelLarge`, `onSurfaceVariant`, fill `surfaceContainerHigh`, 1dp `outlineVariant`, `CircleShape`, horizontal `md`, vertical `xs`).
3. **About** (`ClientProfilePersonalInfo`): heading "About" (`titleLarge`, heading semantics), `md` below, rows `sm` apart. Bio card first (when bio is non-blank): label row (16dp `primary` quote icon, `sm`, "Bio" `labelMedium` `onSurfaceVariant`), then the bio (`bodyLarge`, `onSurface`, wraps, no line limit). Then one info row each, hidden when empty, in this order: Location, Timezone, Languages, Member since. Row: card (`surfaceContainerLow`, 1dp `outlineVariant`, `shapes.medium`, padding `md`), top-aligned: 24dp `primary` icon, `md`, a column with the label (`labelMedium`, `onSurfaceVariant`) over `xs` and the value (`bodyLarge`, `onSurface`, wraps). Location = city, state or province, country joined with ", " skipping blanks; country is the raw code the server sends (Assumption A8). Member since `MMMM yyyy`, locale-aware. If every row is empty the heading stays, as on iOS (practically unreachable: the server always sets member since)

## Accessibility Contract

- Touch targets are at least 48dp: back arrow, Save action box, "Private Note" action, note zone and preview strips, My Note card, "View Profile" link, "Go back" / "Retry", the chat menu item.
- Headings: TopAppBar titles, "About", "Your Sessions Together", "Booking History", the Client Profile name, dialog titles, `EmptyState` headings. Failure states are polite live regions (`ErrorState` already is); the saved check is a polite live region.
- Skeleton groups announce one "Loading" (`SkeletonGroup`).
- Decorative: the avatar block and glow, row icons, status tile icons, note icons and pencils (the surface supplies the name).
- Merged nodes: editor header; each stat cell ("3 Sessions"); each info row (label then value); each history row (title, bucket, date, and "Earnings {amount}" when shown). History rows expose no click action and no button role (D-10). The "Client" pill is read with the name.
- Note controls: each is a Button named "Open private note" (or "Private Note"); the past cards also expose "Private Note" as a custom action on the merged card node, so the nested control is reachable without relying on touch exploration.
- The editor field has the content description "Private note" (same as `ReviewTextField`); the counter is plain text.
- Save disabled and Back ignored while saving is announced by the "Saving" description on the spinner.
- Contrast: all text uses `onSurface`, `onSurfaceVariant`, `extras.onSurfaceMuted` or `primary` on `surface`, `surfaceContainer`, `surfaceContainerLow` or `surfaceContainerHigh`, the same pairs already used app-wide. `primary` at 0.06 to 0.08 fills only tint a surface behind `onSurface` and `onSurfaceVariant` text.
- Dialogs and snackbars follow the Material 3 defaults (focus trap, back dismisses the dialog).
- Font scale: nothing in this phase uses a fixed text height; rows and cards use minimums, `FlowRow` or wrapping so 200% font grows them.
