# Phase 16.4 Plan 07: Private note on the expert Bookings cards Summary

**Expert Bookings cards now carry the private note: "Private Note" plus a preview footer on every past card, a note zone as the last child of every upcoming card, fed by a new `private_note_preview` field on `ExpertBookingItem` and routed to `ExpertBookingNoteKey` (origin Bookings) from the Bookings route.**

## Performance

- **Duration:** about 25 min (Gradle runs dominate: the first cold run took 5.5 min)
- **Tasks:** 2 (Task 1 tracer, Task 2 auto)
- **Files modified:** 9 (5 main, 4 test), none created

## Accomplishments

- Tracer (Task 1): `ExpertBookingItem.privateNotePreview` with a redacted `toString` and rewritten KDoc, `ExpertPastCard.onPrivateNote` with `PrivateNoteAction` on every status, `NotePreviewFooter` for a non-blank preview, a TalkBack custom action in the card's existing semantics block, `onPrivateNote` threaded through `ExpertBookingsScreen`, `ExpertBookingsContent`, `ExpertBookingsTabBody` and `ExpertBookingsList`, and `onPrivateNote = { navigator.navigate(it) }` in `ExpertBookingsRoute`. The tracer verify (`ExpertBookingsScreenTest` plus `ktlintCheck`) passed end to end before expansion: tracer verified end-to-end, expanding.
- Task 2: `ExpertUpcomingCard.onPrivateNote` and `PrivateNoteZone` after both action layouts (Join beside the icon Message, and Join plus the Message/Reschedule pair); Join, Message and Reschedule layouts untouched. `netEarningsText` stays in `ExpertDisplay.kt` (plan 16.4-04).
- Tests: decoding (preview, absent, redacted `toString`) and `aSavedNoteShowsOnReturn` for both lists, proving D-08 with no new refresh code.
- Wider check: every `screens.expertmode.upcomingbookings.*` test (ScreenTest 43, ViewModelTest 28, BucketsTest 9) and `ExpertBookingsApiTest` (11) pass, 0 failures; `ktlintCheck` and `scripts/check-design-rules.sh` pass.

## Deliberate iOS deviations

- D-08: iOS can show a stale preview on return; Android relies on the existing quiet reload on `onScreenShown`, tested rather than re-implemented.
- A blank (whitespace-only) preview counts as absent on both cards, stricter than the iOS `isEmpty`.

## Note for plan 16.4-09

The `expertBookingNoteEntry` registration lands in 16.4-09. Until then, tapping a note control navigates to a key with no entry. This only matters between plans inside one phase run and never ships.

## Deviations from Plan

None of substance; the plan was executed as written. Two process notes:

- **Card-body tap (flagged by the dispatch prompt):** plan 16.4-05 hit a test that tapped a card's centre and landed on a nested control. Here the existing `cardTapOpensSummary` and `pastCardOpensSummary` tests (centre tap) still passed after the note controls were added, so they were left untouched. The new tests that must hit the card body (`pastNoteActionOpensTheNoteNotTheSummary`, `upcomingNoteZoneOpensTheNoteNotTheSummary`) use a `clickCardBody()` helper that taps the top padding, as 16.4-05 did. No product code changed.
- **No separate RED commit:** the plan is `type: execute`, and the RED state for Task 1 is a compile failure (the new tests reference `privateNotePreview` and `onPrivateNote`). Tests and implementation were committed together per task, as in plan 16.4-02. The decoding and return-reload tests added in Task 2 pass against Task 1's DTO by design (no main code for D-08).
- **Taller viewports:** the every-status past test and the two-card layout test use `w411dp-h2400dp`, and the 200% font tests use `w360dp-h2400dp`, because Robolectric's default viewport cannot display five cards or a card at doubled font.

**Total deviations:** 0 auto-fixed. **Impact:** none.
