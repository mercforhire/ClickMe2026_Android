# Phase 16.4 Plan 06: My Note on client Booking Summary and the real shell registration Summary

**The client's full private note (or the prompt) now shows on Booking Summary in the iOS position, and one `clientBookingNoteEntry` registration in `HomeClientShell` makes the note editor open from My Bookings, chat and push, with the note key copying the summary's stack origin.**

## Performance

- **Duration:** about 25 min
- **Tasks:** 2 (1 tracer, 1 auto, both `tdd="true"`)
- **Files:** 11 modified, 0 created

## Accomplishments

- `ClientBookingDetail` decodes `private_note`; the display model maps a blank note to null; both `toString` implementations omit the note (T-16.4-19).
- `MyNoteCard` sits after the Feedback block and before Book Again on every status. A real `BookingSummaryViewModel` over the fake API carries the note to the card, and the tap produces a key matching the loaded booking.
- `noteKey()` copies the summary's origin. The shell test proves both the Bookings stack ("note b2 Default") and a Chats-origin summary ("note b2 Chats"), and that system back returns to the summary on its own stack (T-16.4-20).
- `HomeClientShell` registers `clientBookingNoteEntry(navigator) { key, onBack -> ClientBookingNoteRoute(key, onBack) }`, closing the gap 16.4-05 left: its card controls navigated to a key that had no entry in production. The new `onOpenNote` slot parameter pushes on the same stack as the summary.
- `aSavedNoteShowsOnReturn` passes with no refresh code: the first load has no note, the handler then returns "Call back", and `onScreenHidden()` plus `refreshQuietly()` leave `Loaded` throughout and the note shown.
