# Phase 12 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Requirements CHAT-01..05, SAFE-01..04. Six surfaces:
> 1. Conversations list (the Chats tab root in both the client and the expert shell).
> 2. Chat thread (new route, pushed on the Chats tab stack).
> 3. Report & Block screen (new route, pushed from the thread's top bar menu).
> 4. Expert Profile additions: Message button, the top bar menu, the Block confirm dialog, the Report sheet.
> 5. Message entry points on existing booking, request and call screens (placement and states only).
> 6. The in-call Chat control (enable the Phase 9 placeholder).
>
> Out of scope and must not appear in the UI: image or file attachments, a photo button in the composer, push notifications and the notifications list (Phase 13), an unread badge on the Chats tab icon (D-16), a "Blocked" label on list rows (D-19), paging past 50 conversations, an offline send queue (D-02), "Clear history", Report/Block from Client Profile (DEF-3), Report/Block on Request Decision or the expert Booking Summary (D-11), message editing or deleting on the server, reactions, replies, link previews.
>
> **Baseline.** `01-UI-SPEC.md` (tokens, shapes, motion, shell), `08-UI-SPEC.md` (booking cards, tinted rows, result snackbars, destructive rule A5, `AuthErrorDialog`), `09-UI-SPEC.md` (`JoinCallButton`, call controls, call pill) and `11-UI-SPEC.md` (expert surfaces, radio-row groups, multi-line field, bottom sheets, counters, footer bar) are locked and not restated. Dark only, Material 3, Nunito 400 / 600, exactly four text sizes (12 / 16 / 20 / 28 sp), `Spacing` xs..xxxl, `ClickMeShapes`, `MaterialTheme.extras`. Every value below is an existing token unless marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/ClickMe2026/Views/Screens/Chat/**` and `Client Mode/Expert Profile/**`. The per-screen iOS palettes (`ChattingBrand`, `ChatConversationsBrand`, `ReportChatBrand`) collapse to the Phase 1 tokens (FND-02); iOS glow shadows and glowing-bubble art become plain Material surfaces. Layout is ported and adapted to Material 3, not pixel-matched. Copy is taken from iOS unless marked "(Android)" or "(spec)". Where `CHAT-UNBLOCK.md` or `USER-REPORTING.md` disagree with iOS, the backend spec wins.
>
> **Source of decisions.** CONTEXT D-01..D-19 for behavior and pinned copy. This spec fills the "Claude's Discretion" areas: bubble, failed-state, banner, system-event and Report & Block visuals; Message button placement per screen; the list time label; extra copy. The run was non-interactive, so every assumption is recorded in "Assumptions and Open Items". No RESEARCH.md exists; the backend send limit was read directly from `backend-reference/src/schemas/chat.schema.js` (see Interaction Contract, D-04).

## Spacing Scale

Phase 1 tokens, all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

| Token | Used for in this phase |
|-------|------------------------|
| xs (4dp) | Gap between a bubble and its status line; gap between consecutive bubbles of the same sender; name to preview line on a row; badge vertical padding; icon-to-text gap in banners |
| sm (8dp) | Avatar to bubble gap; gap between bubble groups of different senders (`sm` + `xs`); composer vertical padding; icon-to-text gap in rows; gap between sheet fields; gap between menu icon and label |
| md (16dp) | Screen horizontal padding; gap between conversation rows; card inner padding; gap between the two Report & Block cards; composer horizontal padding; sheet horizontal padding; gap between sheet and dialog buttons; system-event row inner padding |
| lg (24dp) | Top padding under the app bar on the list and Report & Block; gap between blocks inside the Report & Block cards; sheet bottom padding above the navigation inset; empty-state vertical padding |
| xl (32dp) | Bottom scroll padding plus the navigation inset on Report & Block and the list; `EmptyState` icon-to-heading gap (inherited) |
| xxl (48dp) | Minimum touch target: menu items, text actions, icon buttons, the send button, the Load earlier button, the clear-search button |
| xxxl (64dp) | Not used as spacing |

Exceptions (component dimensions and platform minimums, not layout spacing):
- Controls (Message buttons in text form, Block, Unblock, Submit report, sheet buttons, dialog buttons) use `heightIn(min = 56.dp)`. Icon-only Message buttons are 56dp squares in card action rows and 48dp elsewhere.
- Avatars: 56dp on conversation rows, 32dp beside incoming bubbles and in the thread top bar title, 72dp on the existing Request Decision header (unchanged).
- Presence dot: 12dp circle (`primary`) with a 2dp `surface` ring, at the bottom-end of the 56dp avatar. Decorative; the row description says "online".
- Bubble: `widthIn(max = 320.dp)` and at most 75% of the list width (whichever is smaller); padding `md` horizontal and `sm` vertical. Corner radii use shape tokens only (see Shapes).
- Composer text field: `heightIn(min = 48.dp)`, grows to 5 lines (`maxLines = 5`). Send button: 48dp circle touch target (glyph 24dp).
- Unread badge: `widthIn(min = 24.dp)`, `heightIn(min = 24.dp)`, `CircleShape`, text `labelMedium`, horizontal padding `xs` + `xs`.
- System-event icon tile: 40dp, `small` shape, glyph 24dp.
- Jump-to-latest button: `SmallFloatingActionButton` (40dp visible, 48dp touch target), `md` from the end edge and `md` above the composer.
- Details fields: `heightIn(min = 112.dp)`. Stroke widths 1dp resting, 2dp focused. Skeleton shapes copy the real dimensions above.

## Color

Dark only. All colors come from the Phase 1 ColorScheme and `MaterialTheme.extras`. No hex literal appears in this phase's code (`scripts/check-design-rules.sh`). Tinted fills are `color.copy(alpha = ...)` of a scheme color.

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `#131313` `surface` | Every screen background, app bars, the composer bar, the Message-list background, the Report & Block background |
| Secondary (30%) | `#1C1B1B` `surfaceContainerLow`, `#201F1F` `surfaceContainer`, `#2A2A2A` `surfaceContainerHigh` | Conversation rows, system-event rows, Report & Block cards, the blocked banner: `surfaceContainerLow`, `medium`, 1dp `outlineVariant`. Incoming bubbles: `surfaceContainerHigh`. Composer field, search field, details field: `surfaceContainer`. Sheets: `surfaceContainerLow`. Dialogs and menus: `surfaceContainerHigh` |
| Accent (10%) | `#44F697` `primary` | See reserved list |
| Warning | `#FFB833` `tertiary` | The composer character counter once the cap is reached and the `PersonOff` icon on the "This user is unavailable." banner. Text stays `onSurface` or `onSurfaceMuted` |
| Destructive | `#FFB4AB` `colorScheme.error` | The "Block" button (text, icon, 1dp border at 50% alpha) and the "Block" confirm button in the dialog; the failed-message state (the `ErrorOutline` glyph, the "Not sent. Tap to retry" line, the 1dp bubble border at 50% alpha) and the "Delete" menu item. Nothing else. Report is not destructive. Never a filled error button (Phase 8 rule A5) |

Accent reserved for (and nothing else in this phase):
1. Fill of the user's own message bubbles (text `onPrimary`, contrast 9.3:1) and fill of the enabled Send button (glyph `onPrimary`). This is deliberate iOS parity (`myBubble` is the brand green); it is the largest accent area in the app and is accepted for chat.
2. Fill of the single primary CTA per surface: "Submit report" (Report & Block card and Report sheet), "Send a message" (empty thread), "Retry" in every error state (via `EmptyStateAction`), the existing Join Call button.
3. The unread badge fill (text `onPrimary`) and the presence dot on the conversation avatar.
4. The "Read" word in a read receipt (`· Read`), and the system-event icon and 12% tile fill for accepted/positive events (Booking Confirmed, Booking Rescheduled, Session Completed).
5. The selected `RadioButton` in the report reason groups.
6. Focused border and cursor of the composer, search field and details fields; every `CircularProgressIndicator`, including the pull-to-refresh indicator and the spinner in the Message button.
7. The check glyph and the "Report sent" confirmation row on the submitted Report card; the "Unblock" success is a snackbar and uses no accent.

Neutral, deliberately not accent: the Message buttons (outlined `onSurface`, 1dp `outlineVariant`), incoming bubbles, conversation names, previews, times, the date separators, the typing strip, the blocked and unavailable banners, the "Unblock" tonal button, menu items, chevrons (`onSurfaceVariant`).

Failed bubble ("dimmed", D-01): fill is `primary` at 40% alpha (about `#266D48` over `surface`) with text in `onSurface` (not `onPrimary`), computed contrast about 4.8:1, plus the 1dp `error` 50% border. It is not dimmed by lowering whole-bubble alpha (that fails contrast, the Phase 11 expired-card rule). Status is never conveyed by color alone: the failed state carries the word "Not sent. Tap to retry" and the glyph; read carries the word "Read"; unread carries the numeric badge; online carries "online" in the row description.

## Navigation and Structure

```
Client shell (HomeClientShell) and Expert shell (HomeExpertShell): per-tab Navigation 3 back stacks.
Detail entries use BottomBar.hidden().

Chats tab stack:   ChatsRoot  (existing placeholder, now the Conversations list; bottom bar visible)
   |- row tap          >  ChatThreadKey(threadId, peerName, peerAvatarUrl)
   |      |- system-event row tap (event has a booking id)
   |      |       terminal booking  >  client: BookingSummaryKey  |  expert: ExpertBookingSummaryKey   (pushed on the Chats stack)
   |      |       active booking    >  client: UpcomingBookingKey |  expert: ExpertBookingSummaryKey
   |      |- top bar menu "View profile" (client mode, peer is an expert)  >  ExpertProfileKey   (pushed on the Chats stack)
   |      |- top bar menu "Block or report" / "Unblock or report" / "Report"  >  ChatReportBlockKey(threadId, peerName)
   |             |- Block success    >  pop ChatReportBlockKey and ChatThreadKey  (to ChatsRoot, snackbar)
   |             |- Unblock success  >  pop ChatReportBlockKey  (to the unblocked thread, snackbar)
   |             |- Report success   >  stay; the Report card shows its submitted state

Any other tab (Explore, Bookings, Dashboard, Profile ...):
   Message tap (initiateChat OK)  >  Navigator.navigateInTab(ChatsRoot, ChatThreadKey(...))
   The originating tab keeps its own back stack. Back from the thread goes to ChatsRoot, not to the originating tab.

Sheets and dialogs (not routes): Report sheet, Block confirm dialog, error dialogs, thread/profile overflow menus.
```

Keys are `@Serializable NavKey` data classes registered next to the existing keys in both shells. The thread key carries name and avatar so the top bar renders before the first fetch (as iOS `peerName`, `peerAvatarURL`). If a thread of the same `threadId` is already on the Chats stack top, a repeat Message tap reuses it rather than stacking another copy.

| Screen | App bar | Back behavior |
|---|---|---|
| Conversations | Tab-root `TopAppBar`, title "Messages", avatar action (`TopBarAvatarButton`), no back | Selects the home tab (Phase 1 rule) |
| Chat thread | `AuthTopAppBar`, back arrow, title slot = `Avatar` 32dp + `sm` + peer name (`titleMedium`, `maxLines = 1`), action `MoreVert` (hidden when the menu would be empty, see below) | Pops to Conversations, which reloads quietly |
| Report & Block | `AuthTopAppBar`, back arrow, title "Report & block" | Pops to the thread. While Block, Unblock or Submit is in flight Back (arrow, system, predictive) is ignored and the arrow is disabled (`backEnabled = false`, Phase 8 convention) |

**Thread overflow menu (`ThreadOverflowMenu`)** — `DropdownMenu`, each item `heightIn(min = 48.dp)` with a 24dp leading icon:

| Item | Shown when | Action |
|---|---|---|
| "View profile" (`Person`) | Client mode, the peer user id is known (first peer message) and the peer is an expert | Push the Expert Profile. Disabled (38% alpha) until the peer id is known. Hidden in expert mode (Client Profile is DEF-3) |
| "Block or report" (`Block`) | Thread not blocked | Push `ChatReportBlockKey` |
| "Unblock or report" (`Block`) | Thread blocked and `blocked_by_me` | Push `ChatReportBlockKey` |
| "Report" (`Flag`) | Thread blocked and not `blocked_by_me` | Push `ChatReportBlockKey` |

On a self-thread (partner id equals own id) the Block and Report items are hidden; if "View profile" is also hidden the `MoreVert` action is not rendered. Menu item text is `onSurface` (not `error`); the screen it opens holds the destructive confirmation.

Insets: tab-root content handles the bottom bar via the shell. Pushed screens use `safeDrawing`; the composer sits above the IME with `imePadding()` and above the navigation inset; scroll content uses `contentPadding` with `xl` bottom plus the navigation-bar inset on Conversations and Report & Block. Sheet fields use `imePadding()`.

## Screen Specifications

### 1. Conversations list (CHAT-01, D-16 to D-19)

Tab root `ChatsRoot`, identical in both shells. Background `surface`. `GET /chats?page=1&limit=50`, no paging. Refresh: pull-to-refresh (`PullToRefreshBox`), a quiet reload when the tab is shown again and on return from a thread, and realtime updates: `message.new` moves the thread to the top and updates its preview, time and unread count; `user.status` toggles the presence dot.

| State | Rendering |
|---|---|
| Loading (first load) | `ConversationsSkeleton`: a 56dp search-field bar, then five row blocks copying the real row (56dp circle, a 160 x 20 bar, a 72 x 16 end bar, a 240 x 16 bar). `md` between. "Loading" description |
| Failed | `EmptyState` (`ErrorOutline`): heading "Couldn't load conversations", body = server message, else "Check your connection and try again.", action "Retry" (filled). Inside a `verticalScroll` `fillMaxSize` column so pull-to-refresh works |
| Empty (no threads) | The search field is hidden. `EmptyState` (`Forum`): heading "No messages yet"; body (client) "Message an expert from their profile or one of your bookings to start a conversation."; body (expert) "Message a client from a booking or request to start a conversation."; no action. Pull-to-refresh still works |
| Loaded | Search field plus rows below |
| No search results | `EmptyState` (`Search`): heading "No conversations found", body "Try a different name or keyword." The search field stays |
| Quiet reload | The rows update in place and never return to the skeleton. A failed pull-to-refresh shows the snackbar "Couldn't refresh. Check your connection and try again."; a failed return or resume reload shows nothing |
| Arrival snackbar | "Blocked {name}" after a block from a thread (D-09), shown once by the screen's `SnackbarHost` |

Layout: `md` horizontal padding, `md` top, the search field first, `md` below it, then a `LazyColumn` with `md` between rows and `xl` plus navigation inset at the bottom.

**Search field (`ConversationsSearchField`, D-18).** `TextField`, `surfaceContainer` fill, `extraLarge` shape, 1dp `outlineVariant` resting border, 2dp `primary` focused, `heightIn(min = 56.dp)`. Leading `Search` 24dp `onSurfaceVariant`, placeholder "Search" (`bodyLarge`, `onSurfaceMuted`), single line, IME action Search (dismisses the keyboard). Trailing `Close` 24dp in a 48dp `IconButton` (`contentDescription` "Clear search") when the text is non-empty. Filters the loaded threads locally, case-insensitive, by name or last message. Test tag `chats_search`.

**Conversation row (`ConversationRow`).** `surfaceContainerLow`, `medium`, 1dp `outlineVariant`, `md` padding; the whole row is one `Role.Button` (`onClickLabel` "Open conversation"). `Row`, `md` between: `ConversationAvatar` 56dp (presence dot when online), then a column (weight 1, `xs` between lines):

| Block | Spec |
|---|---|
| Line 1 | Name `titleMedium` `onSurface` (`maxLines = 1`, ellipsis, weight 1) and the time label (`bodySmall`, `onSurfaceMuted`, end). Name and time sit in a `FlowRow` so the time wraps below at large font scales |
| Line 2 | Last message `bodyLarge`, `maxLines = 2`, ellipsis; `onSurfaceVariant` for read rows, `onSurface` for rows with unread messages. The `UnreadBadge` (`primary` fill, `labelMedium` `onPrimary`, "99+" above 99) sits at the end of this line (`sm` from the text). Empty last message shows nothing on this line |

Time label (`relativeTimeLabel`, device locale): today short time ("10:23 AM" / "10:23"), yesterday "Yesterday", otherwise a short month-day ("Oct 24"). Empty when there is no last message. Semantics: one merged node, "{name}, {unread count} unread, {last message}, {time}, online". Presence dot is a visual repeat of "online". Rows sort by last message time, newest first, with the realtime move-to-top animation (`animateItem()`). Blocked threads look identical to any other row (D-19).

### 2. Chat thread (CHAT-02 to CHAT-04, D-01 to D-04)

Route `ChatThreadKey`. Background `surface`. Layout: app bar, message list (weight 1), typing strip, composer or banner. Messages: `GET /chats/{id}/messages` page size 30, newest at the bottom. Opening lands at the newest message with no animation.

| State | Rendering |
|---|---|
| Loading | `ChatThreadSkeleton`: five bubble-shaped blocks alternating start and end (widths 200, 140, 240, 120, 180 x 40dp), `md` between. "Loading" description. The composer is shown but disabled |
| Failed | `EmptyState` (`ErrorOutline`): heading "Couldn't load messages", body = server message, else "Check your connection and try again.", action "Retry". The composer is shown but disabled |
| Empty thread | `ChatEmptyThread` = `EmptyState` (`ChatBubbleOutline`): heading "Start your conversation here.", body "Say hello!", action "Send a message" (filled `primary`; focuses the composer and opens the keyboard). The composer is enabled |
| Loaded | Messages, system events, date separators |
| Quiet reload | Pull-to-refresh on the list reloads page 1 and merges by server id and `client_msg_id` (never duplicates, never drops local sending/failed bubbles). A failed pull-to-refresh shows the snackbar "Couldn't refresh. Check your connection and try again." |

List: `LazyColumn`, `md` horizontal padding, `md` vertical contentPadding. Rows: consecutive messages from the same sender within the same minute group (`xs` between); a different sender or a gap adds `sm`. Banner and the composer are outside the list.

**Load earlier (`LoadEarlierButton`).** First item of the list when more pages exist: a centered `TextButton`, `heightIn(min = 48.dp)`, `ArrowUpward` 16dp + `xs` + "Load earlier" (`labelLarge`, `onSurfaceVariant`). While loading it shows a 16dp spinner and "Loading…" and is disabled. A failure is silent and the button stays tappable. Prepending preserves the scroll position (the user keeps reading where they were).

**Date separator (`DateSeparator`).** Centered text ("Today", "Yesterday", otherwise a medium date), `labelMedium`, `onSurfaceMuted`, `md` vertical padding; inserted when the local calendar day changes between adjacent items. A heading-less, non-focusable decorative row except for its text.

## Interaction Contract (summary)

| Rule | Behavior |
|---|---|
| Optimistic send (D-01) | The bubble appears at once as "Sending…". Network error or 5xx → failed state, tap retries with the same `client_msg_id`, long-press Delete removes it locally. No offline queue (D-02) |
| Reconciliation | The ack replaces the optimistic bubble by `client_msg_id`; a `message.new` echo or a page load with the same server id or `client_msg_id` never creates a duplicate; own echoes are ignored |
| Blocked send (D-03) | 403 `THREAD_BLOCKED` / `RECIPIENT_UNAVAILABLE` → bubble removed, text back in the composer, `GET /chats` re-fetch, banner in place of the composer |
| Cap (D-04) | 10000 characters (`chat.schema.js` `content` max). Counter from 9000; paste truncates |
| Typing | `typing.start` on the first non-empty edit after a quiet period, debounced `typing.stop` after 3 s idle, a send also stops. Incoming typing auto-clears after the safety timeout. Own events ignored |
| Read receipts | `message.read` emitted for visible unread peer messages on load and on each incoming `message.new` while the thread is open. An incoming `message.read` flips my bubbles to "Read" |
| Refresh | Conversations: pull-to-refresh, quiet reload when the tab is shown again and on return from a thread. Thread: pull-to-refresh. Only the first load shows a skeleton |
| Search | Local filter over the loaded 50 threads by name or last message, case-insensitive |
| Entry (D-13) | Every Message tap switches to the Chats tab and pushes the thread; the originating tab keeps its stack; Back lands on Conversations |
| Message busy (D-15) | One `initiateChat` at a time per control; spinner; repeat taps ignored; error in `AuthErrorDialog`; `404` → "This user is unavailable." |
| Block from profile (D-05) | Confirm dialog → `initiateChat` → `block`; stays on the profile with a snackbar |
| Block from chat (D-08, D-09) | Confirm dialog → `block` → pop Report & Block and the thread → Conversations snackbar |
| Unblock (D-08, D-09) | No confirm; success returns to the unblocked thread; `NOT_BLOCKER` latches the button off |
| Report (D-06, D-10) | Reason required, details optional (1000, trimmed). Profile sheet closes with a snackbar; the chat Report card shows its submitted state |
| In flight | While Block, Unblock or Submit runs, Back, sheet dismissal and repeat taps are ignored |
| Self targets | Message / Report / Block hidden on your own profile; Report and Block hidden on a self-thread |
| Rotation / process death | Entry-scoped Hilt ViewModels with `SavedStateHandle`: composer text, search text, selected report reason and details, sheet open flag. Sending/failed bubbles are not restored after process death (D-02) |

## Accessibility Contract

- Touch targets at least 48dp: menu items, the send button, search clear, Load earlier, icon-form Message buttons (56dp in cards), dialog and sheet buttons, radio rows (56dp), the failed bubble (whole bubble plus status line).
- Rows and bubbles expose one merged node: conversation row "{name}, {n} unread, {last message}, {time}, online"; bubble "{You|name}, {text}, {time or Sending or Not sent}, {Read}"; system event "{title}, {subtitle}" with `Role.Button` only when tappable.
- A failed bubble is a `Role.Button` with `onClickLabel` "Retry sending" and custom actions "Retry sending" and "Delete message" (the long-press menu is not the only path). Failed, sending, read and unread states each carry a word or number; nothing is color-only.
- New incoming messages while the thread is open are announced through a polite live region on the newest incoming bubble. The typing strip is not a live region. The blocked banner and the "Thanks, we'll review this." row are polite live regions.
- Headings (`heading()`): "Messages", the Block and Report card headlines, sheet and dialog titles, "Start your conversation here." and the error and empty headings.
- Reason groups use `selectableGroup` with `Role.RadioButton`, read once ("Spam, selected"); the required marker on the label is announced.
- In-flight buttons expose `stateDescription` ("Opening chat", "Blocking", "Unblocking", "Submitting"); disabled "Submit report" explains itself ("Choose a reason first").
- Sheets: TalkBack focus lands on the title; the IME never covers the focused field (`imePadding()`); the composer moves above the IME.
- Dialogs trap focus; the Block dialog's default focus is "Cancel".
- 200% font scale: conversation name and time wrap via `FlowRow`; bubbles, banner and cards grow (`heightIn`, never fixed); the Report sheet buttons and the Request Decision footer stack; the thread top bar title truncates. Check the Conversations list, a thread with a failed bubble, the blocked banner, Report & Block, the Report sheet and the Request Decision footer.
- Reduce motion: with the animator scale at 0 every transition and the scroll-to-bottom is instant.
- Contrast: `onPrimary` on `primary` 9.3:1 (own bubbles, badge, Send); `onSurface` on `surfaceContainerHigh` above 11:1 (incoming bubbles); `onSurface` on the failed fill about 4.8:1; `error` on `surface` above 8:1; `onSurfaceMuted` on `surface` at least 5.9:1.
- A full TalkBack pass is Phase 15 (POL-04).

## Assumptions and Open Items (for the planner and checker)

The run was non-interactive, so these were decided without the user:

- **A1. Conversation row unread badge.** D-16 says each row keeps its unread badge, but the iOS `ChatConversationRow` does not render one (the model carries `unreadCount`). The spec renders a `primary` pill and shows unread previews in `onSurface`.
- **A2. Date separators** ("Today", "Yesterday", date) are added; iOS defines the `.timestamp` item but the thread never produces it.
- **A3. "Jump to latest" button** is added so incoming messages never yank the user out of history.
- **A4. "View profile" in the thread menu** is shown in client mode only (the peer is an expert) and hidden in expert mode (Client Profile is DEF-3). If the planner cannot resolve the peer role, hide it.
- **A5. Block card copy** deliberately drops the iOS claims about hidden profile and bookings (the backend block is send-only). Report card copy drops "Your report is anonymous" (not backed by a spec).
- **A6. Other 4xx on send** (not 403 blocked/unavailable) removes the bubble, restores the text and shows `AuthErrorDialog`; CONTEXT only pins the network/5xx and 403 cases.
- **A7. Message placement:** stacked under Book Session on the profile; icon form beside Join on cards; in the Request Decision footer as a leading icon button with a stacked fallback. D-14 left icon versus text to discretion.
- **A8. Past cards have no Message control** (the Summary does). Dashboard Today's Sessions cards have none.
- **A9. Peer name fallback** "Chat" when the key's name is blank.
- **A10. Unblock needs no confirmation**; Delete failed message needs none.
- **A11. The unavailable banner is session-local** (not persisted).
- **A12. Own bubbles use `primary`** (iOS parity). This makes accent the dominant area in a busy thread; if the checker objects, the fallback is `primaryContainer` with `onPrimaryContainer`, but contrast must be re-verified.

Open items:

1. **Navigation keys from the thread** (system-event taps, "View profile") are pushed on the Chats stack. `ExpertBookingSummaryKey` and `AvailabilityKey` carry an `origin`; the planner must add a Chats origin (or no-origin variant) so entry-scoped ViewModels stay distinct.
2. **Thread repository scope** (per-thread or app-scoped) and realtime fan-out to the list and the open thread are planner decisions (CONTEXT discretion); the visuals do not change.
3. **Peer role detection** for A4 and the Conversations empty body (mode comes from the shell, so the body copy is safe).
4. **Backend reads:** `GET /chats` item shape (partner, `is_blocked`, `blocked_by_me`, last message, `unread_count`) and the messages payload (event rows with `event_data`) are to be confirmed by the planner against `backend-reference/src/controllers/chats.controller.js`; the visuals assume the iOS `ChatThreadItem` / `ChatMessageItem` fields.
5. **iOS follow-ups** (from CONTEXT, not Android work): the iOS send waits for the ack; iOS report reasons are labels that do not match the enum.
6. **Manual checks deferred** (project preference): two-way chat with an iOS client on the Samsung SM-A075F, typing and read indicators, block from a thread and from the profile, unblock by the blocker, a send into a blocked thread from the other client, report rate limit (10/hour), 200% font scale on the screens listed in Accessibility.
