- GET /me/payment-methods -> {data:{payment_methods:[{id, brand, last4, exp_month, exp_year, is_default}]}}
- POST /bookings/payment-intent {expert_id, topic_id, selected_date, time_slot, duration_minutes, booking_attempt_id} -> BARE body {payment_intent_id, client_secret, customer_id, ephemeral_key, total_amount, currency, summary}
- POST /bookings/confirm {payment_intent_id, expert_id, topic_id, start_time, meeting_type:"in_app_voice", stripe_payment_method_id}; schema is .strict(): sending booking_attempt_id or any extra key returns 422
  -> 201 {status, data:{booking_id, status:"pending_approval", ...}}
  -> 402 {status:"error", code:"PAYMENT_REQUIRES_ACTION", detail:{client_secret, stripe_account}}
- POST /bookings/:id/join -> {data:{booking_id, connection_type, agora_config:{rtc_token, uid, channel_name}, ...}}

Stripe SDK 23.24.0 (RESEARCH Pattern 8, Pitfall 6):
- PaymentConfiguration.init(applicationContext, publishableKey)
- Compose PaymentSheet: remember { PaymentSheet.Builder(resultCallback) }.build()  (rememberPaymentSheet is deprecated)
- sheet.presentWithSetupIntent(clientSecret, PaymentSheet.Configuration.Builder("ClickMe").customer(PaymentSheet.CustomerConfiguration(id, ephemeralKeySecret)).build())
- PaymentSheetResult: Completed | Canceled | Failed(error)
- rememberPaymentLauncher(publishableKey, stripeAccountId, callback); launcher.handleNextActionForPaymentIntent(clientSecret); PaymentResult: Completed | Canceled | Failed(throwable)
- stripeAccountId is a remember key: set the challenge in state and call handleNextAction from LaunchedEffect(challenge), never from the same click handler.
