<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| App -> /auth/refresh | The rotating refresh token crosses here; reuse revokes the session |
| Backend responses -> session state | 401/403 bodies decide whether the user stays logged in |
| Device storage -> tokens | Tokens at rest on the device |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-18 | Spoofing / Repudiation | Concurrent refresh (refresh-token replay triggers server reuse detection) | mitigate | Mutex single-flight plus sent-vs-current token comparison; rotated pair saved with commit() inside the lock before the retry; 12-way concurrency and late-401 tests |
| T-02-19 | Information disclosure | Bearer sent to public endpoints | mitigate | AuthHeaderInterceptor strips Authorization on the 5 public paths (needAuthToken on encodedPath); refresh runs on a bare client; tests assert no header |
| T-02-20 | Elevation of privilege | Suspended user keeps a working session | mitigate | SuspensionInterceptor clears tokens synchronously on any 403 ACCOUNT_SUSPENDED (including /auth/login) and emits Suspended |
| T-02-21 | Denial of service | Over-eager logout on transient failures or business 401s | mitigate | Only refresh-401, missing refresh token, or a token-coded 401 after a successful refresh clear the session (D-03, resolved Q3); 5xx/429/IO and code-less 401s keep tokens; tests cover each |
| T-02-22 | Information disclosure | Tokens at rest | mitigate | EncryptedSharedPreferences (Keystore-backed AES256) behind SecureTokenStore; Phase 1 backup rules exclude all app data; in-memory cache avoids repeated decrypts |
| T-02-23 | Denial of service | ESP corruption after restore/OS update crashing launch | mitigate | Guarded init deletes the prefs file and Keystore alias, retries once, else falls back to memory (logged-out next launch) |
</threat_model>
