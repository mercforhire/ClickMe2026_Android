<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Backend auth state -> local session | Server decisions (401/403) drive whether local credentials survive |
| Local storage across accounts | One user's cached data must not leak to the next login |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-37 | Information disclosure | Residual data after logout or suspension | mitigate | One logout path clears tokens, DataStore (profile, mode, onboarding) and in-memory state under NonCancellable; profile refresh writes only while a session exists; tests cover both |
| T-02-38 | Elevation of privilege | Suspended user stays in the app | mitigate | Suspended event -> wasSuspended + logout (FND-06); restore returns Login when suspension cleared the tokens |
| T-02-39 | Spoofing | Offline/cached-path launch with a server-revoked token | accept | D-01 locked: transient failures keep the session; any real authed request then goes through the Authenticator, whose rejection clears the session and routes to Login |
| T-02-40 | Denial of service | Session event delivery | mitigate | UNDISPATCHED subscription in init before any request; transport clears tokens synchronously so state is correct even if an event were missed |
| T-02-41 | Tampering | Debug token invalidation in release | mitigate | debugForceTokenRefresh only reachable from BuildConfig.DEBUG-gated UI (plan 02-13); it only degrades the caller's own session |
</threat_model>
