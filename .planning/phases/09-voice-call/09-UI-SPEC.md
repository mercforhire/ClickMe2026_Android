# Phase 9 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Requirements CALL-01 to CALL-08. Seven surfaces:
> 1. The expanded call (`MeetingCallScreen`), in-app voice variant.
> 2. The expanded call, external Skype/Zoom variant (D-05).
> 3. The minimized call pill (`MeetingCallPill`).
> 4. The ongoing-call notification (D-10).
> 5. Root-level dialogs: join error, mic permission (rationale and permanently denied), "Can't do that during a call" guard, time-limit cutoff.
> 6. The live Join button on the three Join sites (D-01 to D-03), plus the "Starting now" badge on Today's Sessions.
> 7. The guard call sites (D-13): which actions show the guard dialog. No new visuals beyond surface 5.
>
> Out of scope and must not appear in the UI: an enabled in-call Chat (Phase 12, D-11), Expert-side Join entry points (Phase 11), `Call/Ready` / `ReadyToStartCallView`, a "Rejoin your call?" prompt after process death (D-15), a Mute action on the notification (D-10), an audio-route picker (Bluetooth / earpiece list), video.
>
> **Baseline.** `01-UI-SPEC.md` (tokens, shapes, motion, shell), `08-UI-SPEC.md` (tinted rows, status pills, dialog conventions, `AuthErrorDialog`, `PressScaleButton`, Join placeholder pattern, destructive rule A5) are locked and not restated. Dark only, Material 3, Nunito 400 / 600, exactly four text sizes (12 / 16 / 20 / 28 sp), `Spacing` xs..xxxl, `ClickMeShapes`, `MaterialTheme.extras`. Every value below is an existing token unless marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/ClickMe2026/Views/Screens/Call/Calling/**` (`MeetingCallView`, `Subviews/*`, `CallOverlayHost`, `ExternalMeetingProvider`) and `Managers/CallCenter.swift`. Copy is taken from iOS verbatim unless marked "(Android)". The iOS `MeetingCallBrand` palette collapses to Phase 1 tokens (FND-02): brand green becomes `primary`, orange becomes `tertiary`, the hard-coded end red becomes `extras.destructive`, glow shadows are dropped (the ambient radial glow behind the avatar stays, as on Phase 5 hero). Layout is ported, not pixel-matched.
>
> **Source of decisions.** CONTEXT D-01..D-16 and the "ported as-is" block for behavior. This spec fills the "Claude's Discretion" areas: mic-permission dialogs and copy, notification channel and content, pill visuals and animation, exact external-variant status lines, timer cadence for the UI. The session had no live questions, so every assumption is recorded in "Assumptions and Open Items".

## Spacing Scale

Phase 1 tokens, all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

| Token | Used for in this phase |
|-------|------------------------|
| xs (4dp) | Gap between the range line and the timer (iOS 10); gap between a control circle and its label; badge vertical padding |
| sm (8dp) | Gap between name and topic; gap between icon and text in buttons and the banner; gap between the Open and Copy Link buttons (iOS 12); overlap of the two avatars in the pair; gap between the avatar and its ring |
| md (16dp) | Gap between controls in the control row; screen horizontal padding on the call (iOS 24 for banner and buttons, `lg` is used there, see below); pill horizontal padding; pill-to-screen-edge margin; gap between the pill avatar and its timer; dialog field gaps |
| lg (24dp) | Horizontal margin of the banner, the End Call button, the external link buttons and the status text (iOS 24 and 32); gap between the info block and the controls; bottom margin under End Call (plus nav-bar inset) |
| xl (32dp) | Gap between avatar block and info block (iOS 40); gap between controls and End Call (iOS 52); top margin when no banner |
| xxl (48dp) | Minimum touch target (pill height, link buttons) |
| xxxl (64dp) | Not used as spacing (see control circle) |

Exceptions (component dimensions and platform minimums, not layout spacing):
- Hero avatar 160dp (iOS 210) in a 4dp `primary` ring at 8dp (`sm`) gap, so the ring outer diameter is 184dp (at pulse peak 1.06 x, about 195dp). Pair avatars 96dp (iOS 130) each in a 3dp ring at `xs` gap, overlapped by `sm`. External hero avatar 96dp in a 3dp ring (iOS 140). Pill avatar 32dp (iOS 24) in a 2dp `primary` ring. Ring stroke widths are hairlines/decoration, not spacing.
- Control circle 64dp (iOS 76). Four circles plus three `md` gaps are 304dp wide, which fits a 320dp-wide screen with `md` side margins. Each control is a column (circle plus label) that is `weight(1f)` in the row and at least 48dp wide, so labels may wrap at 200% font scale.
- End Call and Open in {provider}: `heightIn(min = 56.dp)` (iOS 58 and 52). Copy Link: `heightIn(min = 48.dp)` (iOS 44). Pill: `heightIn(min = 48.dp)`.
- Pill bottom offset: navigation-bar inset plus 96dp (bottom bar 80dp plus `md`; same as iOS 96). On screens where the bottom bar is hidden the pill sits 80dp higher than needed, which is accepted.
- Notification: system layout, no custom dimensions.
- Dialogs: platform `AlertDialog` metrics.

## Typography

Inherited: exactly four sizes (12, 16, 20, 28 sp), two weights (400, 600), line height 1.5 body and 1.2 headings. Nothing in this phase sets `fontSize`; every `Text` takes an M3 slot. The timer uses tabular numerals via `fontFeatureSettings = "tnum"` on the existing style (iOS used a monospaced font); this is not a new size or weight. iOS bold 34 / rounded becomes the 28sp Display slot.

| Role | Size | Weight | Line height | Used for here |
|------|------|--------|-------------|---------------|
| Body | 16sp | 400 | 24sp (1.5) | Status line ("Connected"), dialog messages, external status text |
| Label | 12sp | 600 | 16sp (1.33) | Ending-soon banner text, "{M:SS} left" chip, "Starting now" badge, "Link copied" chip (`labelMedium`). Control labels, scheduled range line and notification-style captions use 12sp regular (`bodySmall`) |
| Heading | 20sp | 600 | 24sp (1.2) | Timer (`titleLarge` + `tnum`), dialog titles. Pill timer and the topic line use 16sp / 600 (`titleMedium`) |
| Display | 28sp | 600 | 34sp (1.2) | Peer name on the expanded call (`headlineLarge`, centered, `maxLines = 2`) |

`titleMedium` (16 / 600): topic line on the call (`onSurfaceVariant`, `maxLines = 2`, centered), pill timer (`tnum`). `labelLarge` (16 / 600): every button label and dialog button.

## Color

Dark only. All colors come from the Phase 1 ColorScheme and `MaterialTheme.extras`. No hex literal appears in this phase's code (`scripts/check-design-rules.sh`). Tinted fills are `color.copy(alpha = ...)` of a scheme color.

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `#131313` `surface` | The expanded call background (with a top radial wash from `surfaceContainerLow` to `surface`, radius about 600dp, replacing the iOS `vignetteTop`), the screen the pill floats over |
| Secondary (30%) | `#2A2A2A` `surfaceContainerHigh` and `#1C1B1B` `surfaceContainerLow` | Control circles, the pill, the "Link copied" chip: `surfaceContainerHigh`. Control circle resting border 1dp `outlineVariant`. Dialogs: `surfaceContainerHigh` |
| Accent (10%) | `#44F697` `primary` | See reserved list |
| Warning | `#FFB833` `tertiary` | Ending-soon banner (10% fill, 1dp 45% border, hourglass icon), the timer text and the "{M:SS} left" chip (12% fill, 1dp 45% border) in the last 300 seconds and after the scheduled end, the pill timer in the same two states (Android). Text on tinted surfaces stays `onSurface`; the timer and chip labels take `tertiary` (contrast about 9.5:1 on `surface`) |
| Destructive | `#FF4D4D` `extras.destructive` with `#1A0000` `extras.onDestructive` | The End Call / End Session button fill and its content only (about 6.5:1). Nothing else on the call surface. See the exception note below |

**Destructive exception (deliberate).** Phase 8 forbids a filled error button and uses `colorScheme.error` outlined for confirm-style actions in cards and dialogs. End Call is different: it is the single primary action of a full-screen call surface, has no confirmation step (hanging up does not end the session, rejoin works for the whole window, CALL-END-SEMANTICS), and the universal call convention is a filled red hang-up button. It therefore uses the existing filled pair `extras.destructive` / `extras.onDestructive`, which passes 4.5:1 as a container with `onDestructive` content. Phase 7 rule A5 (destructive text on `surfaceContainerHigh`) is not triggered because no text is drawn in `destructive` on a dark surface. The checker should treat this as an approved exception.

Accent reserved for (and nothing else in this phase):
1. Fill of the enabled **Join Call** button on the three Join sites (replaces the disabled placeholder). When disabled it keeps the disabled container, not the accent.
2. Fill of **Open in {provider}** on the external variant (the single primary action of that screen).
3. The ring around the peer avatar(s) and the pill avatar, and the ambient radial glow behind the hero (alpha 0.10 to 0.28 pulse).
4. The active (on) state of Mute and Speaker: icon tint plus 1dp border at 50% alpha. A control that is off uses `onSurface` icon and the `outlineVariant` border.
5. The pill's 1dp border (55% alpha).
6. The "Link copied" chip border (60% alpha) and the "Starting now" badge fill on Today's Sessions.
7. Every `CircularProgressIndicator` (End Call in-flight uses `onDestructive` instead, see below).
8. The confirm text button of the mic rationale and mic denied dialogs ("Continue" and "Open Settings"), the single primary action of each dialog (Phase 8 convention).

Neutral, deliberately not accent: the timer outside the last stretch (`onSurfaceVariant`), the status line, the Minimize and Chat controls, Copy Link (outlined, `onSurface`), the notification (system styling; small icon is the app icon).

Contrast: `onPrimary` on `primary` 9.3:1 (Join, Open, badge); `onDestructive` on `destructive` about 6.5:1; `tertiary` on `surface` about 9.5:1; `onSurfaceVariant` on `surface` above 9:1; `onSurfaceMuted` on `surface` 5.9:1+. A disabled Chat control (38% content alpha) is exempt but stays legible. State is never conveyed by color alone: the status line is words, banners carry a word and an icon, toggles carry a `stateDescription` and an icon swap.

## Motion

Phase 1 durations. All of it follows the system animator duration scale; with animations off (scale 0) the pulses are static at their resting values and every transition is instant.

| Interaction | Duration / easing |
|---|---|
| Expand the call (pill to full screen, or first start) | The full-screen layer slides up from the bottom and fades in, 300 ms (`Motion.PUSH_POP_DURATION_MS`, `pushPopEasing`). iOS `fullScreenCover` slides up |
| Minimize (button, system Back, predictive back, Open on the external variant) | The reverse: slides down and fades out, 300 ms. Predictive back drives the gesture progress |
| Pill appear / disappear | Scale 0.6 to 1 plus fade, 200 ms (`Motion.STRENGTH_METER_VISIBILITY_MS`), as iOS `.scale(0.6)` |
| Ring pulse while Connecting or Waiting for peer | Scale 1.0 to 1.06, 900 ms, reverse, infinite (new `Motion.CALL_RING_PULSE_MS = 900`). Static (scale 1.0) when Connected or Call Ended |
| Ambient glow | Alpha 0.10 to 0.28, 2200 ms, reverse, infinite (new `Motion.CALL_GLOW_PULSE_MS = 2200`) |
| Single avatar to pair (status becomes Connected) and back | 300 ms cross-fade of the hero (iOS .35 s) |
| Status line, timer color, banner and chip appearing or disappearing | 200 ms fade and expand (`AnimatedVisibility`); text color change 150 ms (`Motion.CONTROL_STATE_DURATION_MS`) |
| Control press | Phase 1 press scale 0.96, 120 ms (`PressScaleButton`). iOS 0.92 spring is not ported |
| Mute / Speaker toggle | 150 ms icon cross-fade and border color change |
| "Link copied" chip | Fade in 200 ms, hold 1500 ms, fade out 200 ms (iOS) |
| Layer switch between variants (post-join override of the initial hint) | 200 ms cross-fade (iOS .25 s) |

## Navigation and Structure

```
ClickMeApp
 |- AppRoute switch (Login / SignupSetup / ClientHome / ExpertHome)   <- content, unchanged
 |- CallOverlayHost  (sibling above the switch, composed last)
      |- Expanded layer: full screen, handles its own insets (D-08)
      |- Minimized pill: bottom end, above the bottom bar
      |- Root dialogs: join error, mic rationale, mic denied, guard, cutoff
```

- The overlay is not a nav destination and not an Activity. It survives tab changes, the Client/Expert mode switch and navigation (`CallCenter` is the owner, D-08).
- **While expanded:** the layer consumes all pointer input (a `pointerInput` that swallows taps) and the content below is hidden from accessibility (`Modifier.semantics { invisibleToUser() }` on the `AppRoute` subtree) so TalkBack cannot reach it. The status bar and navigation bar are drawn edge to edge over `surface`; content uses `WindowInsets.safeDrawing`, the End Call group uses `navigationBars`. The layer applies its own insets because the root has none.
- **System Back and predictive back (D-09):** `BackHandler(enabled = expanded)` minimizes to the pill. It never ends the call. When only the pill is showing, Back behaves as it does on the screen below.
- **Notification tap (D-10):** `MainActivity` handles the intent, calls `CallCenter.expand()`, and the layer slides in. A cold start from the notification (task was swiped, D-14) shows the Splash/auth route first and the expanded call layers over it once the call state exists; if no call is live (process death, D-15) the tap just opens the app.
- **Tapping the pill** expands. **Minimize** control and **Open** (external) minimize.
- **Hang up** (button or notification action): `CallCenter.endCall()` leaves the channel, `POST /end`, tears down. The layer animates out. No confirmation dialog (iOS has none; rejoin is allowed for the whole window).
- **Orientation:** the app is portrait-first. In landscape or a short window the same single column scrolls (see "Layout" below); no separate landscape layout.

## Screen Specifications

### 1. Expanded call, in-app voice (CALL-01, CALL-03 to CALL-08, D-08, D-09, D-11)

Background: `surface` with the top radial wash. Content is a min-height-fill scroll column: a `BoxWithConstraints` whose child `Column` has `verticalScroll` and `heightIn(min = maxHeight)`, so `Spacer(weight(1f))` can center and bottom-anchor on a normal phone while the whole column scrolls at 200% font scale or in landscape.

Vertical order, top to bottom (all centered, horizontal padding `lg` where noted):

| Block | Spec |
|---|---|
| Safe-area top | `WindowInsets.safeDrawing` top, then `md` |
| Ending-soon banner (conditional) | Shown when `0 < remaining <= 300 s` or `remaining <= 0` (past the scheduled end). Tinted row (Phase 8): `lg` horizontal margin, `md` horizontal and `sm` vertical padding, `Outlined.HourglassEmpty` 20dp `tertiary`, `sm`, text `labelMedium` `onSurface`, wraps to 3 lines. Copy: final stretch "Session ending soon — please start wrapping up."; past end "Scheduled time complete — you can wrap up when ready." Enters with `AnimatedVisibility` (expand and fade from the top). `liveRegion = Polite` |
| `weight(1f)` spacer | Centers the hero and info block between banner and controls |
| Hero (`MeetingCallAvatar`) | Container 320 x 260dp max (`widthIn(max = 320.dp)`, height wraps the ring). Ambient glow: a radial gradient of `primary` (alpha 0.10 to 0.28, 2200 ms pulse) filling a 360dp circle behind, no blur layer. **Connecting / Waiting for peer / Ended:** one `Avatar` 160dp of the peer inside the 4dp ring (scale pulse while Connecting or Waiting). **Connected:** two avatars side by side, mine on the left and the peer on the right, each 96dp in a 3dp `primary` ring (alpha 0.55 gradient to 1.0 is dropped; solid `primary`), overlapped by `sm`. My avatar is the signed-in user's `avatarUrl` (UserManager). Avatars are decorative (`contentDescription = null`) |
| `xl` | Gap |
| Info (`MeetingCallInfo`) | Column, `lg` horizontal padding, `sm` between lines: peer name `headlineLarge` `onSurface` (`heading()`); topic `titleMedium` `onSurfaceVariant` (hidden when blank); scheduled range "{start} – {end}" `bodySmall` `onSurfaceMuted` (device time format; hidden when unknown); `xs`; timer `titleLarge` + `tnum` (`onSurfaceVariant`, `tertiary` in the last 300 s and after the scheduled end); "{M:SS} left" chip when in the last 300 s (`labelMedium` `tertiary`, `CircleShape`, 12% fill, 1dp 45% border, `md` horizontal and `xs` vertical padding); status line `bodyLarge` `onSurfaceVariant` |
| `lg` | Gap |
| Controls (`MeetingCallControls`) | Row, `lg` horizontal padding, `Arrangement.spacedBy(md)`, four columns each `weight(1f)`: Minimize, Chat, Mute, Speaker. Circle 64dp `surfaceContainerHigh`, 1dp border (`outlineVariant` resting; `primary` 50% when on), icon 24dp, then `xs`, label `bodySmall` `onSurfaceVariant` centered (wraps). See control table |
| `xl` | Gap |
| End Call (`MeetingCallEndButton`) | `lg` horizontal padding, full width, `heightIn(min = 56.dp)`, `CircleShape`, fill `extras.destructive`, content `extras.onDestructive`: `Filled.CallEnd` 24dp, `sm`, "End Call" `labelLarge`. In flight (`isEndingCall`): label and icon replaced by a 24dp `onDestructive` spinner, `stateDescription` "Ending call", taps ignored, container stays full opacity (iOS dims to 60%; a dimmed destructive button is harder to read) |
| Safe-area bottom | `navigationBars` inset plus `lg` |

**Status line and call status (ported state machine).**

| `callStatus` | Status line | Hero | Timer |
|---|---|---|---|
| `connecting` | "Connecting..." | single, ring pulses | Runs (anchored to the scheduled start, see below) |
| `waitingForPeer` | "Waiting for other person..." | single, ring pulses | Runs |
| `active` | "Connected" | pair, ring static | Runs |
| `ended` | "Call Ended" | single, ring static | Frozen |

The timer is anchored to the scheduled start, not to the local join (CONTEXT). Before the start it reads "Starts in M:SS" (`%d:%02d`); after it reads "MM:SS" (`%02d:%02d`, minutes grow past 59 without an hours field, e.g. "75:12"). Ticker for the UI: once per second while the layer or pill is visible. The cutoff at `scheduledEnd + 3600 s` is enforced by `CallCenter`, not by this ticker.

**Controls table.**

| Control | Icon (off / on) | Label | Behavior | Semantics |
|---|---|---|---|---|
| Minimize | `KeyboardArrowDown` | "Minimize" | `CallCenter.minimize()` | Button; `contentDescription` "Minimize call" (iOS) |
| Chat | `Forum` | "Chat" | Disabled until Phase 12 (D-11): 38% content alpha, no ripple, not focus-skipped | Button, `enabled = false`, `stateDescription` "Available soon" (Android) |
| Mute | `Mic` / `MicOff` (on = muted) | "Mute" | Toggles the mic. Off at call start | `Role.Switch`-like toggle: `stateDescription` "Muted" / "Unmuted" |
| Speaker | `VolumeDown` / `VolumeUp` (on = speaker) | "Speaker" | Toggles speakerphone. **On by default** (CONTEXT, spike `CallService` profile) | Toggle: `stateDescription` "On" / "Off" |

The Speaker toggle only switches speaker and earpiece. If a Bluetooth or wired headset is the active route, the system route wins and the toggle still reflects the user's last choice (implementation detail, no route picker UI this phase).

**Open behavior.** Tap Open: fire `confirm-connection` (`skype_zoom`) once (only the first tap), `ACTION_VIEW` with the join URL; if no app resolves it, `CustomTabLauncher`; then minimize to the pill (D-05, D-06). The open request runs even if the first attempt fails to resolve (the Custom Tab fallback covers it). Copy Link puts the URL on the clipboard and shows the chip.

**Provider detection.** `ExternalMeetingProvider.detect(uri)` ports the iOS scheme, host and substring rules (`skype:`, `zoommtg:`/`zoomus:`, `msteams:`; hosts containing `skype.com`, `zoom.us`/`zoom.com`, `meet.google.com`, `teams.microsoft.com`/`teams.live.com`; substring fallback). Unknown yields "Open Meeting" and the `OpenInNew` icon so the app never mislabels a link.

**External status text (before / after Open).**

| State | Copy |
|---|---|
| Not yet opened | "Open the meeting link to start the session." |
| Opened, scheduled end known | "Meeting in progress. The session is scheduled to end at {time}. Tap End Session when you're done." (Android; iOS promises it "will end automatically at {time}", which is not true because the call is soft-ended and only cut off 3600 s later) |
| Opened, end unknown | "Meeting in progress — tap End Session when you're done, or leave the session to end automatically." (iOS) |

### 4. Ongoing-call notification (CALL-03, D-10)

### 5. Root dialogs (D-04, D-12, CALL-02, CALL-07)

All are Material `AlertDialog`s hosted by `CallOverlayHost` (composed above the layer and the pill), shape `extraLarge`, container `surfaceContainerHigh`, title `titleLarge` `onSurface`, message `bodyLarge` `onSurfaceVariant`, buttons `TextButton` `labelLarge`. One dialog at a time; a later one waits for the earlier one to be dismissed (queue, first in first shown). Single-button error dialogs reuse `AuthErrorDialog` with "OK".

| Dialog | Trigger | Title | Message | Buttons |
|---|---|---|---|---|
| Join error | `CallCenter.joinError` (D-04): server refusal, network, missing `agora_config` or `join_url` | "Couldn't join session" (iOS) | Server `message`, else per case: "This booking isn't set up for in-app voice." / "This booking is missing a meeting link. Contact the other party." / network "Check your connection and try again." / unmapped "Something went wrong. Please try again." | "OK". The call layer is already torn down when it shows; no `/end` |
| Mic rationale | Mic permission was denied once before (`shouldShowRequestPermissionRationale`) and the user taps Join again for an in-app call. (Android) | "Continue" (`primary`, launches the system prompt) / "Not now" (`onSurface`, tears down the call container, no `/end`) |

Notes:
- The mic and notification permissions are requested in one `RequestMultiplePermissions` launcher hosted by `CallOverlayHost` (API 33+: `RECORD_AUDIO` and `POST_NOTIFICATIONS`; below 33: `RECORD_AUDIO` only). The request happens after `POST /join` returns an `agora_config` and before the service starts (a microphone foreground service cannot start without the grant). A notification denial alone never blocks the call. The external variant never asks for either permission.
- A mic denial (rationale "Not now", permanent denial, or a denied system prompt) tears down the call container with no `/end` and no join-error dialog (separate signal, as iOS `micPermissionDenied`).
- `{action}` strings come from each call site (surface 7), lower case and verb-first, for example "switch modes", "log out", "add a payment method", "cancel this booking".

### 7. Guard call sites (D-12, D-13)

`CallCenter.attempt` / `attemptModifyBooking` returns `false` and shows the guard dialog when a call is live; the caller aborts. No new visuals at the sites.

| Site | Call | `{action}` string |
|---|---|---|
| Switch mode (`ModeSwitchScreen`) | `attempt` | "switch modes" |
| Log out (wherever the action lives) | `attempt` | "log out" |
| Add a payment method (Phase 7 Payment Methods) | `attempt` | "add a payment method" |
| Client Cancel on a booking (Upcoming Details "Cancel Booking" and the Cancel flow entry) | `attemptModifyBooking(bookingId, ...)` | "cancel this booking" |

## Interaction Contract (summary)

| Rule | Behavior |
|---|---|
| Starting | Join tap opens the expanded layer at once in "Connecting..." and runs `POST /join`; a failure tears the layer down and shows the join-error dialog (no `/end`) |
| One call at a time | A second `startCall` shows the guard message; no second engine, no second layer |
| Minimize / expand | Button, Back, predictive back and Open minimize; the pill and the notification tap expand. The call, timer and audio are unaffected |
| Hang up | Only End Call / End Session / the notification action end the call. Peer leaving or `call.ended` for the same booking only moves to "Waiting for other person..." |
| Backgrounding | The in-app call keeps running in a `microphone` foreground service with the screen off and after a task swipe (D-14). The external variant has no service (D-07) |
| Process death | No restore (D-15); the booking stays live, the user taps Join again |
| Not optimistic | Mute and Speaker flip after the engine call returns; End shows its spinner until `/end` completes or fails (a failed `/end` is logged and the call still tears down locally, never branching on the response, CALL-END-SEMANTICS) |
| Audio interruptions | An incoming phone call or other audio focus loss is handled by Agora and the OS defaults. No extra UI; the channel stays connected and audio resumes when focus returns |
| Timer | Anchored to the scheduled start; amber with "{M:SS} left" when `0 < remaining <= 300 s`; the "scheduled time complete" state past `scheduledEnd` (call continues); force-end once at `scheduledEnd + 3600 s` with the time-limit dialog |
| Rotation / configuration change | `CallCenter` is app-scoped, so the layer and pill recompose over the same state; permission dialogs hold their flags in `rememberSaveable` |
| Realtime | `call.ended` is filtered by booking id; events for other bookings are ignored |

## Accessibility Contract

- Touch targets at least 48dp: pill (48 minimum height), control circles (64), Copy Link (48), End Call and Open (56), Join (56), dialog buttons.
- On expand, TalkBack focus lands on the peer name (`heading()`); the status line, the ending-soon banner, the "Link copied" chip and the external status text are `liveRegion = Polite`, so state changes are announced once ("Connected", "Waiting for other person...").
- The ticking timer is not a live region. It carries a spoken description built from the value: "Starts in 1 minute 30 seconds" / "2 minutes 5 seconds elapsed"; it updates only when TalkBack focuses it, never every second.
- While the layer is expanded, content below is `invisibleToUser`; the layer is a single traversal group ordered: banner, name, topic, range, timer, status, controls (Minimize, Chat, Mute, Speaker), End Call.
- Toggles expose `stateDescription` and an icon change (not color alone). The disabled Chat control is announced as disabled with "Available soon".
- The pill is one merged button with a static label; the avatar and ring are decorative.
- Hang up has no confirmation; the End Call button spinner exposes `stateDescription` "Ending call".
- The notification action is a standard action button, reachable from the shade and lock screen.
- 200% font scale: name wraps (2 lines), topic wraps (2 lines), banner wraps (3 lines), control labels wrap and the row grows, the column scrolls (min-height-fill pattern); End Call and Open keep `heightIn(min)`, never a fixed height. Check the Connected pair state, the final-stretch banner, and the external variant with the status text at 200%.
- Reduce motion: with the system animator scale at 0 the ring and glow pulses are static and slides are instant.
- A full TalkBack pass is Phase 15 (POL-04).

## Assumptions and Open Items (for the planner and checker)

- **A1. End Call is a filled `extras.destructive` button.** This is the one exception to the Phase 8 "never a filled error button" rule (see Color). - **A2. Join on the same booking while its call is live** shows the D-12 guard message ("You're already on a call...") exactly as CONTEXT says. A friendlier alternative is to expand the existing call instead; not adopted because D-12 is explicit. Raise it if device testing finds it awkward.
- **A3. Join Call under the Skype/Zoom link row on Upcoming Details** goes beyond iOS (D-01 wires the card). Drop it by deleting the added button; the My Bookings and Today's Sessions Join cover the external flow.
- **A4. Mic UX.** First request goes straight to the system prompt; the rationale dialog appears only after a prior denial; the permanent-denial dialog offers Open Settings. POST_NOTIFICATIONS is asked together with the mic on API 33+ and never blocks the call. Alternative: ask notifications separately on first app use.
- **A5. Pill offset** is a fixed 96dp above the navigation bar. It does not track the bottom bar visibility; on screens with a hidden bar it floats 80dp higher than needed.
- **A6. Time-limit dialog** ("Call ended") is Android-only copy; if the checker prefers no new copy, the call can end silently and the user sees the layer disappear.
- **A7. Notification channel** importance `LOW` (silent, not heads-up). The notification chronometer switches from "Starts at {time}" at the scheduled start.
- **A8. Timer UI cadence** is 1 s while visible; the notification chronometer is system-driven, so no per-second notification updates. The Join clock flow is 30 s (D-03 discretion).
- **A9. Control and avatar sizes** (64dp circles; 160 / 96 / 32dp avatars) are chosen for 320dp-wide screens and the existing Avatar size allow list.
- **A10. External status line** change from the iOS promise of an automatic end.
