# Phase 5 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Four surfaces: the Explore home (replaces `PlaceholderTabContent` in `ExploreRoot`), the All Categories sheet, Expert Profile (pushed inside the Explore tab's back stack), and the stub booking screen that Book Session pushes. Requirements: DISC-01, DISC-02, DISC-03 plus the DEF-7 slice pulled in by CONTEXT D-06. Out of scope and must not appear in the UI: the Search tab and every "See all" link (DEF-2), the favorites heart, the reviews "See all" (DEF-3), Message and the "…" Report/Block menu (Phase 12), the booking flow itself (Phase 6), Today's Sessions interactions (Phases 8 and 9).
>
> **Baseline.** `01-UI-SPEC.md` (tokens, shapes, motion, shell) and `04-UI-SPEC.md` (picker sheet pattern, accent rules) are locked and are not restated. Dark only, Material 3, Nunito 400/600, exactly four text sizes (12 / 16 / 20 / 28 sp), `Spacing` xs..xxxl, `ClickMeShapes`, `MaterialTheme.extras`. Every value below is an existing token unless it is marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/ClickMe2026/Views/Screens/Client Mode/Explore/**` and `Expert Profile/**`. Copy is taken from iOS verbatim unless marked "(Android)". Layout is ported, not pixel-matched. `ExploreBrand`, `ExpertProfileBrand` and `AllCategoriesBrand` palettes collapse to the Phase 1 tokens (FND-02).
>
> **Locked upstream decisions used here.** CONTEXT D-01..D-21. Where this spec adds detail inside a "Claude's Discretion" area it says so.

## Spacing Scale

Phase 1 tokens, all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

| Token | Used for in this phase |
|-------|------------------------|
| xs (4dp) | Gap between stars, between a card's name and its sub-line, tag chip vertical padding, gap between the rating number and the review count |
| sm (8dp) | Gap between tag chips (both axes), icon-to-label inside buttons and rows, gap between avatar and name on Featured cards, gap between stat cells, section heading to its subtitle |
| md (16dp) | Screen horizontal padding on Explore and Profile (card screens use `md`, forms used `lg`); card inner padding; gap between cards in a vertical list; gap between a section heading and its content; gap between category and featured cards in their rows |
| lg (24dp) | Gap between Profile sections; gap from Book Session to the cards; sheet footer padding; top padding under the Explore app bar |
| xl (32dp) | Gap between Explore sections (iOS 32); bottom scroll padding on both screens; empty and error state icon-to-text spacing (inherited) |
| xxl (48dp) | Minimum touch target |
| xxxl (64dp) | Empty-state top offset on the "unavailable" screen (inherited) |

Exceptions (component dimensions and platform minimums, not layout spacing):
- Touch targets stay at least 48dp: "View all", "Retry", "Clear filter", the sheet close button, every card (all cards are taller than 48dp).
- Controls (`PressScaleButton` CTAs) use `heightIn(min = 56.dp)`.
- Category card: 112dp wide, `heightIn(min = 104.dp)`; icon badge 40dp x 40dp.
- Featured Topic card: 224dp x 176dp (iOS 220 x 176, snapped to the grid); left accent bar 4dp wide.
- Expert card image: `Avatar` 96dp (iOS 96).
- Today's Sessions avatar: `Avatar` 40dp (iOS 42). Featured card avatar: `Avatar` 32dp (iOS 22; 32 is the smallest allowed `Avatar` size).
- Profile hero: `Avatar` 160dp inside a 2dp `primary` ring with a 4dp gap; glow layer behind it.
- Stars: 16dp on cards and review rows, 20dp in the hero.
- Stroke widths 1dp resting, 2dp selected or active (hairlines).
- Skeleton shapes copy the real component dimensions above.

## Typography

Inherited: exactly four sizes (12, 16, 20, 28 sp), two weights (400, 600), line height 1.5 body and 1.2 headings. Nothing in this phase sets `fontSize`; every `Text` takes an M3 slot.

| Role | Size | Weight | Line height | Used for here |
|------|------|--------|-------------|---------------|
| Body | 16sp | 400 | 24sp (1.5) | Hero subtitle, session topic and time, expert title, About text, topic descriptions, review comments, empty and error text, search field text (`bodyLarge`) |
| Label | 12sp | 600 | 16sp (1.33) | Category card names, rating number on cards (`labelMedium`). Regular-weight 12sp captions (featured card expert name, tag chips, stat labels, review count on cards) use `bodySmall` |
| Heading | 20sp | 600 | 24sp (1.2) | Section headings ("Today's Sessions" and so on), sheet title, About / Expertise / Topics / Recent Reviews card headings when a heading level is needed, empty-state heading (`titleLarge`) |
| Display | 28sp | 600 | 34sp (1.2) | Explore hero "Find your next expert" and the profile hero name (`headlineLarge`) |

`titleMedium` (16sp / 600) is used for card titles (expert name, featured topic title, session expert name, review author, topic row title), stat values, the profile hero title line, and the price text. `labelLarge` (16sp / 600) is used for buttons and the "View all" link. The iOS 34pt hero is folded to 28sp per the Phase 1 folding rule.

## Color

Dark only. All colors come from the Phase 1 ColorScheme and `MaterialTheme.extras`. No hex literal appears in this phase's code.

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `#131313` `surface` | Both screens' backgrounds, TopAppBar container (Explore); profile app bar when scrolled uses `surfaceContainer` |
| Secondary (30%) | `#1C1B1B` `surfaceContainerLow` and `#201F1F` `surfaceContainer` | Session, category, featured topic, expert, About, Topics and Reviews cards and the stat cells on `surfaceContainerLow` with a 1dp `outlineVariant` border; Topics and Reviews card header strip on `surfaceContainer`; `ExpertTagChip` on `surfaceContainerHighest`; sheet and skeletons on `surfaceContainerHigh` |
| Accent (10%) | `#44F697` `primary` | See reserved list |
| Destructive | `#FF4D4D` `destructive` | Not used. This phase has no destructive action and no validation errors |
| Rating | `#FFB833` `tertiary` | Filled stars only (new use of the Phase 1 amber; not a warning here). iOS used yellow on cards and green on the profile; one amber for both keeps the accent budget |

Accent reserved for (and nothing else on these screens):
1. Fill of the single primary CTA: "Book Session" on Expert Profile and "Apply" in the All Categories sheet. "Join Call" on Today's Sessions cards is the same filled button but is always shown in the M3 disabled style in this phase (D-02), so it carries no accent.
2. Category icons (D-11): `primary` tint on the 40dp badge of every Trending Categories card and on every row in the All Categories sheet.
3. Selected state of a category: the 2dp `primary` border on a selected card and the check mark (`Outlined.Check`, 24dp) on selected sheet rows.
4. The 4dp left bar of each Featured Topic card.
5. The word "Free" wherever a topic price is shown (D-21).
6. The Profile hero ring (2dp) and the static `GreenGlowBlobLayer` behind it (D-14).
7. Focused border and cursor of the sheet search field (inherited from `ValidatedField`), and `CircularProgressIndicator` / pull-to-refresh indicator.

Text links ("View all", "Clear filter") use `onSurface`, `labelLarge`, underlined, not accent (Phase 1 rule). Secondary text uses `onSurfaceMuted` (`#999999`) or `onSurfaceVariant`. `onSurfaceFaint` is not used.

Surface tier rules follow Phase 1 exactly: Screen `surface`; Card (list) `surfaceContainerLow`; Resting container `surfaceContainer`; Raised `surfaceContainerHigh`; Highest `surfaceContainerHighest`. Selected category card fill is `secondaryContainer`.

## Motion

Phase 1 durations plus the following. All of it follows the system animator duration scale.

| Interaction | Duration / easing |
|---|---|
| Push / pop (Explore to Profile, Profile to Booking stub) | Phase 1: horizontal slide + fade, 300 ms, `FastOutSlowIn`; predictive back drives pops |
| Press feedback on tappable cards (expert, featured topic, category) | Phase 1 press scale 0.96, 120 ms (`Modifier.pressScale`) |
| Category card selected state | 200 ms `animateColorAsState` on fill and border |
| Skeleton pulse | 1000 ms alpha 0.5 to 1.0, reverse repeat (`SkeletonBlock`) |
| Skeleton to content | 150 ms cross-fade per section (`Crossfade` or `AnimatedContent`), no size jump beyond the content's own height |
| Section appear (Today's Sessions, Featured Topics, Profile sections arriving) | `AnimatedVisibility` 200 ms fade + vertical expand |
| Pull to refresh | M3 `PullToRefreshBox` defaults |
| All Categories sheet open / close | M3 `ModalBottomSheet` defaults |
| Profile hero glow | Static. No pulse (D-14) |

No Compose `blur`.

## Navigation and Structure

```
Explore tab back stack (ExploreRoot):
Explore home   (TopAppBar "Explore" + TopBarAvatarButton, bottom bar visible)
 ├─ All Categories  (ModalBottomSheet, not a route)
 └─ Expert Profile  (ExpertProfileKey)           (TopAppBar back arrow, bottom bar visible)
      └─ Book a Session stub  (BookingKey, the key Phase 6 will use)   (TopAppBar back arrow, bottom bar HIDDEN)
```

| Screen | App bar | Back behavior |
|---|---|---|
| Explore home | Existing `TopAppBar`, title "Explore" (`tab_explore`), `TopBarAvatarButton` action pushing Mode Switch (unchanged from Phase 4). Hero heading sits in the scrolling content below it, so the bar title stays short | Tab root: system Back selects the home tab rules from Phase 1 |
| Expert Profile | `TopAppBar` with `AutoMirrored.ArrowBack` (contentDescription "Back"), empty title, `containerColor = Transparent` over the hero; `scrolledContainerColor = surfaceContainer` once the list scrolls (`pinnedScrollBehavior`). No actions (D-05) | Pops to Explore |
| Booking stub | `TopAppBar` title "Book a Session" (`titleLarge`), back arrow; route metadata `BottomBar.hidden()` | Pops to Expert Profile |

Route keys (`@Serializable NavKey`, registered in the client shell `entryProvider`, D-04 / D-15):
- `ExpertProfileKey(expertId, name, title, imageUrl, rating: Double?, reviewCount: Int?, tags: List<String>)`. From an expert card all fields are known. From a Featured Topic card only `expertId`, `name` and `imageUrl` are set; `title` is empty, `rating` and `reviewCount` are null and `tags` is empty. Null means "unknown, show a skeleton", not zero.
- `BookingKey(expertId, expertName, expertTitle, expertImageUrl)` (iOS `MakeABooking` input). Phase 6 replaces the body, not the key.

Insets: every screen handles `safeDrawing`. Scrolling content uses `contentPadding` with `xl` bottom padding so the last card clears the bottom bar.

**States (D-16, D-17).**

Message: the server message, else "Check your connection and try again." Every Retry calls the same `/client/home` request (D-16). Today's Sessions is not affected by this error.

- Filter re-fetch in flight (chip tap or Apply): Recommended Experts shows its skeletons; Trending Categories and Featured Topics stay as they are.

## Accessibility Contract

- All tap targets at least 48dp (links, buttons, cards, sheet rows). Cards are merged semantic nodes with `Role.Button`, except Today's Sessions cards and Topic rows, which are plain text groups.
- Section headings carry `heading()` semantics (Explore sections, hero name, the profile card headings).
- Category cards expose a checked state (`Role.Checkbox`); sheet rows expose checked state and the accent check is paired with the selected semantic (color is not the only signal: the card border plus the checked state; the filled star plus the numeric rating).
- The disabled Join Call and "Not accepting bookings" controls announce as disabled with a reason (`stateDescription`).
- Stars are decorative; the numeric and text description is on the parent node.
- Skeleton groups announce "Loading" once; section content arriving is not live-announced except the Snackbar and the empty and error states (`liveRegion = Polite`).
- Contrast: `onSurfaceMuted` on `surfaceContainerLow` is at least 5.9:1; `tertiary` stars are decorative and accompanied by text; disabled controls are exempt by WCAG but keep legible text.
- Check both screens at 200% font scale: expert card name allows 2 lines, tags wrap in `FlowRow`, the session time row and stat cells wrap, category names stay at 2 lines and the card grows (`heightIn(min)`), the Featured card title stays at 2 lines inside the fixed 176dp height (reduce to the content's own height if a larger scale would clip: use `heightIn(min = 176.dp)`, not a fixed height). Nothing clips.
- The sheet is IME-aware; focus order is search, list, footer.
- Full TalkBack pass is Phase 15 (POL-04).
