Diagnosis (`.planning/debug/android-ios-peers-never-meet-after-profile-fix.md`, about 85-90%): the two peers are in DIFFERENT Agora channels whose names differ only by letter case.
- Backend `src/controllers/call.controller.js` `join` takes `bookingId = req.params.id` (the raw URL text) and passes it to `generateToken`, which uses it verbatim as the token channel and as the returned `channel_name`.
- iOS builds the URL with Swift `UUID.uuidString` (UPPERCASE). Android uses the lowercase id from JSON.
- Postgres matches uuids case-insensitively, so both requests authorize and both get a valid token for their own string. An Agora channel is its exact name. iOS to iOS and Android to Android each share one casing, which is why only the cross-platform pair fails.

**Locked decision (user): fix it on the SERVER, in the backend repo, not by changing Android's request casing.** The backend derives the channel from the canonical loaded row id. This also fixes iOS builds already in the field. 11-17's channel-profile change is correct and stays. No Android or iOS code changes in this plan.
