<objective>
Close gap G-11-1, a blocker. Every Android in-app voice join (client and expert, all six Join sites) shows "Couldn't join session". The cause is in `AgoraManager.createEngine()`. Inside the config-builder lambda, the bare name `context` resolves to the SDK getter `RtcEngineConfig.getContext()`, which still returns null, instead of AgoraManager's injected `@ApplicationContext`. `.applicationContext` then throws a NullPointerException, so the engine is never created and `join()` returns false. Device logcat (twice) and the compiled bytecode both prove this; see `.planning/debug/android-expert-cannot-join-session.md`.

This plan fixes the context, makes the failure diagnosable without logging sensitive data, treats a null `RtcEngine.create` as an explicit failure, and adds a JVM regression test that reproduces the bug before the fix and passes after it. The fix is small: one production file changes and one small helper file is added. CallCenter and the Join sites stay as they are.

Purpose: Phase 11 SC-3 (the PRD Week 5 checkpoint: the iOS client and the Android expert both join the call, D-14) and the Phase 9 call paths (CALL-01..CALL-08) cannot work on a device until the engine can be created.
Output: `AgoraEngineConfig.kt`, the fixed `AgoraManager.kt`, two Robolectric test classes, a green full gate, a VALIDATION row, and a STATE open item for the device re-check.
</objective>

**Agora SDK 4.6.4 facts (checked with javap on the cached AAR at planning time):**
- `io.agora.rtc2.RtcEngineConfig` has public fields `mContext`, `mAppId` and `mEventHandler`. It also has public getters `getContext()` and `getAppId()`, which Kotlin exposes as the synthetic properties `context` and `appId` on any config receiver. That collision is the bug.
- The config's no-arg constructor and `IRtcEngineEventHandler`'s constructor only assign fields. They are safe to call on the JVM under Robolectric.
- `RtcEngine.create(RtcEngineConfig)` returns null and does not throw when the config or its `mContext` is null, or when the native libraries fail to load. Kotlin sees its return type as a platform type.
- `RtcEngine` is abstract with hundreds of abstract methods and there is no mocking library on the test classpath. So tests stop at the factory boundary, and the `joinChannel` code log is checked by grep, not by a test.

**Kotlin name resolution:** a local variable or a function parameter wins over a member of an implicit receiver. A member of an inner implicit receiver (the config inside a scope function) wins over a property of the outer class. So read the application context into a local before any config receiver scope, and name the builder's parameter `appContext`.

**Test conventions:** these come from `BundledAssetsTest` and `RealtimeDebugLoggerTest`.
- Robolectric tests use `@RunWith(RobolectricTestRunner::class)` and `ApplicationProvider.getApplicationContext<Context>()`.
- Log lines are read with `ShadowLog.getLogsForTag(tag)` and their `type` and `msg`.
- `app/src/test/resources/robolectric.properties` pins sdk 35.
- Coroutine tests use `runTest` with `UnconfinedTestDispatcher(testScheduler)`.
