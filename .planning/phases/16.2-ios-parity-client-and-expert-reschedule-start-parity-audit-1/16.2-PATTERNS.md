## Pattern Assignments

### `RescheduleProposer.kt` (service, request-response with one retry)

**Analog:** `screens/clientmode/mybookings/RescheduleResponse.kt` lines 70-130 (`RescheduleResponder.accept`).

Core pattern to mirror (swap `acceptReschedule` for `reschedule`, `AcceptOutcome` for `ProposeOutcome`):
```kotlin
override suspend fun accept(bookingId: String): AcceptOutcome {
    try {
        bookings.acceptReschedule(bookingId)
        return AcceptOutcome.Accepted
    } catch (e: ApiException) {
        if (!e.isPaymentMethodRequired()) return AcceptOutcome.Failed(e.toRescheduleFailure())
    }
    val cards = try { paymentMethods.list() } catch (_: ApiException) { return AcceptOutcome.CardsUnavailable }
    val cardId = (cards.firstOrNull { it.isDefault } ?: cards.firstOrNull())?.id
        ?: return AcceptOutcome.NeedsPaymentMethod
    return try {
        bookings.acceptReschedule(bookingId, cardId)
        AcceptOutcome.Accepted
    } catch (e: ApiException) {
        if (e.isPaymentMethodRequired()) AcceptOutcome.CardUnusable else AcceptOutcome.Failed(e.toRescheduleFailure())
    }
}
private fun ApiException.isPaymentMethodRequired(): Boolean =
    this is ApiException.Http && code == ErrorCode.PaymentMethodRequired
```
Imports (RescheduleResponse.kt:1-16): `model.enums.ErrorCode`, `network.ApiException`, `screens.settings.paymentmethods.PaymentMethodsRepository`, `javax.inject.Inject`. Class shape: `class X @Inject constructor(private val bookings: ClientBookingsRepository, private val paymentMethods: PaymentMethodsRepository) : RescheduleProposing`. Per RESEARCH, `Failed` carries the raw `ApiException` (no copy in the proposer). Add `reschedule(id, body)` to `ClientBookingsRepository` next to `acceptReschedule`. Never log the `pm_` id or note.

The interface split (RescheduleResponse.kt:55-65, `RescheduleResponding`) is the model for `RescheduleProposing`; the expert implementation must have no card path.

```kotlin
fun accept() {
    if (_state.value.isSubmitting) return
    _state.update { it.copy(submitting = RescheduleSubmitting.Accepting) }
    scope.launch {
        try {
            when (val outcome = responder.accept(bookingId)) {
                AcceptOutcome.Accepted -> succeed(RescheduleNotice.Accepted)
                AcceptOutcome.NeedsPaymentMethod -> showDialog(RescheduleDialog.PaymentMethodNeeded)
                AcceptOutcome.CardUnusable -> showDialog(RescheduleDialog.CardUnusable)
                AcceptOutcome.CardsUnavailable ->
                    showDialog(RescheduleDialog.Error(FieldError.Res(R.string.reschedule_error_cards_unavailable)))
                is AcceptOutcome.Failed -> fail(outcome.failure)
            }
        } finally { _state.update { it.copy(submitting = RescheduleSubmitting.None) } }
    }
}
```

## Shared Patterns

### Money-safe single-flight and no logging
**Source:** `RescheduleResponse.kt:120-165`. **Apply to:** both pickers, both proposers. One `isSubmitting` guard spanning the whole proposer call; never log `pm_` id or note; never retry after returning from Payment Methods (D-08).

### Error dialogs
**Source:** `components/RescheduleResponseCard.kt:550-561` (`PaymentMethodDialog`, currently `private`; make internal or give `RescheduleOutcomeDialog` a message override). **Apply to:** client picker only. Use `AuthErrorDialog` directly for propose errors (title "Couldn't reschedule booking"); do not reuse accept mappers `toRescheduleFailure` / `toExpertRescheduleFailure`.

### Error-code mapping
**Source:** `mybookings/RescheduleErrors.kt` (reference shape only), `ErrorCode.PaymentMethodRequired` (`model/enums/ErrorCode.kt:59`). **Apply to:** `ProposeErrors.kt`: RESCHEDULE_OUTSIDE_AUTH_WINDOW fixed D-13 copy (terminal), RESCHEDULE_TOO_FAR_AHEAD and VALIDATION_ERROR clear slot and re-read clock, INVALID_PAYMENT_METHOD server text, else server message.

### Quiet refresh and snackbar on return
**Source:** `UpcomingBookingScreen.kt:138-142, 200`; `RefreshFailedSnackbarEffect` (Phase 15). **Apply to:** all four origins.

### Skeleton / ErrorState loading
**Source:** Phase 15 `SkeletonGroup`/`SkeletonBlock`, `ErrorState(onRetry)` used in `MakeABookingScreen.kt`. **Apply to:** both picker screens.
