## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug avoidance] Reload on hand-off uses `startLoad`, not `refreshQuietly()`**
- **Found during:** Task 3
- **Issue:** `refreshQuietly()` returns immediately while a current load is in flight, so a load that started before the send could be the one that lands, leaving the old state on screen instead of "Awaiting expert's response".
- **Fix:** The hand-off collector calls `startLoad(quiet = state is Loaded, flagFailure = true)`, which cancels and supersedes any older load and reuses the existing refresh-failed snackbar on failure. Same observable behavior the plan's tests specify (one extra call, state stays Loaded).
- **Files modified:** UpcomingBookingViewModel.kt
- **Commit:** 0517b3a4

**2. [Rule 3 - Test set-up] HomeShellsTest Task 1 cases push the picker with a captured navigator, then switch to the real button in Task 2**
- **Found during:** Task 1
- **Issue:** The fake `upcoming` slot has no `onReschedule` until Task 2, so Task 1's `rescheduleKeyHidesBottomBarAndPops` could not reach the picker from the details screen through a button.
- **Fix:** Task 1 pushed the key through the navigator the shell hands to `detailEntries`; Task 2 replaced that with the "upcoming reschedule" button and removed the captured navigator. Final tests go through the real slot callback.
- **Commits:** dfc4a809, 9dc420a9
