## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| app → backend | Authenticated PATCH `/client|expert/bookings/:id/reschedule`; strict zod schema rejects unknown keys | proposed time, timezone, user note; client retry only: saved-card `pm_` id (sensitive) |
| app → backend (money) | Client retry sends a saved-card `pm_` id so the server can keep or convert a payment authorization | `pm_` id (sensitive) |
| backend → app | Server JSON decoded into DTOs; error codes and messages pick the dialog | `actions.can_reschedule`, availability grid, reschedule response, error codes/text |
| backend → UI | Names, titles, topic, slot times and server error text rendered on cards, picker and dialogs | display text (untrusted) |
| client rules → backend authority | D-04 24 h gate, paid cap, current slot only decide what is offered; server re-checks every PATCH | none (UX only) |
| signed-in identity → availability call | Expert calendar always uses the signed-in expert's id, never the booking payload | user id |
| user → money timing | Disclosure dialog is the consent point before a move that converts a held card to a charge at T-24h | consent |
| navigation back stack | Keys carry only booking id, opener and origin; screens reload from the server | booking id (non-secret) |
| process death / SavedStateHandle | Selection and message persisted on device; secrets must not be | month, date, slot start, message, disclosure flag |
| session boundary | Hand-off singleton outlives screens; must not leak a pending notice into the next account | booking id |
| QA runbook | Phase 16 matrix rows for live-money tests | error codes, outcomes, brand + last 4 at most |
