# Phase 16.2 Plan 16: Label-fit stacking for ActionButtonPair (G-16.2-3) Summary

ActionButtonPair now stacks its two buttons when either one's single-line content is wider than its half of the row, so "Cancel Booking" no longer wraps on the details screens at 360 dp. The other three gate commands are green; the design-rules script fails on two pre-existing color literals from Phase 16.1 that this plan may not touch (see Blocker).

`commits: 2` counts the two task commits measured against the ledger at SUMMARY write time. The SUMMARY commit follows.

## Accomplishments

- **Task 1 (tracer):** the two-child path is a multi-content `Layout` (no BoxWithConstraints). Each slot is invoked with a plain `Modifier`. The measure block derives `half = (width - gap) / 2` and stacks when font scale >= 1.5, width is unbounded, width < 320 dp, or a slot's `maxIntrinsicWidth(Constraints.Infinity)` exceeds the half. Row: start measured at exactly the half, end at the remainder (absorbs the rounding pixel), placed with `placeRelative` so RTL mirrors. Stacked: both at the full width, start then gap then end. Min height is 0 and max height passes through, which matches the old BoxWithConstraints behavior. KDoc rewritten (rule, intrinsic-measurement contract, dropped the response-card claim). Single-child and both-null branches and the public signature are unchanged.
- **Task 2:** `rescheduleAndMessageFitOneLineAt360dp` in MyBookingsScreenTest (two cards) and ExpertBookingsScreenTest. UI-SPEC section 3 now states the 8 dp padding (`ActionButtonPairDefaults.ContentPadding`), the label-fit stacking sentence for Upcoming Booking Details, and "stacks under the same rule" on both card rows.
- **Task 3:** gate run, see below.
