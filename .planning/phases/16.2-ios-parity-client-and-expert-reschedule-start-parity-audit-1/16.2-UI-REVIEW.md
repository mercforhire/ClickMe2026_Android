## Top 3 Priority Fixes

1. **WARNING: no loading-state semantics in the picker's skeleton** — `LoadingContent` (`ReschedulePickerScreen.kt` ~l.168) sets only a polite liveRegion. It was not confirmed to pass the "Loading" description the spec requires; if not, TalkBack announces nothing meaningful. Fix: pass the `SkeletonGroup` description explicitly and add a test.
2. **WARNING: `FailedContent` is a non-scrolling centered `Box`** (`ReschedulePickerScreen.kt` ~l.188) — at 1.5x or larger font scale, or in landscape, Retry can clip off-screen. Fix: wrap it in `verticalScroll`.
3. **WARNING: `RescheduleActionButton` border does not change when disabled** — it uses a fixed `.border(1.dp, outline)`. The spec says the Expert Booking Summary button is disabled while an action runs, and the preview shows a disabled variant. A disabled button keeps a full-strength border and only the content color changes, so it reads as still tappable. Fix: dim the border to about 38% alpha when disabled.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- Strings in `strings_reschedule_start.xml` match the spec's Copywriting Contract, including iOS-verbatim titles ("Couldn't reschedule booking", "Submit Reschedule Request", "Message Text (optional)").
- WARNING: `reschedule_start_disclosure_message` always says "more than a few days out". The dialog also appends `reschedule_accept_dialog_charges_soon` when `chargesSoon` is true. That second case mixes two explanations (a far-future move, plus a charge soon) and can read as contradictory. Check the copy against the iOS alert.

### Pillar 2: Visuals (3/4)
- Block order follows the spec: booking card, calendar, Current banner, slots, message, Submit. Banner and Current chip match the spec.
- WARNING: the spec prescribed extracting `BookingCalendarCard`, `BookingTimeSlotsCard`, `BookingNotesField` and `BookingExpertCard` into a neutral `bookingpicker/` package. The picker instead imports `MakeABooking*` composables directly from `clientmode.makeabooking.subviews`. The new params (`hidePastSlots`, `currentSlotStart`, `paidWindowNote`, `tagPrefix`) were added with defaults, so it works. The expert route now depends on a client-mode package, which breaks the "neutral package" intent. Cosmetic debt, not a user-visible defect.
- Pass: per-card `contentDescription` ("Reschedule session with {name}") distinguishes several buttons in a list.

### Pillar 3: Color (4/4)
- No hex literals in `screens/clientmode/reschedule`, `screens/expertmode/reschedule` or `RescheduleActionButton.kt`.
- Banner alpha is 0.10 fill and 0.45 border (spec-exact) with a `tertiary` icon. Continue uses `primary`; Dismiss and Reschedule use `onSurface`. Accent stays on the reserved list.

### Pillar 4: Typography (4/4)
- Banner uses `labelMedium`, dialog titles `titleLarge`, dialog buttons `labelLarge`. The `fontSize` and `.sp` grep returned nothing.

### Pillar 5: Spacing (3/4)
- WARNING: `Spacer(Modifier.padding(top = Spacing.sm))` (~l.268) is a zero-size Spacer padded to produce a gap. It works but hides intent. Use `Spacer(Modifier.height(Spacing.sm))`.
- Note only: skeleton heights (88/360/168/144/56) and `ButtonMinHeight`, `GlyphSize`, `IconSize` are raw dp. The spec lists these as component-dimension exceptions.
- Pass: `ActionButtonPair` stacks vertically at font scale 1.5 or more, or when the width is under 320dp.

### Pillar 6: Experience Design (2/4)
- See Top 3 fixes 1 to 3 (skeleton semantics, non-scrolling error state, disabled-border styling).
- Pass: `BackHandler` and `backEnabled = !isSubmitting` block back while a submit is in flight.
- Pass: the Submit button keeps its footprint and enabled fill while submitting, with "Choose a new time first" and "In progress" state descriptions.
- Pass: the picker never receives `authorization_expires_at`, matching the locked non-gating rule.
- Pass: the "Reschedule request sent" snackbar is wired in all four origin screens.
