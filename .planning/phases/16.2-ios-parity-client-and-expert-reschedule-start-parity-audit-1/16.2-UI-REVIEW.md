## Top 3 Priority Fixes

1. **WARNING (still open): `RescheduleActionButton` uses a fixed `outline` border even when disabled** (`RescheduleActionButton.kt`, `.border(OutlineWidth, outline, CircleShape)`). A disabled button looks tappable. `DestructiveOutlinedButton` already switches to `outlineVariant` when disabled. Fix: use `outline.copy(alpha = 0.38f)` or `outlineVariant` when `!enabled`.
2. **WARNING (still open): `FailedContent` is a non-scrolling `Box(fillMaxSize)`** (`ReschedulePickerScreen.kt` ~l.188). At large font scale or in landscape the Retry action can clip off-screen. Fix: add `verticalScroll(rememberScrollState())`.
3. **WARNING (still open, partly resolved): loading semantics.** `LoadingContent` (l.170) sets only `liveRegion = Polite`. `SkeletonGroup` merges descendants, but the "Loading" description the spec requires was not confirmed. Fix: pass the description explicitly and add a test.

Further items: the border color differs inside the pair (see Pillar 2), the spacer hack, the disclosure copy, and the package extraction.

## Detailed Findings

### Pillar 1: Copywriting (3/4)
- Strings match the contract. "Reschedule" is fixed for the label, and the per-card a11y string "Reschedule session with {name}" is used.
- WARNING: `reschedule_start_disclosure_message` says "more than a few days out" unconditionally. When `chargesSoon` appends the charge-soon sentence, the two can contradict each other. Verify against the iOS alert.

### Pillar 2: Visuals (3/4)
- Plan 13: the pending-approval card now shows the tinted notice followed by a Reschedule + Message pair (`UpcomingBookingCard.kt` l.177-190). Without `onReschedule` it falls back to a full-width Message. The confirmed card stacks Join full width above the pair. Hierarchy is clear. The Reschedule + Message row is shared through `RescheduleMessageRow`, which avoids drift between the two branches.
- Plan 16: the `Layout`-based pair gives equal halves, or a full-width stack when a label does not fit. This removes the earlier two-line "Reschedule" wrap. Trade-off: the card height changes between the paired and stacked states. That is acceptable.
- WARNING: borders inside one pair differ. Reschedule uses `outline`; Message uses `outlineVariant` (`MessageButton.kt`). Side by side they read as unequal weights. Align them, or document the intent.
- WARNING (carried over): the picker still imports `MakeABooking*` composables from the client-mode package, not a neutral package.

### Pillar 3: Color (4/4)
- No hex literals in the touched files. Reschedule and Message use `onSurface`. Destructive uses `error`. Accent stays reserved (a `primary` spinner only).

### Pillar 4: Typography (4/4)
- No `fontSize` or `.sp` overrides. The destructive button applies `labelLarge`. The Reschedule label uses the button default.

### Pillar 5: Spacing (3/4)
- Pass (plan 15): `ActionButtonPairDefaults.ContentPadding` is 8 dp horizontal (`Spacing.sm`) and is the single shared token. `MessageButton` and `DestructiveOutlinedButton` take a `contentPadding` parameter whose defaults are unchanged (24 dp / `Spacing.lg`), so non-paired usages are unaffected. The gap is `Spacing.md` or `Spacing.sm` per site, as the spec says.
- WARNING: the `Spacer(Modifier.padding(top = Spacing.sm))` hack remains. Use `Modifier.height`.
- Note: `ButtonMinHeight` (56 dp) and the glyph sizes are raw dp, which the spec allows as component-dimension exceptions. The `DestructiveOutlinedButton` `MinTouchTarget` is 48 dp while Reschedule and Message are 56 dp. In a Reschedule + Cancel pair the heights may differ in the paired layout. Each button's height is measured independently, so the row is not equalized. Verify visually.

### Pillar 6: Experience Design (2/4)
- Open: the disabled-border and non-scrolling-error items above.
- Pass (plan 14): the call guard on disclosure Continue is wired at the call site. Only `onContinue` sends, and Cancel or a scrim tap leaves the picker untouched. The full guard behaviour was not exercised.
- Pass (plan 13): Reschedule is shown by status only. It appears on pending approval and confirmed, via a null `onReschedule`. The `MessageButton` `busy` flag swallows taps and exposes "Opening chat".
- Pass: `BackHandler` blocks back while submitting. The Submit button has state descriptions. The "Reschedule request sent" snackbar is wired at all four origin screens.
- Risk: `ActionButtonPair` reads `maxIntrinsicWidth` on its slots, which breaks if a slot ever uses subcomposition. This is documented in the KDoc, and the current slots are fine.
