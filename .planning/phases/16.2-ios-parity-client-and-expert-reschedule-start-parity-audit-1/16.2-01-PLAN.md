<objective>
Build the wire contract for starting a reschedule: the two `PATCH .../reschedule` endpoints with their request types and repository methods, the optional `exclude_booking_id` on the availability call, and `can_reschedule` on the expert booking DTOs. Every later plan in this phase compiles against these.

Purpose: the backend `rescheduleSchema` is `.strict()` (unknown keys are a 422) and the client body carries a money-relevant card id on its retry, so the exact JSON is pinned by MockWebServer tests before anything is built on it. The leading tracer proves both PATCH paths end to end (URL constant, Retrofit method, request DTO, repository, fake override, wire test).
Output: 7 modified main files, 1 new test class, 3 extended test classes, the fake and fixture updates.
