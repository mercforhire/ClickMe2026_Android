# Phase 16.1 Plan 02: Explore See all and Search stack reset Summary

**Both Explore headers now carry "See all", which switches to the Search tab exactly like iOS `onSeeAllExperts`, and the client "View My Bookings" / "Explore Experts" resets also clear the Search stack so a booking started from Search never leaves Request Sent parked there.**

## Performance

- **Duration:** about 50 minutes (start time was not captured at spawn; estimated from the commit timeline)
- **Tasks:** 3 of 3
- **Files:** 11 modified, 0 created (275 insertions, 20 deletions)

## Accomplishments

- Added `explore_see_all` and an `onSeeAll` callback threaded `ExploreScreen` -> `ExploreContent` -> both sections, with `EXPLORE_EXPERTS_SEE_ALL_TAG` and `EXPLORE_FEATURED_SEE_ALL_TAG`. The Recommended Experts header shows it in every section state; the Featured Topics header shows it whenever the section renders (loaded with topics, or error).
- Added `internal fun Navigator.showSearch() = navigate(SearchRoot)` and wired the Hilt `exploreRoot` with `onSeeAll = navigator::showSearch`. It selects the tab only: no reset, no filter hand-off.
- `showMyBookings` now resets `ExploreRoot, SearchRoot, ClientBookingsRoot` and `showExplore` resets `ExploreRoot, SearchRoot`; `Navigator.resetAndSelect` KDoc points at them.
- Tracer proved the full path from the real Recommended Experts button inside the real `HomeClientShell` to the selected Search tab before any expansion.
