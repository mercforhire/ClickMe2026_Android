# Phase 16.1 Plan 03: Search ViewModel Summary

**Hilt `SearchExpertViewModel` porting iOS: browse-set first load with a non-blocking chip job, 300 ms debounced trimmed-query text search, immediate chip and sort re-runs, single-job latest-wins cancellation, and the D-07/D-08/D-09 skeleton, inline-failure and keep-rows-on-refresh rules, all proven under virtual time.**

## Accomplishments

- Tracer: `SearchExpertViewModel` first load end to end (ViewModel -> `SearchRepository` -> `FakeClickMeApi`, plus the real `CategoryStore`): browse set `("", null, "relevance", 1, 20)` sent once, chips loaded in a separate `categoriesJob` whose `ApiException` is swallowed to an empty list, `Failed` carries the server message or `error_state_body`.
- Triggers: `onQueryChange` (300 ms debounce, raw text kept in the field, trimmed in the request, no dedupe), `onCategorySelected` (single select, re-tap re-runs, All sends no category), `onSortSelected` (`relevance` / `rating`), all through one `searchJob`.
- Refresh and retry: `onRefresh` keeps rows and raises one-shot `refreshFailed` on failure when rows are on screen, otherwise acts as a new search; `onRetry` is a new search; both repair empty chips; `onRefreshFailureConsumed` clears the flag.
- 21 virtual-time tests in `SearchExpertViewModelTest`; no saved-state handle (D-02).
