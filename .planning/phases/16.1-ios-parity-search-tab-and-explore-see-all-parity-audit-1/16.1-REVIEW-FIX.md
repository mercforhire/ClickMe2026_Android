### WR-01: Hoisted `LazyListState` keeps the old scroll position across new searches

**Files modified:** `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertUiState.kt`, `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertViewModel.kt`, `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertScreen.kt`, `app/src/test/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertViewModelTest.kt`
**Commit:** 455b1578
**Status:** fixed: requires human verification (scroll/UI behaviour is not covered by a unit test)
**Applied fix:** Added `searchRevision: Int` to `SearchExpertUiState`. `runSearch` bumps it in the same state update that lands a Fresh search's results. A Refresh and a failed search leave it unchanged. In `SearchExpertContent`, a `LaunchedEffect(state.searchRevision)` calls `listState.scrollToItem(0)` only when the revision differs from a `rememberSaveable` "seen revision". The saveable value means a tab-switch recomposition (same revision) does not reset the scroll position (D-03), and pull-to-refresh (same revision) keeps its position. Added two ViewModel tests covering the revision bump rules.

### IN-01: `contentDescription` on the text field may hide the typed text from TalkBack

**Files modified:** `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/subviews/SearchExpertSearchBar.kt`
**Commit:** 4f717197
**Status:** fixed: requires human verification (TalkBack speech is not testable on the JVM; check on the Samsung device)
**Applied fix:** Confirmed in the Compose UI 1.12.1 accessibility delegate source that a `contentDescription` on an editable node replaces the node text in TalkBack output and disables per-character traversal, so the finding was real. Replaced it with `semantics { if (query.isNotEmpty()) text = AnnotatedString(placeholderText) }`. The delegate prefers `EditableText` over `Text` for the node's spoken text, so the typed value is what is read back, while the placeholder stays in the merged semantics tree as the field's name once the real placeholder has left composition. This is the closest Compose gets to a hint, because Compose has no public `hintText` property. The project's JVM audit (`assertActionablesNamed`) treats an editable value as not a name, so simply removing the semantics block failed `searchFieldPassesTheA11yAudit`; the `Text` property satisfies it. No test asserted the old contentDescription, so no test needed updating.

### IN-05: The "one bad row cannot fail the list" claim does not hold, and Search/Explore stacks can still share un-keyed booking-flow routes

**Files modified:** `app/src/main/java/com/uptrendinvestments/clickmeapp/model/responses/ExpertsSearchPayload.kt`, `app/src/main/java/com/uptrendinvestments/clickmeapp/navigation/StackOrigin.kt`
**Commit:** 19033e32
**Applied fix:** (a) Rewrote the `ExpertSearchResultItem` KDoc. Nullable display fields still decode and get UI fallbacks. `expertId` is required because the RPC returns it as the non-null primary-key uuid and a row without it cannot be opened, so a missing id fails the whole decode and the screen shows its inline error. It also notes that `totalReviews` is parsed for iOS parity but not shown. I did not thread `origin` through `BookingKey`, because that is a wider navigation change.
