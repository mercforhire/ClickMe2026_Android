### WR-01: Hoisted `LazyListState` keeps the old scroll position across new searches

**Files modified:** `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertUiState.kt`, `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertViewModel.kt`, `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertScreen.kt`, `app/src/test/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertViewModelTest.kt`
**Commit:** 455b1578
**Status:** fixed: requires human verification (scroll/UI behaviour is not covered by a unit test)
**Applied fix:** Added `searchRevision: Int` to `SearchExpertUiState`. `runSearch` bumps it in the same state update that lands a Fresh search's results. A Refresh and a failed search leave it unchanged. In `SearchExpertContent`, a `LaunchedEffect(state.searchRevision)` calls `listState.scrollToItem(0)` only when the revision differs from a `rememberSaveable` "seen revision". The saveable value means a tab-switch recomposition (same revision) does not reset the scroll position (D-03), and pull-to-refresh (same revision) keeps its position. Added two ViewModel tests: Fresh searches (sort, chip) bump the revision while Refresh does not, and a failed refresh and a failed fresh search leave it unchanged.

### WR-02: A "Couldn't refresh" snackbar outlives the search that superseded it

**Files modified:** `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertScreen.kt`, `app/src/main/java/com/uptrendinvestments/clickmeapp/screens/clientmode/search/SearchExpertViewModel.kt`
**Commit:** 3ba474d9
**Status:** fixed: requires human verification (snackbar timing is not covered by a unit test)
**Applied fix:** Added `LaunchedEffect(state.query, state.selectedCategorySlug, state.sort, state.results) { snackbarHostState.currentSnackbarData?.dismiss() }` in `SearchExpertContent`. A visible refresh-failed snackbar is now dismissed when the query, chip, sort or rows change. The refresh failure itself changes none of these, so the snackbar still shows. Corrected the `runSearch` KDoc to say the screen owns dismissal of a snackbar that is already visible.
