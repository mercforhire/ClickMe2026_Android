# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Phase 1 builds the app-wide design system (Material 3 theme: color, type, shape, spacing, motion), the Android 12 splash, the client and expert 5-tab scaffolds with per-tab back stacks and placeholder tab content, and the six shared components (FND-09, FND-10, FND-11, FND-12). Later phases reuse this contract, so tokens are defined app-wide. Screen-specific copy for later phases is out of scope.
>
> **Design source.** The original designs live in Google Stitch, which is not accessible. The iOS implementation is the stand-in: `ios-reference/ClickMe2026/Theme/Brand.swift` ("Luminous Dark", already using Stitch/M3 token names), `Theme/BrandFont.swift`, and `Views/Components/**`. A Stitch export can refine the derived values below later (derived values are marked "(derived)"). Replace them then; do not fork the theme.
>
> **Platform rule.** Use Material 3 idioms where iOS and Android differ. Pixel parity with iOS is not a goal (CLAUDE.md "Platform swaps").

## Spacing Scale

Declared values (all multiples of 4, in `dp`). Token names are the Kotlin names in `Spacing.kt` (identifiers cannot start with a digit, so `xxl` / `xxxl`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4dp | Icon gaps, field error text gap, inline padding |
| sm | 8dp | Compact spacing: icon-to-text in buttons and fields, gap between list items |
| md | 16dp | Default: screen edge padding, card inner padding, field horizontal padding, field bottom margin |
| lg | 24dp | Section padding, form screen edge padding, gap between sections |
| xl | 32dp | Layout gaps, empty-state icon-to-text spacing |
| xxl | 48dp | Major section breaks, minimum touch target |
| xxxl | 64dp | Page-level spacing, empty-state top offset |

Layout defaults: screen content padding `md` (16dp) horizontally; form screens (login, signup, later) use `lg` (24dp). Vertical rhythm between sections `lg`; between related elements `sm`. Values off this scale (iOS uses 6, 10, 18, 54) are rounded to the nearest token when porting: 6 to xs or sm, 10 to sm, 18 to md, 54 to 56 (see exceptions).

Exceptions (component dimensions and platform minimums, not layout spacing):
- **Touch targets:** minimum 48dp x 48dp for anything tappable (Android guideline; iOS used 44pt). The 32dp avatar is visually 32dp but its tap target is 48dp.
- **Control heights:** `AsyncSaveButton` and `ValidatedField` minimum height 56dp (iOS 56 and 54; 56 is the M3 text field height). Use `heightIn(min = 56.dp)` so large font sizes can grow the control.
- **M3 NavigationBar:** default container height 80dp.
- **Stroke widths:** 1dp resting border, 2dp focused/error border (hairlines, not spacing).
- **Glow blob geometry** (GreenGlowBlobLayer) uses decorative sizes of 300dp / 190dp and offsets of 30dp and 20dp, which are not layout spacing.

## Typography

Nunito, two weights only: **Regular 400** and **SemiBold 600**. iOS weights map as: regular and medium to 400; semibold and bold to 600. Letter spacing 0 everywhere. Line height is body 1.5, headings about 1.2.

The whole app uses exactly **four sizes: 12, 16, 20 and 28 sp**. There are no reserved extra sizes; hierarchy beyond size comes from weight (400 / 600) and color (`onSurface` / `onSurfaceVariant` / `onSurfaceMuted`).

### Declared roles

| Role | Size | Weight | Line Height | M3 slot |
|------|------|--------|-------------|---------|
| Body | 16sp | 400 | 24sp (1.5) | `bodyLarge` |
| Label | 12sp | 600 | 16sp (1.33) | `labelMedium` (nav bar labels, field error text, badges) |
| Heading | 20sp | 600 | 24sp (1.2) | `titleLarge` (TopAppBar title, empty-state heading) |
| Display | 28sp | 600 | 34sp (1.2) | `headlineLarge` (not used by a Phase 1 screen; reserved for hero headings in later phases) |

### Full app-wide mapping (the iOS `BrandFont.swift` table onto `ClickMeTypography`)

Every M3 slot is assigned one of the four sizes. Later phases consume these slots; they must not set `fontSize` directly.

| iOS style (original sizes) | Android slot(s) | Size / line height | Weight |
|---|---|---|---|
| `.caption2` (9–11), `.caption` (12–13) | `bodySmall`, `labelSmall` (regular); `labelMedium` (semibold) | 12sp / 16sp | 400 (`bodySmall`, `labelSmall`); 600 (`labelMedium`) |
| `.subheadline` (14–15), `.callout`, `.body` (16–17) | `bodyLarge`, `bodyMedium` (regular); `titleMedium`, `titleSmall`, `labelLarge` (semibold; `labelLarge` is the button label) | 16sp / 24sp | 400 (`bodyLarge`, `bodyMedium`); 600 (`titleMedium`, `titleSmall`, `labelLarge`) |

Folding notes: iOS subheadline (14–15) text becomes 16sp; distinguish it from body with weight (600) or color (`onSurfaceVariant` / `onSurfaceMuted`), not size. iOS title2 (22–24) text becomes 20sp. Check that layouts ported from iOS still fit at 16sp where iOS used 14–15.

Rules: use `Text(style = MaterialTheme.typography.X)`; don't hard-code `fontFamily` or `fontSize`. Do not truncate with fixed-height containers; text containers use `heightIn(min = …)`. Check every Phase 1 component at 200% font scale.

## Motion

| Interaction | Duration / easing |
|---|---|
| Press scale (all pressable buttons) | 120ms, `EaseInOut`, scale 0.96 |
| Control state change (`AsyncSaveButton` idle/saving/saved) | 150ms crossfade; width never changes |
| Field error appear/disappear (border color, message) | 200ms, fade + slide-down 4dp |
| Tab switch (within a mode shell) | fade-through: 150ms in (after 90ms out) |
| Push/pop inside a tab | horizontal slide + fade, 300ms, `FastOutSlowIn`. System predictive-back drives pops. |
| Splash | System-owned (no custom animation, no fixed delay) |

Do not port the iOS splash pulse (1.6s halo) or logo scale-in; the Android 12 SplashScreen API owns that moment. All animations follow the system animator duration scale (Compose does this for `tween`/`animate*AsState`; don't add custom `Handler` delays).

## App Shell and Navigation (FND-12)

### Structure

- `ClickMeApp` (root) holds a `NavHost` over `AppRoute`. Each mode has its own tab shell: `HomeClientScreen` and `HomeExpertScreen` (mirrors `Client Mode/Home/HomeClientView.swift` and `Expert Mode/Home/HomeExpertView.swift` → `screens/clientmode/home/HomeClientScreen.kt`, `screens/expertmode/home/HomeExpertScreen.kt`, each with a `*ViewModel.kt`). They share one `HomeTabScaffold` composable that takes a list of tab definitions.
- Per-tab back stacks: one `NavHost` per shell with one nested navigation graph per tab. Tab selection calls `navigate(tab.graphRoute) { popUpTo(startDestination) { saveState = true }; launchSingleTop = true; restoreState = true }`. Each tab's stack and state survive switching.
- Re-tapping the selected tab pops that tab to its root.
- System Back: pops within the current tab; at a non-home tab root it selects the home tab (Explore / Dashboard); at the home tab root it exits the app.
- Bottom bar is visible on every route by default. A route can opt out with a `showsBottomBar = false` flag for later full-screen flows (call, booking). Phase 1 defines the flag; no route uses it.
- Cross-tab navigation (iOS: "message" jumps to Chats and pushes a thread) is a shell-level action: `selectTab(tab)` then `navigate` into that tab's graph. Phase 1 exposes this API; it has no caller yet.

### Tabs (NavigationBar, labels always visible)

|---|---|---|
| Client | Explore | `Outlined.AutoAwesome` / `Filled.AutoAwesome` |
| Client | Search (placeholder) | `Outlined.Search` / `Filled.Search` |
| Client | Bookings | `Outlined.CalendarMonth` / `Filled.CalendarMonth` |
| Client | Chats | `Outlined.ChatBubbleOutline` / `Filled.ChatBubble` |

Icons from iOS: sparkles, magnifyingglass, calendar, message, person, house, pencil.and.list.clipboard.

NavigationBar styling:
- `containerColor = surfaceContainer`, `tonalElevation = 0.dp`; draws under the gesture/3-button bar (insets handled by `NavigationBar`).
- `NavigationBarItemDefaults.colors`: selected icon and text `primary`; indicator `secondaryContainer`; unselected icon and text `onSurfaceVariant`.
- Label style `labelMedium` (12sp / 600). `alwaysShowLabel = true` (iOS shows labels).

### Top app bars

- Tab roots: small left-aligned `TopAppBar`, title = tab name in `titleLarge`, container `surface`, `scrolledContainerColor = surfaceContainer`, title color `onSurface`.
- **Explore (client) and Dashboard (expert)** show `TopBarAvatarButton` in the trailing action slot (iOS: Explore is the only tab with the branded top bar; avatar opens the mode switch in Phase 4). Phase 1 renders it with the fallback silhouette and a no-op `onClick` parameter.
- Pushed screens: `TopAppBar` with `Icons.AutoMirrored.Filled.ArrowBack` navigation icon (contentDescription "Back"), same colors.
- Insets: `Scaffold` handles them. No content hidden behind system bars or cutouts.

### Shared EmptyState and placeholder tab content (each of the 10 tabs)

`EmptyState(icon: ImageVector, heading: String, body: String, action: EmptyStateAction? = null)` (`components/EmptyState.kt`) is the shared empty-state layout for the whole app. **`heading` and `body` are required and have no defaults**: every caller supplies specific copy (heading names what is missing; body says what to do next). `EmptyStateAction(label: String, onClick)` renders a `PressScaleButton` below the body when present.

Layout: centered column inside the tab's `Scaffold`; icon (Outlined, 48dp, `onSurfaceMuted`), `xl` (32dp) gap, heading (`titleLarge`, `onSurface`, centered), `sm` (8dp) gap, body (`bodyLarge`, `onSurfaceMuted`, centered, max width 320dp), optional action `lg` (24dp) below. Background `surface`.

Phase 1 placeholder tabs are a thin wrapper, `PlaceholderTabContent(tab)`, that calls `EmptyState(icon = tab icon, heading = tab name, body = "Nothing here yet.")`. That body string is the **Phase 1 stub only**; later phases replace each tab's content and pass real copy.

**Focal point and hierarchy (placeholder tabs):** the focal point is the centered icon plus heading cluster. Order of emphasis: heading (20sp / 600, `onSurface`) first, then body (16sp, `onSurfaceMuted`), then the muted icon. The only accent color on the screen is the selected NavigationBar item (`primary`), which anchors the user's location.

### Debug-only affordances (`BuildConfig.DEBUG`, removed or hidden in release; Phase 4 replaces the scaffold switch with the real mode switch)

On the Profile tab placeholder of each shell:
- Button "Switch to expert scaffold" / "Switch to client scaffold" (outlined button) so both shells can be verified on a device.
- Button "Design system gallery" opening `DesignSystemGalleryScreen` (pushed, back arrow). The gallery renders every shared component in every state with the real theme (success criterion 3), and a type-scale and color-token swatch list. Every component also has `@Preview` functions (dark).

**Focal point and hierarchy (debug gallery):** a single scrolling column on `surface` with `md` edge padding, one section per component separated by `lg` gaps. In each section the focal point is the live component demo; hierarchy is section heading (`titleLarge`, `onSurface`) first, then the demo, then a state caption beneath it (`labelMedium`, `onSurfaceMuted`). `AsyncSaveButton` is the only filled accent element in its section, so the accent stays a single focal point per screen area.

## Shared Components (FND-10)

Files mirror `Views/Components/**` under `app/src/main/java/com/uptrendinvestments/clickmeapp/components/`. All read colors and styles from `MaterialTheme`; no hex literals.

### 1. PressScaleButton (`components/buttonstyles/PressScale.kt`; iOS `PressScaleButtonStyle`)

- API: `Modifier.pressScale(interactionSource: InteractionSource, pressedScale: Float = 0.96f)` plus `PressScaleButton(onClick, modifier, enabled, shape = CircleShape, colors, content)` wrapping M3 `Button` and sharing its `MutableInteractionSource`.
- Scales to 0.96 while pressed, animated 120ms `EaseInOut`. Keeps the M3 ripple (Android idiom) clipped to the shape.
- Min size 48dp touch target; default content padding 24dp horizontal.
- Default colors: container `primary`, content `onPrimary`; disabled uses M3 default (`onSurface` 12% / 38%).
- Variants available via `colors`: filled (accent), `surfaceContainerHigh` tonal (neutral), `destructive`/`onDestructive`.
- Label style `labelLarge`.

### 2. AsyncSaveButton (`components/buttons/AsyncSaveButton.kt`; iOS `AsyncSaveButton`, `SaveState`)

- API: `AsyncSaveButton(title: String, state: SaveState, onClick: () -> Unit, modifier, savedTitle: String = "Saved!", enabled: Boolean = true)`; `enum class SaveState { Idle, Saving, Saved }`.
- Full width, `heightIn(min = 56.dp)`, `CircleShape`, built on `PressScaleButton`.
- Container `primary`, content `onPrimary`. Glow: `Modifier.shadow(12.dp, CircleShape, ambientColor = primary.copy(alpha = 0.5f), spotColor = primary.copy(alpha = 0.5f))` (iOS: primary 50%, radius 18, y +5). Colored shadows need API 28; on API 26–27 the tint is ignored, which is acceptable.
- States (crossfade 150ms, same width and height in all three):
  - **Idle:** `title` in `labelLarge` (16sp / 600).
  - **Saving:** `CircularProgressIndicator`, 24dp, 3dp stroke, color `onPrimary`. Not clickable.
  - **Saved:** `Icons.Filled.CheckCircle` 20dp + `sm` gap + `savedTitle`, all `onPrimary`. Not clickable.
- Saving and Saved keep the full `primary` look (not the grey disabled look), matching iOS. The button is disabled for input only. If `enabled = false` while Idle (for example, invalid form), use the M3 disabled colors.
- Accessibility: `stateDescription` "Saving" / "Saved"; announce Saved with `liveRegion = Polite`.

### 3. ValidatedField (`components/ValidatedField.kt`; iOS `ValidatedField`)

- API: `ValidatedField(value, onValueChange, placeholder: String, leadingIcon: ImageVector, error: String?, modifier, isSecure: Boolean = false, keyboardOptions, keyboardActions, enabled)`.
- Built on `OutlinedTextField`, `singleLine = true`, `shape = CircleShape`, `heightIn(min = 56.dp)`, horizontal content padding `md`.
- Container fill `surfaceContainer`. Border via `OutlinedTextFieldDefaults.Container`: 1dp `outline` at rest; 2dp `primary` focused; 2dp `destructive` when `error != null` (pass `unfocusedBorderThickness = 2.dp` when in error).
- Leading icon 20dp: `onSurfaceMuted`, `destructive` on error. Gap to text `sm`.
- Text `bodyLarge` `onSurface`; placeholder `bodyLarge` `onSurfaceMuted` (deliberately higher contrast than iOS white-30%). Cursor `primary`, `destructive` on error.
- Error text below the field: `labelMedium` (12sp / 600) `destructive`, start padding `xs`, gap `xs`; appears with the Motion spec (200ms). Set `Modifier.semantics { error(message) }` so TalkBack reads it. The accessible name of the field is `placeholder`.
- Bottom margin `md` below the whole block (error text included).
- Non-secure: `capitalization = None`, `autoCorrectEnabled = false`; caller supplies `keyboardType`.
- Secure: `PasswordVisualTransformation` by default, trailing eye toggle (`IconButton` 48dp, icon `Visibility` / `VisibilityOff` 24dp, `onSurfaceMuted`) with contentDescription "Show password" / "Hide password" (copy from iOS). The visibility flag is local `rememberSaveable` state. Keyboard `Password`, autofill content type Password, `autoCorrectEnabled = false`, `capitalization = None`.

### 4. Avatar and TopBarAvatarButton (`components/avatar/`; iOS `TopBarAvatarButton`)

- `Avatar(url: String?, size: Dp = 32.dp, contentDescription: String?, modifier)`: Coil `AsyncImage`, `ContentScale.Crop`, `CircleShape`, 200ms crossfade. Allowed sizes: 32, 40, 56, 96 dp.
- Fallback (null/blank URL, loading, or error): disc `surfaceContainerLow` with `Icons.Filled.Person` at 62.5% of the size in `onSurfaceVariant` (replaces the SF Symbol `person.crop.circle.fill`).
- `TopBarAvatarButton(avatarUrl: String?, onClick: () -> Unit)`: 32dp `Avatar` inside a 48dp `IconButton`; contentDescription "Your profile". Never `Modifier.clickable` on a 32dp view.
- Decorative avatars (next to a name) pass `contentDescription = null`.

### 5. GreenGlowBlobLayer (`components/backgrounds/GreenGlowBlobLayer.kt`; iOS `GreenGlowBlobLayer`)

- A `Box`/`Canvas` background layer drawn behind screen content; fills its parent, clipped to bounds, `clearAndSetSemantics {}`.
- Two blobs, `primary` radial gradient: center stops `primary` @ 18% alpha, `primary` @ 7% at 55%, transparent at 100%; gradient radius 190dp (iOS: 300pt frame, 44pt blur; the extra radius stands in for the blur).
- Blob 1 center: x = width + 30dp, y = 10% of height. Blob 2 center: x = -20dp, y = 65% of height.
- No `Modifier.blur` (API 31+ only and costs GPU time). Gradient only.
- Opt-in per screen (login, signup, welcome-style screens); tab placeholders do not use it. Appears in the gallery on a `surface` background.

### 6. Custom Tab launcher (`components/web/CustomTabLauncher.kt`; iOS `SafariView`)

- API: `fun Context.openCustomTab(url: Uri, onFailure: () -> Unit)` and `@Composable rememberCustomTabLauncher(): (Uri) -> Unit`.
- `CustomTabsIntent.Builder`: `setColorScheme(COLOR_SCHEME_DARK)`; `setDefaultColorSchemeParams(CustomTabColorSchemeParams.Builder().setToolbarColor(surface).setNavigationBarColor(surface).build())` using `#131313`; `setShowTitle(true)`; `setUrlBarHidingEnabled(true)`; share button on (default).
- Only `https` (and `http` for dev links). If no Custom Tabs provider exists, fall back to `ACTION_VIEW`; if that also fails, call `onFailure` (callers show a Snackbar with the copy below). `mailto:` links are not routed here (later phases use `ACTION_SENDTO`).
- Used for policy pages, Stripe Connect onboarding (Phase 14) and external join URLs (Phase 9). Back returns to the app.

## Copywriting Contract

Phase 1 has almost no user-facing copy. All strings go into `res/values/strings.xml` (English only for now); nothing is hard-coded in composables.

| Element | Copy |
|---------|------|
| Primary CTA | None in shipped Phase 1 UI. `AsyncSaveButton` and `PressScaleButton` take a caller-supplied label; the gallery uses "Save changes". Saved-state default: "Saved!" |
| Tab labels | Client: "Explore", "Search", "Bookings", "Chats", "Profile". Expert: "Dashboard", "Bookings", "Topics", "Chats", "Profile". |
| Empty state heading | Caller-supplied and specific (names what is missing). Phase 1 stub: the tab name. |
| Empty state body | Caller-supplied (says what is missing and the next step). Phase 1 stub only: "Nothing here yet." |
| Error state | Heading "Something went wrong", body "Check your connection and try again.", button "Retry connection". Defined now as the shared pattern for Phase 15. No Phase 1 screen can fail. |
| Custom Tab failure | "Couldn't open the link. Try again in your browser." (Snackbar) |
| Password toggle (a11y) | "Show password" / "Hide password" |
| Avatar button (a11y) | "Your profile" |
| Back (a11y) | "Back" |
| Debug-only (not localized, not shipped in release) | "Switch to expert scaffold", "Switch to client scaffold", "Design system gallery" |
| Destructive confirmation | None in Phase 1. App-wide pattern for later phases: Material `AlertDialog` (`surfaceContainerHigh`, `extraLarge` shape); title = verb + noun as a question ("Log out?"), body states the consequence and whether it can be undone, confirm button in `destructive` labeled with the same verb ("Log out"), dismiss button "Cancel". |

Splash wordmark and tagline ("ClickMe", "Book time with the best minds.") are intentionally not shown on Android.

## Accessibility Contract

- Touch targets at least 48dp x 48dp (see Spacing exceptions).
- Every icon-only control has a contentDescription from the table above; decorative icons have `null`.
- Text contrast: 4.5:1 for text; 3:1 for input borders and icons (see Color, Contrast). `onSurfaceFaint` is never used for required text.
- All text is `sp`; verify the shell and components at 200% font scale (no clipping; controls grow via `heightIn(min)`).
- Selected tab is exposed through `NavigationBarItem` semantics (selected state + tab role).
- Full TalkBack pass is Phase 15 (POL-04); Phase 1 only has to not make it harder.
