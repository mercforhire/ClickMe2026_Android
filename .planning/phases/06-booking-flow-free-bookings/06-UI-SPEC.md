# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope.** Two surfaces: the Make a Booking screen (replaces the body of `MakeABookingStubScreen`, route `BookingKey` unchanged) with its Topic picker sheet and error dialog, and the Request Sent screen (new route, replaces the booking screen in the back stack). Requirements: BOOK-01, BOOK-02, BOOK-03, BOOK-04. Out of scope and must not appear in the UI: the paid path (payment sheet, payment-methods gate, "Add a Payment Method", "How does payment work?", the payment-lifecycle card), promo codes, reschedule, My Bookings content, booking detail screens.
>
> **Baseline.** `01-UI-SPEC.md` (tokens, shapes, motion, shell), `04-UI-SPEC.md` (picker sheet) and `05-UI-SPEC.md` (card, skeleton, section-header and Free-price patterns) are locked and not restated. Dark only, Material 3, Nunito 400 / 600, exactly four text sizes (12 / 16 / 20 / 28 sp), `Spacing` xs..xxxl, `ClickMeShapes`, `MaterialTheme.extras`. Every value below is an existing token unless marked "(new)".
>
> **Design source.** Google Stitch is not accessible. The stand-in is `ios-reference/ClickMe2026/Views/Screens/Client Mode/Make a Booking/**` and `Request Sent/**`. Copy is taken from iOS verbatim unless marked "(Android)". Layout is ported, not pixel-matched. `MakeABookingBrand` and `BookingRequestSentBrand` collapse to the Phase 1 tokens (FND-02).
>
> **Locked upstream decisions used here.** CONTEXT D-01..D-15 (see "Decision Traceability"). Where this spec fills a "Claude's Discretion" area it says so: slot row layout, skeletons, card styling, dot style, paid "coming soon" copy, free headline copy, timezone note copy, topic sheet, no-topics state, week start.

## Spacing Scale

Phase 1 tokens, all multiples of 4: xs 4, sm 8, md 16, lg 24, xl 32, xxl 48, xxxl 64.

| Token | Used for in this phase |
|-------|------------------------|
| xs (4dp) | Gap between a card title and its sub-line; gap between the day number and the open-day dot; gap between the notes field and its counter |
| sm (8dp) | Section heading to its content (iOS 10); gap between slot chips (both axes); icon-to-text inside rows and chips; chip vertical padding; summary row gap |
| md (16dp) | Screen horizontal padding (iOS 20); card inner padding; gap between a card's title and its content; slot chip horizontal padding; Request Sent card row padding and button gap (iOS 14) |
| lg (24dp) | Gap between the eight sections (iOS 28); gap between the check icon and the headline, headline and card, card and buttons on Request Sent (iOS 28); top padding under the app bar |
| xl (32dp) | Bottom scroll padding on both screens (iOS 40) so the last control clears the navigation bar; error-state icon-to-text spacing (inherited) |
| xxl (48dp) | Minimum touch target; Request Sent bottom padding (iOS 48) |
| xxxl (64dp) | Not used |

Exceptions (component dimensions and platform minimums, not layout spacing):
- Touch targets stay at least 48dp tall: month arrows (48 x 48), slot chips (`heightIn(min = 48.dp)`), picker row, meeting type rows (`heightIn(min = 56.dp)`), Retry buttons, dialog buttons.
- **Calendar day cell: 48dp tall, one seventh of the card width wide** (about 44dp on a 360dp-wide device, with `xs` card horizontal padding). This is the only target under 48dp wide; seven columns cannot reach 48dp on small phones. Inside the cell the selection circle is 36dp and the open-day dot is 4dp. Cell layout, top to bottom: 36dp number circle, `xs`, 4dp dot, `xs` = 48dp.
- Controls (Book Now, View My Bookings, Back to Home) use `heightIn(min = 56.dp)`.
- Expert card `Avatar` 56dp (iOS 52). Request Sent expert row `Avatar` 40dp.
- Topic sheet radio mark: Material `RadioButton` drawn with `onClick = null` (visual only, 24dp); the whole card is the target.
- Request Sent: check badge 128dp circle, check icon 64dp, topic icon badge 40dp (`small`), status dot 8dp.
- Stroke widths 1dp resting, 2dp selected or focused (hairlines).
- Skeleton shapes copy the real component dimensions above.

## Typography

Inherited: exactly four sizes (12, 16, 20, 28 sp), two weights (400, 600), line height 1.5 body and 1.2 headings. Nothing in this phase sets `fontSize`; every `Text` takes an M3 slot.

| Role | Size | Weight | Line height | Used for here |
|------|------|--------|-------------|---------------|
| Body | 16sp | 400 | 24sp (1.5) | Topic description, summary labels and values, meeting type labels, notes text and placeholder, day numbers, slot chip times (unselected), "No available slots on this day.", paid note, Request Sent body copy, date and time value, dialog message, loading text (`bodyLarge`) |
| Label | 12sp | 600 | 16sp (1.33) | Status pill text, Request Sent "Booking Details" caption (`labelMedium`). Regular-weight 12sp captions (weekday headers, notes counter, topic duration, timezone note) use `bodySmall` |
| Heading | 20sp | 600 | 24sp (1.2) | The eight section headings (`titleLarge`, via `SectionHeader`), sheet title "Choose a Topic", dialog title "Couldn't book", Request Sent topic value |
| Display | 28sp | 600 | 34sp (1.2) | "Request Sent!" (`headlineLarge`). The booking screen has no display text |

`titleMedium` (16sp / 600) is used for the expert name, the selected topic title, topic card titles in the sheet, the month-year label, the "Available Time Slots" card title, the selected slot chip time and the Expert name on Request Sent. `labelLarge` (16sp / 600) is used for button labels and dialog buttons. Weekday headers and the timezone note are `bodySmall` in `onSurfaceMuted`.

## Color

Dark only. All colors come from the Phase 1 ColorScheme and `MaterialTheme.extras`. No hex literal appears in this phase's code.

| Role | Value | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `#131313` `surface` | Both screens' backgrounds and app bars |
| Secondary (30%) | `#1C1B1B` `surfaceContainerLow` and `#201F1F` `surfaceContainer` | Expert card, topic row, calendar card, slots card, meeting type card, notes field fill (`surfaceContainer`), summary card, Request Sent details card: `surfaceContainerLow`, `medium`, 1dp `outlineVariant`. Topic cards inside the sheet: `surfaceContainer` (the sheet itself is `surfaceContainerHigh`). Selected topic card and the status pill: see below |
| Accent (10%) | `#44F697` `primary` | See reserved list |
| Destructive | `#FF4D4D` `destructive` | Not used. The only error surface is the neutral `AlertDialog`; no field validation errors exist in this flow |
| Pending | `#FFB833` `tertiary` | The 8dp dot in the "Awaiting Approval" pill only |

Accent reserved for (and nothing else on these screens):
1. Fill of the single primary CTA on each screen: "Book Now" (booking) and "View My Bookings" (Request Sent). "Back to Home" is tonal (`surfaceContainerHigh`, `onSurface`).
2. The selected calendar day (36dp filled circle, `onPrimary` number) and the selected time slot chip (filled, `onPrimary` time).
3. The open-day dot under calendar days that have at least one bookable slot (D-03; 4dp, `primary`).
4. Selected state of radio-style choices: `RadioButton` selected color on meeting type rows and sheet topic cards, and the 2dp border on the selected topic card (fill `secondaryContainer`).
5. The word "Free" wherever a topic price is shown: topic row, sheet card, Summary Price row (Phase 5 D-21).
6. The check icon (64dp) on Request Sent.
7. Focused border and cursor of the notes field (inherited from `ValidatedField`), and every `CircularProgressIndicator`.

Month arrows, today's marker, links and the Retry buttons are neutral (`onSurface`, `onSurfaceVariant`, `outline`). **Today's marker** (when not selected): 1dp `outline` ring around the 36dp circle, number in `onSurface`. Disabled or past content (days, slot chips, month arrow): `onSurface` at 38% alpha for text, `outlineVariant` at 38% for borders. Secondary text uses `onSurfaceMuted`. `onSurfaceFaint` is not used.

Surface tier rules follow Phase 1 exactly. Contrast: `onPrimary` on `primary` 9.3:1 (selected day, selected chip, CTA); `onSurfaceMuted` on `surfaceContainerLow` at least 5.9:1 (timezone note, captions).

## Navigation and Structure

```
Explore tab back stack (ExploreRoot):
Explore home
 └─ Expert Profile (ExpertProfileKey)                  (bottom bar visible)
      └─ Make a Booking (BookingKey)                   (bottom bar HIDDEN)
           ├─ Topic sheet            (ModalBottomSheet, not a route)
           ├─ "Couldn't book" dialog (AlertDialog, not a route)
           └─ on success: Request Sent (RequestSentKey) REPLACES Make a Booking (D-12)
                                                       (bottom bar HIDDEN)
```

| Screen | App bar | Back behavior |
|---|---|---|
| Make a Booking | `AuthTopAppBar`, title "Book a Session" (`make_a_booking_title`, existing), back arrow ("Back") | Pops to Expert Profile. No discard confirmation (iOS has none). Back while the topic sheet is open closes only the sheet |
| Request Sent | `AuthTopAppBar`, title "Booking Request", back arrow ("Back") | Pops to Expert Profile (the booking screen is gone, so the filled-in form can't be re-submitted). Same result as the system Back |

Route keys (`@Serializable NavKey`, registered in the client shell `entryProvider` in `HomeClientScreen.kt`, both with `BottomBar.hidden()`):
- `BookingKey(expertId, expertName, expertTitle, expertImageUrl)`: unchanged (Phase 5 D-04).
- `RequestSentKey(bookingId: String)` (new, `screens/clientmode/requestsent/`). It carries only the booking id (D-14). The screen fetches the rest.

Navigator operations needed (planner's choice of shape, per CONTEXT): replace-top (booking to Request Sent), and a cross-tab call that clears the Explore stack and selects the client Bookings tab (`ClientBookingsRoot`) for "View My Bookings"; "Back to Home" clears the Explore stack back to `ExploreRoot` and stays on the Explore tab.

Insets: every screen handles `safeDrawing`. The booking screen's scroll content uses `contentPadding` with `xl` bottom padding plus the navigation-bar inset, and `imePadding()` so the notes field and Book Now clear the keyboard.

## Screen Specifications

### 1. Make a Booking (BOOK-01, BOOK-02, BOOK-03)

Background `surface`. One `LazyColumn` (or `verticalScroll` Column), `md` horizontal padding, `lg` top padding, `lg` gap between sections. Each section is `SectionHeader` (`titleLarge`, `heading()` semantics) then `sm`, then its content. Tapping outside the notes field or starting a scroll clears focus and hides the keyboard (replaces the iOS keyboard "Done" toolbar). Section order is fixed:

| # | Section | Heading |
|---|---|---|
| 1 | Expert card | "Expert" |
| 2 | Topic picker | "Topic of Discussion" |
| 3 | Calendar | "Select a Time" |
| 4 | Time slots | card title "Available Time Slots" (inside the card, no `SectionHeader`) |
| 5 | Meeting type | "Meeting Type" |
| 6 | Message | "Message (optional)" |
| 7 | Summary | "Summary" |
| 8 | Book Now | none |

**1. Expert card.** Card (`surfaceContainerLow`, `medium`, 1dp `outlineVariant`, `md` padding), not clickable. Row: `Avatar` 56dp (decorative), `md`, column: name `titleMedium` `onSurface` (`maxLines = 2`), `xs`, title `bodyLarge` `onSurfaceMuted` (`maxLines = 2`, omitted when blank). Data comes from `BookingKey`; no loading state.

**2. Topic picker.** One card-shaped button (`Role.Button`, `heightIn(min = 56.dp)`, `md` padding, same card style). Row: column (selected topic title `titleMedium` `onSurface`, `maxLines = 2`; `xs`; sub-line = `bodySmall` `onSurfaceMuted` "{n} min", " · ", `PriceText` at `bodySmall` size ("Free" in `primary`, paid in `onSurface`)), flexible space, `Outlined.ExpandMore` 24dp `onSurfaceVariant`. Tapping opens the topic sheet. Semantics: merged "Topic of Discussion, {title}, {n} minutes, {price}", button.

| State | Rendering |
|---|---|
| Loading | One `SkeletonBlock` row, 56dp tall, `medium`, with a 60% width bar and a 25% width bar (copies iOS). Group `contentDescription` "Loading" |
| Loaded | As above. D-02: the first free topic is preselected, else the first topic |
| No topics (Claude's discretion) | The same card, not clickable, `onSurfaceMuted` text "This expert has no topics to book yet." (no chevron). Calendar, slots and the rest still render; Book Now stays disabled |
| Failed | `SectionError` inside the card: message = server message, else "Check your connection and try again."; Retry re-calls the details request |

**Topic sheet ("Choose a Topic").** `PickerSheet(title = "Choose a Topic")`, no search, no footer. Content is a `LazyColumn` of topic cards, `md` gap, `md` horizontal padding, `xl` bottom padding. Each card (`surfaceContainer`, `medium`, 1dp `outlineVariant`; selected: `secondaryContainer` fill and 2dp `primary` border; 150 ms color transition) is one merged `selectable(role = Role.RadioButton)` target with `md` padding:

| Element | Spec |
|---|---|
| Radio mark | `RadioButton(selected, onClick = null)` at the start, top-aligned with the title, `md` gap to the text column |
| Row 1 | Title `titleMedium` `onSurface` (wraps, no max lines), flexible space, price `PriceText` (`titleMedium`; `Money.format` for paid, "Free" in `primary`, "—" when unknown), `sm` gap |
| Row 2 | `sm` below. `Outlined.Schedule` 16dp `onSurfaceMuted`, `xs`, "{n} min" `bodySmall` `onSurfaceMuted` |
| Description | `sm` below, only when non-blank. `bodyLarge` `onSurfaceMuted`, wraps |

Every topic is listed, paid ones included (D-01). Tapping a card selects it and closes the sheet; tapping the already-selected topic only closes the sheet. Choosing a different topic clears the selected slot (D-02) and the Summary and Book Now update at once.

**3. Calendar ("Select a Time", D-03, D-06, D-07).** Card (`surfaceContainerLow`, `medium`, 1dp `outlineVariant`) with `xs` horizontal padding and `sm` vertical padding.

| Element | Spec |
|---|---|
| Month row | Previous arrow `IconButton` (48dp, `Outlined.ChevronLeft` 24dp `onSurface`, contentDescription "Previous month"), month-year label centered (`titleMedium` `onSurface`, localized "MMMM yyyy", `liveRegion = Polite`), next arrow (`Outlined.ChevronRight`, "Next month"). The previous arrow is disabled (38% alpha, not focusable as enabled) while the displayed month is the current month (D-06). Forward has no limit |
| Weekday headers | One row of seven, `bodySmall` `onSurfaceMuted`, centered, localized short names (`DayOfWeek.getDisplayName(SHORT)`), `sm` below. The first column follows the locale's first day of the week (Claude's discretion; iOS uses Sunday) |
| Day grid | 7 columns, rows of 48dp, no gaps. Leading and trailing cells outside the month are empty (no numbers). Day number `bodyLarge`, centered in the 36dp circle |
| Day states | Normal: `onSurface`. Today (not selected): 1dp `outline` ring. Selected: `primary` filled circle, `onPrimary` number, `titleMedium`. Past day in the current month: 38% alpha, not clickable (D-06). Open day (D-03): 4dp `primary` dot under the number, also under a selected day |
| Selection rule | The screen opens with today selected (no auto-jump, D-03). Tapping an enabled day selects it and clears the selected slot. Changing the month does not change the selected day and clears the selected slot (D-07). The slots card always states the selected date (below), so a selected day in another month is never ambiguous |
| Loading | The grid renders at once from the calendar alone; dots appear when the center month's availability arrives and are absent while it loads or after it fails |
| Semantics | Each day: label "{weekday}, {month} {day}, {year}", `selectable`, `stateDescription` "Has open times" when dotted, "Today" for today, disabled for past days. The dot itself is decorative |

**4. Time slots (BOOK-02, D-04, D-05, D-07).** Card (`surfaceContainerLow`, `medium`, 1dp `outlineVariant`, `md` padding), content in a column with `sm` gaps:

| Element | Spec |
|---|---|
| Title | "Available Time Slots" `titleMedium` `onSurface` (`heading()`) |
| Date line | The selected date, `bodyLarge` `onSurfaceMuted`, e.g. "Thursday, October 22" (locale-aware "EEEE, MMMM d" pattern from `DateFormat.getBestDateTimePattern`) |
| Timezone note (D-05) | `bodySmall` `onSurfaceMuted`, wraps. Expert zone known and different from the device zone: "Times are in your time zone ({clientAbbr}). Expert is in {City} ({expertAbbr})." Same zone: "Times are in your time zone ({clientAbbr})." Expert zone unknown: the same single line. `{City}` is the IANA id's last segment with underscores as spaces ("America/Toronto" gives "Toronto"); abbreviations are `TimeZone.getDisplayName(isDaylight, SHORT)` for the selected date, so EST and EDT switch correctly. Never show the raw IANA id |
| Slot list | `FlowRow` (Claude's discretion: wrapping, not the iOS horizontal scroller, so every slot is visible at 200% font scale and no scroll-to-first-open logic is needed), `sm` gaps. Slots are in time order |
| Slot chip | `CircleShape`, `heightIn(min = 48.dp)`, `md` horizontal / `sm` vertical padding, label = start time in the device 12 or 24-hour format (`DateFormat.getTimeFormat`), `bodyLarge`. Resting: transparent with 1dp `outline` border, `onSurface` text. Selected: `primary` fill, `onPrimary` `titleMedium` text, no border. Unavailable (`available == false`, `held == true`, or start in the past; D-04): 38% alpha text and border, not clickable, never hidden |
| Chip semantics | `selectable(role = Role.RadioButton)` inside a `selectableGroup`; label = time; `stateDescription` "Unavailable" for dimmed chips (disabled) |
| Empty day | "No available slots on this day." `bodyLarge` `onSurfaceMuted` (iOS), `xs` vertical padding. Shown when the selected day has no slots at all. A day with only dimmed slots shows them, not this message |
| Loading | 4 `SkeletonBlock` capsules (96 x 48dp) in a `FlowRow` while the center month is loading and nothing is cached for it. Group `contentDescription` "Loading" |
| Failed (center month only, D-07) | `SectionError` inside the card: server message, else "Check your connection and try again."; Retry re-loads the displayed month. Neighbor-month failures show nothing |
| Slot list reload (D-09) | After a 409 the list refreshes in place; the taken slot appears dimmed. No full-card skeleton if data is already on screen |

**5. Meeting type.** Card (`surfaceContainerLow`, `medium`, 1dp `outlineVariant`), `selectableGroup`. Two rows, each `heightIn(min = 56.dp)`, `md` horizontal padding, `RadioButton(selected, onClick = null)` then `md` then label `bodyLarge` `onSurface`, whole row `selectable(role = Role.RadioButton)`, 1dp `outlineVariant` divider inset `md` between them. Labels: "In-app Voice Call" (default, first) and "Skype/Zoom Call". On `422 MEETING_LINK_UNAVAILABLE` the selection snaps back to "In-app Voice Call" (D-08).

**6. Message (optional).** A multi-line text field (new, built with the `ValidatedField` tokens): `surfaceContainer` fill, `medium` shape, 1dp `outline` border resting, 2dp `primary` border when focused, `bodyLarge` `onSurface` text, `minLines = 4` (about 100dp, grows with content), `md` padding. Placeholder (`bodyLarge`, `onSurfaceMuted`): "Add context for the expert — what you'd like to focus on, questions you have, etc." Input beyond 500 characters is cut off at 500 (paste included). Below, `xs` gap, end-aligned counter "{n}/500" `bodySmall` `onSurfaceMuted` (semantics "{n} of 500 characters"). Keyboard: `ImeAction.Default` (Enter inserts a newline), `KeyboardCapitalization.Sentences`. The field scrolls into view when focused (`BringIntoViewRequester`). The text is trimmed when sent and omitted when empty (D-11).

**7. Summary.** Card (`surfaceContainerLow`, `medium`, 1dp `outlineVariant`, `md` padding), five rows with `sm` gap. Each row: label column fixed at 120dp (`bodyLarge` `onSurfaceMuted`; iOS 100, widened for 16sp), value `bodyLarge` `onSurface` end-aligned, wraps to multiple lines. Rows and values:

| Label | Value |
|---|---|
| "Topic:" | Selected topic title, else "—" |
| "Date & Time:" | Short date (`FormatStyle.MEDIUM`, e.g. "Oct 24, 2026") only until a slot is chosen; with a slot, "Oct 24, 2026, 2:00 PM" (device time format) |
| "Duration:" | "{n} min", else "—" |
| "Meeting Type:" | "In-app Voice Call" or "Skype/Zoom Call" |
| "Price:" | `PriceText` (Free in `primary`, paid via `Money.format`), else "—" |

Semantics: each row is merged "{label} {value}". Group is not a live region.

**8. Book Now (BOOK-03, D-01, D-11).** `PressScaleButton`, full width, `heightIn(min = 56.dp)`, filled `primary` / `onPrimary`, label "Book Now" (`labelLarge`). No glow shadow (iOS had one).

| Condition | Rendering |
|---|---|
| Enabled | A topic is selected and it is free, a slot is selected, and no request is in flight |
| Disabled | M3 disabled colors (`onSurface` 12% fill, 38% text). `stateDescription`: "Choose a time slot to continue" (no slot), "Paid booking is coming soon" (paid topic), or "Choose a topic to continue" (no topic). No visible hint for the missing slot (iOS parity) |
| Paid topic selected (D-01) | Disabled, plus the note directly below (`md` gap): "Booking paid sessions is coming soon. Choose a free topic to book now." (`bodyLarge`, `onSurfaceMuted`, centered, `liveRegion = Polite`). No "How does payment work?" link, no "Add a Payment Method". Phase 7 replaces this branch with the same footprint |
| In flight | The label is replaced by a 24dp `CircularProgressIndicator` in `onPrimary`; the button keeps its enabled fill; taps are ignored (D-11). `stateDescription` "Booking" |

**Error dialog (D-08, D-09, D-10).** `AuthErrorDialog` (`AlertDialog`): `surfaceContainerHigh`, `extraLarge`, title "Couldn't book" (`titleLarge`), message `bodyLarge` `onSurfaceVariant`, one confirm `TextButton` "OK" (`labelLarge`, `onSurface`). Scrim tap, Back and OK all dismiss. Messages are in the Copywriting Contract. After dismissal: `MEETING_LINK_UNAVAILABLE` has already reset the meeting type; `SLOT_UNAVAILABLE` has already cleared the slot and reloaded the displayed month.

### 2. Request Sent (BOOK-04, D-12..D-15)

Background `surface`. Content depends on the booking-detail fetch (`GET /client/bookings/:id`).

| State | Rendering |
|---|---|
| Loading | Centered column: `CircularProgressIndicator` (`primary`), `sm`, "Loading your booking…" `bodyLarge` `onSurfaceMuted` (Android; iOS says "Sending your booking…", which is wrong because the request is already sent). `liveRegion = Polite` |
| Failed | `EmptyState` (`Outlined.CloudOff`): heading "Couldn't load your booking", body "Your request was sent, but we couldn't load the details. Check your connection and try again." (Android; the server message is not used because the booking exists), action "Retry". Retry re-fetches and plays the entry animation on success |
| Loaded | Scrolling column below, centered, `md` horizontal padding, `lg` between blocks, `xxl` bottom padding |

Loaded layout, top to bottom (the first block has `lg` top padding):

| # | Block | Spec |
|---|---|---|
| 1 | Check icon | 128dp circle `surfaceContainer` with a 1dp `primary` border at 25% alpha; `Outlined.CheckCircle` 64dp `primary` centered. Decorative (`contentDescription = null`) |
| 2 | Headline | "Request Sent!" `headlineLarge` `onSurface`, centered (`heading()`). `md` below: body `bodyLarge` `onSurfaceVariant`, centered, wrapping: "Your booking request has been sent to {expertName}. They will review it and respond shortly. You'll be notified as soon as it's confirmed." The expert name is `onSurface` at weight 600 (not accent). Same copy for free bookings (Claude's discretion); it never mentions payment. Phase 7 may add a paid line |
| 3 | Details card | `surfaceContainerLow`, `medium`, 1dp `outlineVariant`, full width. See below |

## Interaction Contract (summary)

| Rule | Behavior |
|---|---|
| Initial state | Topics load from the expert details; the first free topic (else the first) is selected; today is selected; the displayed month is the current month; In-app Voice Call; empty notes; no slot |
| Availability loading | Displayed month and its two neighbors; only the center month's failure is shown; changing the month cancels the in-flight load (D-07). A tap on a day or chip never waits on a neighbor month |
| What clears the selected slot | Changing topic, changing day, changing month, a 409 (D-09) |
| What does not | Changing meeting type, editing notes, reloads that don't change the selected slot's status |
| Book Now | Ignored while in flight; success replaces the screen with Request Sent (D-12) |
| Errors | One `AlertDialog` at a time, titled "Couldn't book"; network failures use the standard network copy |
| Request Sent buttons | "View My Bookings": clear the Explore stack and select the client Bookings tab (placeholder content until Phase 8). "Back to Home": clear the Explore stack to its root (D-13) |
| Rotation / process death | Selected topic id, selected date, displayed month, selected slot start instant, meeting type and notes survive via `rememberSaveable` / `SavedStateHandle`. Network data reloads. The sheet's open state survives rotation. Request Sent re-fetches by id and does not replay the animation |
| Time and zone | Every slot and time label is in the device zone and device 12/24-hour format; slots are grouped by the device-local date of `startUtc` (D-07) |

## Accessibility Contract

- All tap targets at least 48dp tall; the calendar day cell is 48dp tall and about 44dp wide on a 360dp screen (declared exception).
- Section headings carry `heading()` semantics (`SectionHeader`, the slots card title, "Request Sent!").
- Radio-style groups (topic cards in the sheet, meeting type rows, slot chips, calendar days) use `selectableGroup` / `selectable` with `Role.RadioButton`; the selected state is announced and is never color alone (fill plus border for topic cards, filled circle plus text weight for the day and the chip, radio mark for rows).
- Dimmed days and chips are disabled with `stateDescription` ("Unavailable" for chips, "Today", "Has open times" on days). The open-day dot is not the only signal: the `stateDescription` carries it.
- The month label is a polite live region, so changing months is announced. Errors appear in an `AlertDialog` (announced by the platform); the paid note and the loading and error states of Request Sent use `liveRegion = Polite`. Skeleton groups announce "Loading" once.
- Book Now exposes a `stateDescription` for why it is disabled and "Booking" while in flight.
- Decorative icons (`CheckCircle`, `Layers`, `CalendarMonth`, `ExpandMore`, the row avatars) have `contentDescription = null`; the parent node carries the text.
- Contrast: `onPrimary` on `primary` 9.3:1; `onSurfaceMuted` on `surfaceContainerLow` at least 5.9:1; the notes border uses `outline` (about 5.8:1, at least 3:1 for input boundaries). Disabled content is exempt but stays legible.
- Check both screens at 200% font scale: the topic title and sheet cards wrap, the slot `FlowRow` wraps onto more lines, the summary values wrap beside the 120dp label column, calendar day numbers stay inside the 36dp circle (the number uses `bodyLarge`; if a larger scale would clip, grow the circle with `heightIn`, not the text), the details card rows wrap, and Request Sent scrolls. Nothing clips.
- Focus order follows section order. The sheet is IME-independent. The notes field uses `imePadding` and scrolls into view.
- A full TalkBack pass is Phase 15 (POL-04).

## Open Items (for the planner and checker)

1. **Selected day versus displayed month.** Changing the month keeps the selected day (iOS), so the slots card can show a date outside the displayed month. The date line on the slots card removes the ambiguity. If device testing finds it confusing, the alternative is to move the selection to the first bookable day of the new month; that is a behavior change and needs a CONTEXT decision.
2. **Timezone abbreviations.** `TimeZone.getDisplayName(SHORT)` returns "GMT+9" style text for some zones on some devices. The note then reads "(GMT+9)", which is acceptable. Do not special-case it.
3. **Reuse of `AuthErrorDialog`.** It lives in `screens/login`. Reusing it from `makeabooking` is a cross-package import; the planner may move it to `components/` as a pure refactor.
4. **Request Sent error state hides the real booking state.** If the detail fetch keeps failing the user can only retry or press Back. Acceptable for Phase 6; Phase 8 (My Bookings) is the recovery path.
5. **Manual checks deferred** (per project preference): 200% font scale on both screens, notes field with the keyboard open, month-edge and cross-timezone slot grouping with the iOS expert in a different zone, held-slot dimming, a free booking reaching the iOS expert, entry animation feel, animations off.
