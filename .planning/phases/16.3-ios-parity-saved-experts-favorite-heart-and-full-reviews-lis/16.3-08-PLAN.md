<objective>
Close the one failed truth of Phase 16.3 (VERIFICATION truth 12, review CR-01): a booking started from Saved Experts must not leave a finished Request Sent screen parked on the client Profile stack.

Purpose: Saved Experts (new in 16.3) made the Profile stack a fourth stack that can host the Profile to Book flow. Neither shared reset set contains the Profile tab, so the next tap on Profile lands on Request Sent with the bottom bar hidden, three Backs from the hub. The fix resets the Profile stack only from the two Request Sent callbacks, and only when this booking ran there. `FavoritesRouteActions`, `showMyBookings` and `showExplore` keep their code, so runbook row D1.FV4 and RESEARCH A3 stay true.
Output: 2 new navigator helpers in 1 main file, KDoc in 3 main files, 9 new test cases in 2 test classes, 1 runbook row, the CR-01 disposition.
</objective>

**Why the reset is conditional.** The client `ExpertProfileKey` entry has no hidden-bar metadata (`M/screens/clientmode/home/HomeClientScreen.kt:157`), so a user can open Saved Experts, open an expert, switch tabs from the bottom bar, and book somewhere else with that profile still open on the Profile tab. An unconditional reset from the callbacks would drop it, which changes behavior for a booking that did not start on the Profile stack. So the reset fires only when the Profile stack holds this exact `RequestSentKey`. Membership is used rather than the selected tab because `Navigator` documents that outgoing content still accepts input during a transition, so a tap can land after a programmatic tab change; membership states the failed truth directly.

**iOS.** `HomeClientView.swift:87-94`: `showMyBookings` resets `explorePath` and `bookingsPath`, `returnToHome` resets `explorePath`. Neither touches `profilePath`, so this reset is a deliberate Android deviation of the same kind as the Search reset (KDoc on `showMyBookings`, user decision 2026-10-30).

**The D1.FV4 trade-off.** Two exits now treat the Profile stack differently on purpose. Saved Experts' own buttons keep the list open (D-05, D-06, RESEARCH A3, D1.FV4), because the user only stepped away. A finished booking returns the Profile tab to the hub, because the flow is over; the user loses their place in Saved Experts only after actually booking. Adding the Profile tab to the shared sets, the review's first suggestion, would break D1.FV4 and also reset the stack for every other caller of those functions (`MyBookingsScreen.onExploreExperts`, cancel `onCancelled`).
