## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Heart measured 40 dp, not 48 dp**
- **Found during:** Task 1 (test `cardHasTwoTalkBackStops`)
- **Issue:** `IconButton` lays out at 40 dp and only pads its touch bounds to 48 dp, so the layout and semantics bounds were below the plan's 48 dp requirement.
- **Fix:** `Modifier.size(48.dp)` on the heart `IconButton`.
- **Files modified:** `subviews/FavoriteExpertCard.kt`
- **Commit:** e3b9bea1

**2. [Rule 1 - Bug, test only] First composition double-loaded against a synchronous fake**
- **Found during:** Task 1 (the "exactly one list request" assertion saw 2)
- **Issue:** `ON_RESUME` and the first-composition `LaunchedEffect` both call `onScreenShown()`. The ViewModel coalesces them only while a load is in flight; the fake API answered without suspending, so the first load had already finished and the second call started a quiet reload. A real request suspends, so production is unaffected.
- **Fix:** the test's list handler awaits a `CompletableDeferred` gate that is released after the first composition settles. No ViewModel or screen change.
- **Files modified:** `FavoritesScreenTest.kt`
- **Commit:** e3b9bea1

### Other notes

- **TDD RED:** Task 1 was RED as "does not compile" (the screen types did not exist); Tasks 2 and 3 were RED as runnable failures (8 failing tests at the start of Task 2). For Task 3 the new tests and the screen changes were written before the first run, so its RED state was not observed separately.
- **Plan layout vs semantics:** the plan placed the heart in the card's top row. To give TalkBack two separate stops, the heart is overlaid at the card's top end beside the clickable column, and the name column reserves 36 dp at its end. The visual result matches.
- **Dialog back test:** Espresso is not on the unit-test classpath, so the back-press test calls `ShadowDialog.getLatestDialog().onBackPressed()` on the UI thread, which goes through the Compose dialog's own back dispatcher.
- The unused-parameter suppression added in Task 1 was dropped once Task 2 and 3 used every parameter of `FavoritesContent`.
