# Phase 16.3 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| app → backend | Authenticated GET/PUT/DELETE on `/client/favorites*`; the reviews list | Expert id in the path; page and limit on list calls |
| backend → app | Server JSON decoded into DTOs, UI models and snackbars | Favorites rows, `is_favorite`, review text, names, topics, date labels, avatar URLs, error messages |
| user → app | Rapid heart taps; destructive remove from the card heart | Tap events |
| Nav3 back stacks | Keys from different tabs flatten into one `NavDisplay` | Keys built from server ids and names |
| Shell boundary | Client-only Saved Experts route vs. the Reviews route both shells register | Route keys |
| App internal | `BookingsLaunchRequest` hand-off to My Bookings | A tab value |
| Process death | `rememberSaveable` and Nav3 saved state | Expert id for the dialog target; public display seed on profile keys |
| Repository docs → people | Committed Phase 16 runbook | Must carry no credentials, emails or card data |
