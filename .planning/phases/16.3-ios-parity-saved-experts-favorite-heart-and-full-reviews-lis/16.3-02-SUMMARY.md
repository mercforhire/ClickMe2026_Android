# Phase 16.3 Plan 02: Reviews data layer, nav keys and ViewModel Summary

Full Reviews list foundations: `session_context` DTO, `expertReviews` pinned to page=1 and limit=20, `StackOrigin.Profile`, `FavoritesKey`, an origin-copying `ExpertReviewsKey`, and an assisted-Hilt `ExpertReviewsViewModel` with load, retry, pull-to-refresh and the iOS title rule.

## What was built

- **Task 1 (tracer):** `ReviewItemDto.sessionContext` (appended last, defaulted) with nullable topic, date and date_label. `ReviewsRepository.expertReviews(expertId)` calls `getExpertReviews(expertId, 1, EXPERT_REVIEWS_PAGE_SIZE)`. `ExpertReviewsApiTest` pins the wire (page=1, limit=20, two query params) and decoding of present, null and missing context. `ReviewFixtures.reviewItem` and `reviewsPayload` added.
- **Task 2:** `StackOrigin` is now `Default, Chats, Search, Profile`. `FavoritesKey` is a serializable data object. `ExpertReviewsKey(expertId, expertName, origin)` plus `ExpertProfileKey.reviewsKey(expertName)` which copies the profile key's origin. Tests cover origin copying for every value, distinct keys across stacks, and a serialization round trip.
- **Task 3:** `ExpertReviewsViewModel` loads on creation (Loud), `retry()` reloads, `refresh()` is a Pull over Loaded content and a Loud load otherwise, a failed pull keeps content and raises `refreshFailed` once, `consumeRefreshFailure()` clears it. Starting any load clears both flags first (Pitfall 6). Null overall rating reads 0.0; blank reviewer name, topic, date label and comment map to null. `reviewsTitleFirstName` ports iOS `navigationTitle`.
