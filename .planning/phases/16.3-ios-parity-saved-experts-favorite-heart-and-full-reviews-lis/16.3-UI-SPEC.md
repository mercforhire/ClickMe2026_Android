# Phase 16.3 — UI Design Contract

> Visual and interaction contract for Phase 16.3 (Saved Experts, favorite heart, full Reviews list). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Designs live in Google Stitch and are not accessible, so the iOS views under `ios-reference/ClickMe2026/Views/Screens/Client Mode/{Favorites,Reviews,Expert Profile}` are the stand-in source of truth. Where iOS and the Android design system disagree on a value, the Android token wins (listed in "Deliberate visual deviations from iOS"). No new colors, sizes, weights or spacing tokens are introduced.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Jetpack Compose + Material 3; shadcn does not apply to Android) |
| Preset | not applicable |
| Component library | Material 3 (`androidx.compose.material3`) plus the in-house `components/` set |
| Theme | Dark only. `ClickMeTheme` in `ui/theme/` (`Color.kt` `ClickMePalette`, `Type.kt`, `Spacing.kt`, `Shape.kt`, `Extras.kt`, `Motion.kt`, `ContentWidth.kt`) |
| Icon library | Material Icons Extended (`androidx.compose.material:material-icons-extended`, `Icons.Outlined.*` / `Icons.Filled.*`) |
| Font | Nunito variable font (`NunitoFamily`), weights 400 and 600 only |

Hard rules inherited from the project (enforced by `scripts/check-design-rules.sh`): no hex literals outside `ClickMePalette`; never set `fontSize` outside `Type.kt`; read colors from `MaterialTheme.colorScheme` or `MaterialTheme.extras`; read spacing from `Spacing`. Do not pass `FontWeight.Bold` (the font family only defines 400 and 600, so Bold would resolve unpredictably): use the 600 styles.

## Screen and Component Contracts

### 1. Favorite heart (Expert Profile app bar)

- Placement: `ProfileTopBar` `actions`, immediately before `SafetyMenu` (the three-dot menu). Both are 48dp `IconButton`s.
- Visibility: only when `state.details is DetailsState.Loaded` and not `isSelfView` and not `chatEntry.isSelf(expertId)` (same gate pattern as `showSafetyMenu`). Not rendered at all otherwise (no disabled/placeholder slot).
- Control: `IconToggleButton(checked = isFavorite)`. Icon swaps `Icons.Outlined.FavoriteBorder` (tint `onSurface`) to `Icons.Filled.Favorite` (tint `colorScheme.error`), 24dp. Cross-fade 150ms (`Motion.CONTROL_STATE_DURATION_MS`). Content description per the copy table; the toggle semantics (Checked / Unchecked) come from `IconToggleButton`.
- Behavior (D-03, D-04): tap flips the icon immediately; a tap while a request is in flight is ignored with no visual change (no spinner, no dimmed state: the call is short and a flicker is worse). On success the icon reconciles to the server `is_favorite`. On failure the icon rolls back and the screen's existing `SnackbarHost` shows the server message.
- Initial state: `is_favorite` from `GET /experts/:id/details`, false by default.

### 2. Recent Reviews card (Expert Profile)

- Always rendered once reviews have loaded (including 0 reviews). `ReviewsState.Loading` keeps `ExpertProfileReviewsCardSkeleton`. `ReviewsState.Failed` keeps the card hidden (so "See all" never reads as "0 reviews").
- Header strip (`surfaceContainer`): title `Recent Reviews` (16sp/600, left) and a trailing "See all" `TextButton` (16sp/600, `onSurface`, underlined, min height 48dp, horizontal content padding `sm`; header start padding `md`). Matches the `SectionHeader` link treatment. The header is a heading for TalkBack; the button is a separate Button node.
- Zero reviews: the card is just the header strip (no divider, no rows). "See all" still shown (D-13, D-14).
- 1 to 3 reviews: header, divider, existing `ReviewRow`s unchanged (still capped at 3).
- Self-view keeps the card and "See all" (D-15).

### 3. Saved Experts screen (`FavoritesScreen`)

Chrome: `Scaffold` + `TopAppBar` (title `Favorite Experts`, `titleLarge`, one line with ellipsis; back arrow `Icons.AutoMirrored.Outlined.ArrowBack` with `a11y_back`). Container `surface`, scrolled container `surfaceContainer`, same colors as `ProfileTopBar` but not transparent. Snackbar host in the scaffold. Content wrapped in `contentMaxWidth()`; horizontal padding `md`; bottom padding 48dp.

States, crossfaded over 300ms (iOS 0.30s):

| State | Contract |
|-------|----------|
| First load | `SkeletonGroup` with 3 `SkeletonBlock`s, 144dp tall, `shapes.medium`, `md` apart, under the tagline-height spacer. Vertically scrollable so pull works. No tagline while loading |
| Populated | Tagline (`bodyMedium`, `onSurfaceVariant`, top `md`, bottom `lg`), then `LazyColumn` of `FavoriteExpertCard`s, `md` apart, keyed by `expertId`, `Modifier.animateItem()` (250ms placement) so a removal slides the rest up. Pull-to-refresh via `PullToRefreshBox`. No Pro Tip card |
| Empty | `GreenGlowBlobLayer` background; vertically centered, scrollable column (so pull-to-refresh works), top to bottom: `FavoritesGlowingStar` (200dp), `xl` gap, title (`titleLarge`, `onSurface`, heading semantics, centered), `md` gap, body (`bodyLarge`, `onSurfaceVariant`, centered, `xl` side padding), `xl` gap, the two buttons (`lg` side padding, full width, 56dp tall, `md` gap, `PressScaleButton` capsule: "Explore Experts" `filledColors()`, "View My History" `tonalColors()` plus a 1dp `overlayWhite10` border), `lg` gap, `FavoritesProTipCard` (`lg` side padding). Whole block is a polite live region |
| Error (first load) | `ErrorState(heading = "Couldn't load favorites", body = message, retryLabel = "Retry")`, centered in a scrollable column |
| Refresh in progress | Existing rows stay; M3 pull indicator |
| Refresh failed over rows | Rows stay, `RefreshFailedSnackbarEffect` shows "Couldn't refresh" with Retry. Return-triggered background refreshes (D-09) that fail are silent: no snackbar, no error view |

`FavoriteExpertCard` (port of iOS, 16.1 `SearchExpertCard` precedent):
- Shell: `surfaceContainerLow`, 1dp `outlineVariant` border, `shapes.medium`, padding `md`, `Modifier.pressScale`, whole card clickable (opens Expert Profile for `expert_id`).
- Top row (top-aligned): `FavoriteExpertPhoto` 72x80dp, `shapes.extraSmall` clip, `Crop` scale; fallback fill `ClickMePalette.avatarFallback` with a centered `Icons.Filled.Person` (~32dp, `onSurfaceVariant`) while loading, on failure and when there is no URL. `md` gap. Text column (weight 1): name (`titleLarge` 20/600, `onSurface`, max 2 lines, ellipsis; fallback `Expert`) then 4dp then headline (`labelLarge` 16/600, `primary`; omitted when blank, max 2 lines). Trailing: 48x48dp heart `IconButton`, `Icons.Filled.Favorite` 24dp, tint `error`, content description `Remove {name} from favorites`. Tapping the heart opens the Remove dialog and does not open the profile.
- Tags: `md` below the top row, `FlowRow` of `ExpertTagChip` (all non-blank tags, wraps, `sm` gaps). Row omitted when there are no tags.
- No bio line (endpoint has none).
- TalkBack: two stops per card, the card (name, headline, tags, click label "Open profile") and the heart.
- No fixed height; grows with font scale.

`RemoveFavoriteDialog` (Material `AlertDialog`, copy of `LogOutConfirmDialog` styling): `containerColor = surfaceContainerHigh`, `shape = shapes.extraLarge`, title `titleLarge` (wraps), text `bodyLarge` `onSurfaceVariant`, dismiss `TextButton` "Cancel" (`labelLarge`, `onSurface`), confirm `TextButton` "Remove" (`labelLarge`, `colorScheme.error`). `FavoritesGlowingStar` (200x200dp, decorative, `clearAndSetSemantics {}`): follows the 16.1 `SearchExpertGlowingIllustration` approach, no render-effect blur (API 31+ only). The iOS two-color gradient on the star is dropped (single `primary`). Pulse stops when the system animator scale is 0.

`FavoritesProTipCard`: row, `surfaceContainerLow` with 1dp `outlineVariant`, `shapes.medium`, padding `md`. Leading 44x44dp tile (`surfaceContainerHigh`, 1dp `outlineVariant`, `shapes.extraSmall`) holding `Icons.Outlined.Lightbulb` 24dp in `primary`; `md` gap; text column with "Pro Tip:" (`labelMedium` 12/600, `onSurface`) over the body (`bodySmall` 12/400, `onSurfaceVariant`, wraps). Merged into one TalkBack node. Not interactive.

## Accessibility Contract

- Touch targets are at least 48dp: heart buttons, "See all", hub row (56dp), empty-state buttons (56dp), Retry.
- The profile heart is an `IconToggleButton` (announces checked / unchecked) with a state-dependent description. The card heart is a Button with a per-expert description.
- Titles are heading nodes (TopAppBar title, empty-state title, section header, "Recent Reviews", dialog title). The empty-state block and the error views are polite live regions (`ErrorState` already does this).
- Skeleton groups announce one "Loading" (`SkeletonGroup`).
- Decorative: the illustration, glow layer, Pro Tip lightbulb, star rows (the card supplies "Rated n out of 5").
- Contrast: all text uses `onSurface`, `onSurfaceVariant` or `extras.onSurfaceMuted` on `surface` / `surfaceContainerLow`, the same pairs already used app-wide.
- Dialogs and snackbars follow the Material 3 defaults (focus trap, back dismisses the dialog).

## Notes for the planner
