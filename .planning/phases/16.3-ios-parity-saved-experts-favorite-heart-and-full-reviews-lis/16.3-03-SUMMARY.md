# Phase 16.3 Plan 03: Expert Profile Heart and See All Summary

**An app-bar favorite heart that seeds from `is_favorite`, flips optimistically through `FavoritesRepository`, reconciles to the server value, rolls back with a snackbar and ignores taps in flight, plus an always-present "See all" on the Recent Reviews card that reports the shown expert name.**

- **Tasks:** 3 of 3 complete
- **Files:** 0 created, 9 modified
- **Verification:** `screens.clientmode.expertprofile.*` tests and `ktlintCheck` pass after every task; `scripts/check-design-rules.sh` prints "Design rules: OK". Both shells compile unchanged (main source set compiled as part of the test builds).

## Accomplishments

- Task 1 (tracer): `ExpertProfileUiState.isFavorite` / `favoriteError`; `ExpertProfileViewModel` takes `FavoritesRepository`, `mergeDetails` seeds the heart unless a toggle is in flight, `onToggleFavorite()` flips at once, calls PUT or DELETE and takes the server's `is_favorite`, rolls back on `ApiException` with `toFavoriteFailure()`. The heart is an `IconToggleButton` (48 dp, `Crossfade` between outlined and filled `colorScheme.error`) placed before the More options menu. The tracer is proved end to end through the real ViewModel, repository and `FakeClickMeApi` (`heartTapThroughTheRealViewModel`).
- Task 2: favorite-failure snackbar (resolve text in composition, show on the composition scope, consume), with tests for rollback with the server message, network fallback, dropped in-flight taps, taps before details load, Retry mid-toggle, and the heart hidden for self-view, own profile and before load.
- Task 3: `ExpertProfileSectionCard` gets `headerAction` and `hasContent`; the reviews card shows an underlined `onSurface` "See all" `TextButton` (48 dp min) for any `Loaded` size (header strip only at 0 reviews); `Failed` stays hidden; `onSeeAllReviews(state.name)` is plumbed through `ExpertProfileScreen` and `ExpertProfileContent`. Self-view keeps the card and See all.
