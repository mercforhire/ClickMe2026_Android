## Integration (gsd-integration-checker, sampled read-only trace)

**Wired:**
- All nine 16.x route keys have both an entry registration and a navigate caller. There are no orphaned routes or `PushDestination` members.
- Expert-only screens are registered only in the expert shell.
- Connect deep links work end to end.
- Notification preferences are independent of the Phase 13 channels.
- The realtime socket disconnects on every logout path.

**Findings:**
1. **WARNING, POL-02:** the 16.x input screens are not process-death safe. Files: `BookingNoteViewModel`, `FeedbackViewModel.kt:68`, `SearchExpertViewModel.kt:39`.
2. **WARNING, PUSH-01/FND-08 (carried over):** on a forced logout, DELETE push-token goes out with no bearer and fails silently, so the server row stays. Files: `TokenAuthenticator.kt:82-83`, `UserManager.kt:204`, `FcmPushTokenRegistrar.kt:71-85`.
3. **INFO:** `BookingsLaunchRequest`, `ExpertLaunchRequest` and `AccountDeletionState` are not `SessionDataCleaner`s. Only cosmetic state can leak.
4. **LOW:** the Notification prefs screen does not show a hint when the OS notification permission is denied. iOS behaves the same way.
