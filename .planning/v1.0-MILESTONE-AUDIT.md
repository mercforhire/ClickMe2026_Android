## Integration (gsd-integration-checker, Phase 17 delta plus carried items)

**Wired:**
- All three 17-01 ViewModels resolve under Hilt.
- BookingNote is assisted-injected with SavedStateHandle.
- No handle key collides with a Nav3 route argument.
- Feedback is reachable from both hubs, and the booking note from both role shells.
- A restored Search query does not affect Explore → Search → profile → Reviews.
- The MeetingCallScreen change is layout only. The public API is unchanged, so Waiting/Connected, End Call, the external overlay and push → call are unaffected.
- `AppLinks.SUPPORT_EMAIL` is used consistently in the Help screen and in the suspended-account dialog text and mailto. No hard-coded old address remains, apart from a KDoc.

**Findings:**
1. **WARNING, PUSH-01/FND-08 (carried, still present).** After a forced session rejection, the push-token DELETE goes out without a bearer, so the server row stays. Code: `TokenAuthenticator.kt:80-83` → `UserManager.kt:133,204`.
2. **WARNING, POL-02/AUDIT-1/AUDIT-7 (17-REVIEW WR-01, confirmed).** Text written to SavedStateHandle is uncapped at `FeedbackViewModel.kt:136,143` and `SearchExpertViewModel.kt:76`. A very large paste could cause a TransactionTooLargeException crash. The fix is about 10 lines using `capText`.
3. **INFO, FND-08 (carried).** `BookingsLaunchRequest`, `ExpertLaunchRequest` and `AccountDeletionState` are not SessionDataCleaners. The only state that can leak is cosmetic.
